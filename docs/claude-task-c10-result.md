상태: **구현 / 자체 검사 통과 / Codex 검토 대기 / 사용자 확인 대기(Q-U2)**. 저장 명령·스키마·`timeSpec`/`timeRange` 계약·백업 형식은 바꾸지 않았다.

## 1. 칸 대응표 (기존 → 새)
| 폼 | 기존 | 새 |
|---|---|---|
| 활동 추가·일정 수정 | 활동 제목 → 장소 → 계획 날짜 → `발생 시각`(시각 정밀도 → 발생 날짜 → 현지 시각 → IANA 시간대) | 활동 제목 → 연결할 장소 → 계획 날짜 → `시각 (선택)` → `종료 시각 (선택)` → (수정만) `변경 이유 (선택)`. 정밀도·원문·UTC 오프셋·시간대는 `자세히` 접기 |
| 실제 기록·정정 | 활동 이름 → 실행 결과 → 장소 → 발생 시각(4칸) → 메모 | 활동 이름 → 실행 결과 → (장소) → `날짜` → `시각 (선택)` → 메모. 정밀도는 `자세히` 접기, `날짜만 확인`은 시각 칸을 비움 |
| 숙박 | 입실·퇴실 날짜 → 입실·퇴실 시각 → 시간대 | 입실 날짜 → 입실 시각 → 퇴실 날짜 → 퇴실 시각. 시간대는 여행 기본값 자동, 접기 안에서 변경(여행 시간대가 없을 때만 칸 노출) |
| 이동 | 변경 없음(로직) | 저장 버튼 하단 고정만 적용 |
| 모든 대화상자 | 저장 버튼이 스크롤 아래 | 제목 줄(닫기)·`form-actions` 영역 `position: sticky` |

- 시각 칸을 비우면 계획은 `unspecified`, 기록은 날짜가 있으면 `date`(날짜만 확인), 채우면 `local`. 시간대는 여행의 확인된 시간대를 자동 사용(`timeZoneStatus: confirmed`). 여행 시간대가 `unknown`이면 시각을 넣을 때 `시간대 (예: Asia/Tokyo)` 칸이 보인다.
- 기존 `text`/`instant` 값은 사용자가 바꾸기 전에는 다시 쓰지 않고, `자세히` 안에서 그대로 편집된다.
- **방문 기록** 한 번 누르면 기기 시계·여행 시간대의 현재 시각(분 단위, `local`)으로 바로 저장하고 "…방문을 HH:mm에 기록했습니다" 알림을 보인다. 시간대를 모르거나 저장에 실패하면 기존 폼을 연다.
- **종료 시각**: 시작보다 이르면 "다음 날 …에 끝나는 것으로 저장할까요?" 확인 뒤 `end.date`를 +1일로 저장, 타임라인은 `23:30 ~ 00:30 (다음 날)`.
- **변경 이유**: 비우면 기존 문구 `사용자 일정 수정`. 계획 버전 목록(`계획 N · 이유`)에 남는다.

## 2. 선택자 대응표 (E2E)
| 이전 | 이후 |
|---|---|
| `시각 정밀도` 선택 → `local` + `발생 날짜` + `IANA 시간대` | 기록: `날짜`(exact) + `시각 (선택)`(exact). 계획: `시각 (선택)`만(날짜는 계획 날짜). 시간대 입력 없음 |
| `시각 정밀도` = 날짜만 확인 + `발생 날짜` | `날짜` 입력 + `시각 (선택)` 비우기 |
| `방문 기록` → 폼 → 시각·메모 → 저장 | 한 번 누르면 저장(시계 고정 `page.clock.setFixedTime`) → `정정`으로 날짜·시각·메모 |
| 날짜 미상 기록을 폼 기본값으로 생성 | 새 폼이 날짜를 기본 채우므로 `시각`·`날짜`를 비워 생성(retrospective·c06) |
| 숙박 `시간대 (확인한 경우만)` 입력 | 삭제(여행 기본값 자동) |

정정 단계 수 단언(`3/3 · 최신 정정본`)은 유지했다: 방문 저장 1 → 날짜·시각·메모 정정 2 → 메모 정정 3.

## 5. 지시와 다르게 한 곳·남은 후보
- 실제 기록 폼의 시각 기본값: 지시는 "현재 시각"이나, **보고 있는 날짜가 오늘일 때만** 지금 시각을 넣고 지난 날을 보며 기록하면 날짜만 채운다(사실과 다른 시각 방지). 방문 기록 한 번 누르기는 항상 지금이다.
- 일정 폼의 `메모` 칸: 계획 항목에 메모 필드가 없어(`summary`는 원천 요약) 추가하지 않았다. 활동 메모는 기존 `⋯ → 메모`를 쓴다.
- 대화상자의 `취소` 버튼은 따로 만들지 않고 고정된 제목 줄의 `닫기`를 쓴다.
- 회고 화면에서 변경 이유 표시는 기존 계획 버전 목록·회고의 이유 표시를 그대로 사용한다(이번 시험은 계획 버전 목록에서 확인).
- C-11(`codex/c11-restore-ux`)과 같은 파일(ContentApp·E2E 선택자)을 건드려 병합 시 충돌 가능. 이 브랜치는 지시대로 C-09 검토 통과 커밋에서 분기했다.
- 사용자 PC·모바일 화면 확인(삿포로 대본 S3~S4)은 미실시. 사용자 확인 상태: **검토 준비**.
