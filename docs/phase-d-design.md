# D단계 설계서 · 실제 AI 운영·모바일 사용 검증

2026-10-30 · 작성: Codex · **설계 제안 / 사용자 검토 준비 / 구현·유료 호출·배포 승인 아님**

[요구사항](product-requirements.md)·[결정](decisions.md)·[목표](goal-and-migration-criteria.md)·[상위 계획](development-plan.md) §7을 따른다.
구현 순서/검증 관문은 [D 개발계획](phase-d-plan.md)에 둔다. C-06 진행 중 작성한 문서이며 그 결과·C 전체 완료를 선행 확정하지 않는다.

## 1. 목표·범위

확정한 휴대폰 환경에서 앱 내부 조사→근거·이유·영향이 있는 변경안→사용자 확인→원자 저장→재조회까지 연결한다.
오프라인에서는 기존 일정·본문·실제 기록·백업을 계속 사용한다. 온라인 AI 연결을 오프라인 기능의 조건으로 만들지 않는다.
확정 요구는 OpenAI API 사용, 개인용·모바일 우선, 모든 변경안 확인 후 적용, 실제 기록/과거 계획 보존이다.

| 구분 | 범위 |
|---|---|
| D 핵심 흐름 | 기존 장소/선택 날짜의 활동 추가·수정·제거 제안, 웹 근거, 요청별 전송 동의, 비용/인증/복구, 모바일 실제 사용 |
| 기존 기능 재사용 | v2 provider·job manager·컨텍스트·StageAiProposal·DecideProposal·C의 편집/현장 기록/회고/백업 |
| 후속 선택 확장 | AI 새 장소/가이드 생성·숙박/이동 변경 제안. 별도 payload/승인·소유 연결/예약 영향 설계 후 결정 |
| 제외 | 예약/결제 실행, 무확인 자동 적용, 자동 기기 동기화, 전체 DB 서버 업로드, 비밀값을 브라우저에 저장, v1 삭제 |

후속 확장이 현재 계획 변경안 스키마에 이미 들어간 것으로 설명하지 않는다. D 핵심 통과를 모든 AI 확장 완료로 확대하지 않는다.

## 2. 현재 코드·증거와 공백

2026-10-30 읽기 조사 기준. 현재 체크아웃의 C-06 작업과 독립된 AI 경로를 확인했다. 아래는 정적 조사이며 새 기능 검사 통과 주장이 아니다.

| 영역 | 현 구현/과거 증거 | D에서 필요한 보완 |
|---|---|---|
| 실행 | server/ai-v2.ts: Responses·웹 검색/구조화 출력·store:false, 로컬 v2 job manager | 실제 v2 모델/계정 접근·출력 품질·오류/사용량 검증 |
| 전송 | src/ai-v2-context.ts: 최대7일, 숙박/일부 예약 필드 제외, 기록 기본 제외 | 모든 활성 장소 전송·기록 포함 시 전체 이력 전송, 남은 plan/header 필드·자유문장 노출을 허용 목록으로 축소 |
| 모바일 | server/index.ts는 127.0.0.1 바인딩·로컬 Host/Origin 허용 | 인증된 HTTPS 접근 경로·사용자/기기별 작업 소유권. 단순 CORS/Host 검사는 사용자 인증이 아님 |
| 공개 Pages | AiPlanner는 staticHosting이면 실행 비활성 | 운영 방식에 맞춘 앱/서버 연결. URL만 바꿔 호출 가능한 것으로 가정하지 않음 |
| 비용 | 작업5분·웹 검색2·작성2·하루20건·보관200·동시2 등의 실행 기본값 | 금액 기준 한도·요청별 예약/사용량·불명 비용 처리. 현재 수치는 사용자 예산 합의 아님 |
| 상태/복구 | jobs.json 저장·request 지문·중단·재시작 interrupted·브라우저 polling | 실제 프로세스 종료·응답 유실·과금 불명·저장 실패·재회수 검증 |
| 저장/확인 | StageAiProposal 근거+초안 원자 저장, stale 거부·중복 방지·사용자 결정 | C 확장 후 회귀, 실제 모델 결과와 모바일 저장/복원 증거 |

[기존 구현 보고](phase-3-report.md)·[10/26 모의 검증](phase-3-mock-verification-2026-10-26.md)은 과거 증거다.
초기 v1의 가상 실제 호출 성공은 실제 v2/G3 통과 증거가 아니다. 키의 현재 유효성·잔액·모델 접근은 이번에 조회하지 않았다.

## 3. 접근 구조·데이터 정본

```text
휴대폰 앱/브라우저 ──인증된 HTTPS── AI 게이트웨이/작업 저장소 ──OpenAI API
       │                                      │
       └ 로컬 여행 DB·계획·실제·근거/초안        └ 키·작업 상태·최소 결과·비용 원장
```

여행 정본은 해당 기기의 기존 로컬 DB다. 서버는 전체 여행 저장소/동기화 서버가 아니며 직접 현재 계획을 바꾸지 않는다.

| 운영 후보 | 장점·제약 | 결정 상태 |
|---|---|---|
| A. 개인 관리 서버+인증된 비공개 접근, 앱/API 동일 origin | 제한된 접근·단순 세션. 여행 중 서버 전원/네트워크·사설 접근 유지 필요 | 우선 비교 후보, 미확정 |
| B. 관리형 서버에 개인 인증 앱/API 동일 origin | 이동 중 접근·운영 가능. 호스팅 비용·로그/보관·배포 관리 필요 | 대안, 미확정 |
| C. 기존 Pages+별도 인증 AI API | 기존 앱 origin 유지 가능. CORS/세션·모바일 cross-site 제약·API 연결 설정 추가 | 대안, 미확정 |

같은 origin의 앱/API를 단순화 후보로 제안하되 호스팅 제품·구매·공개 범위를 정하지 않는다.
origin이 바뀌면 IndexedDB/PWA 저장소도 다르다. 기존 여행이 자동 이동했다고 가정하지 말고 별도 백업→빈 검토 공간 복원·재실행을 검증한다.
새 origin을 먼저 가상 데이터로 확인하고 사용자 자료 이동은 별도 선택으로 둔다. 기존 Pages/프로필을 초기화하지 않는다.
다른 기기는 별도 DB다. 로그인만으로 여행이 동기화되는 UI를 만들지 않는다.

## 4. 인증·키·작업 소유권

- 모든 status/create/list/get/cancel/result 경로에 인증을 적용한다. UUID·X-Travel-App·tripId를 비밀 토큰처럼 신뢰하지 않는다.
- 작업은 서버 사용자/세션 권한과 요청 식별자에 연결한다. 다른 사용자·다른 공간의 같은 tripId로 작업 조회/취소/회수가 불가능해야 한다.
- 기본 제안은 동일 origin의 HttpOnly/Secure 세션과 변경 요청 CSRF 방어다. 구체 로그인 수단·만료·기기 해지는 운영 후보 선택 후 확정한다.
  API 분리 시 정확한 origin 허용 목록·인증 정보 전달·CSRF를 설계한다. wildcard·공개 무인증 비용 발생 경로는 허용하지 않는다.
- v1 경로·프록시·진단 경로가 새 인증을 우회하지 않는지 함께 검사한다. v1 삭제 대신 비활성/격리 정책을 명시한다.
- OpenAI 키는 서버 비밀 저장소/승인된 로컬 env에만 둔다. 빌드·브라우저·URL·로그·Git·테스트 산출물에 넣지 않는다.
- 이번 설계로 새 키 발급/조회·기존 키 교체/폐기를 승인하지 않는다. 필요한 시점에 기존 설정 재사용 여부와 안전한 목적지를 확인한다.

## 5. 전송 최소화·두 번의 확인

**확인1: 외부 전송/유료 실행**, **확인2: 변경안의 현재 계획 적용**은 별개다. 동의한 실행이 적용 승인이 아니다.

| 데이터 | D 기본 전송 제안 |
|---|---|
| 요청·선택 날짜/활동 | 작업에 필요한 내용만. 제목/자유문장에 개인 정보가 있을 수 있어 실제 전송 내용을 확인 |
| 장소 | 선택 활동/요청이 참조한 장소 ID·이름·필요 요약만. 전체 여행 장소를 무조건 보내지 않음 |
| 실제/메모 | 기본 제외. 사용자가 선택한 날짜/항목의 최신 유효 기록만 선택 포함, 원문/정정 전체 이력은 기본 제외 |
| 예약/숙박/첨부 | 비공개 예약값·숙소 상세·연락처·위치 이력·첨부 바이트·전체 본문·원천 파일 경로 기본 제외 |
| 보존용 식별자/필드 | 브라우저 내부 매핑·저장 검증에 필요한 값과 API에 보낼 DTO를 분리. 서버에도 필요한 최소 값만 전달 |

실행 요청 envelope, 공개 정보 조사 DTO, 변경안 작성 DTO를 분리하고 각 필드 허용 목록·크기/일수 한도를 검사한다.
웹 검색에는 정제한 공개 장소/질문만 전달한다. 연구 호출에 원래 자유 요청을 그대로 넣고 모델 지시만으로 비공개 검색 유출 방지를 보장하지 않는다.
모의 provider로 실제 전송 body/검색 입력을 대조한다. 사용자용 화면은 전체 JSON 대신 전송 범위·제외값·요약을 우선 보여주고 상세 미리보기를 제공한다.
동의는 정확한 payload 지문·기준 revision·서버/모델·한도에 연결한다. 입력/선택/정책이 바뀌면 동의를 취소한다.
재시도도 같은 범위인지 확인하며 더 넓은 자료·더 비싼 모델로 자동 전환하지 않는다.

## 6. 조사·출력·승인 저장

1. 로컬 일정/최신 실제 기록에서 요청 작성→자료/비용/대상 서버 확인→실행 동의.
2. 인증·소유권·payload/한도 검사→작업/예산 예약을 먼저 영속화→조사→구조화 변경안 생성→로컬 의미 검증.
3. 결과 회수→기준 revision 재확인→근거+초안을 StageAiProposal로 한 번에 저장. 계획/실제 기록은 변경하지 않음.
4. 근거·이유·예약 영향·활동 차이를 사용자 확인→기존 DecideProposal로 적용/거절→새 계획/과거/회고 재조회.

기존 item 연산만 핵심 범위로 사용한다. C의 수동 stay/leg 연산을 AI 허용 목록에 자동 편입하지 않는다.
기존 장소 밖의 새 장소는 존재하는 ID처럼 생성하지 않고 수동 작성/후속 확장 필요를 안내한다.
날짜/시각/참조·기존 ID로 add 금지·무관 필드 보존·예약/현장 필드 보호·고아 이동/소유 연결·여행 격리를 재검증한다.
웹 출처와 사용자 메모는 데이터이며 지시 권한이 없다. 외부 지시가 자동 적용·키 노출·외부 쓰기를 유도해도 실행하지 않는다.
URL 존재만으로 주장 검증 완료라 하지 않는다. 공식 출처·확인 시각·적용 날짜·불확실성/예약 영향이 읽혀야 한다.
근거는 클릭 가능한 인용과 고정 revision으로 보여주고 회고/백업/복원 뒤에도 당시 내용을 보존한다.

## 7. 비용·중복·취소

- 모델은 요청마다 서버 허용 목록에서 확정한다. 코드 기본 모델을 사용자 선택/계정 접근 증거로 간주하지 않는다.
- 작업·일일·기간 총액(통화/기준일 포함), 최대 입력/출력·검색/보정 횟수·동시 실행을 사용자 결정으로 설정한다.
  가격표/모델 기능 확인 날짜를 기록하고 미확인 가격/계정이면 실제 호출을 차단한다. 현재 문서에 가격/특정 권장 모델을 고정하지 않는다.
- 서버에서 추정 상한을 예약하고 각 외부 호출 전 잔여/토큰/도구 한도를 확인한다. 사용량·도구 호출·모델·가격 기준을 원장에 기록한다.
  일일 작업 수 제한만으로 금액 한도를 지킨다고 보고하지 않는다. 확정되지 않은 사용량은 비용 미확정으로 남긴다.
- 인증 소유자+requestId+payload 지문으로 중복 요청을 합치고, 서버 재시작 전후에도 외부 호출 intent/in-flight 상태를 보존한다.
- 응답 유실/서버 종료 때 제공자가 처리·과금했는지 모르면 자동 재호출하지 않는다. 예약액을 임의 해제하지 말고 ‘결과/비용 불명’으로 안내한다.
  이 경계에서 정확히 한 번의 외부 과금을 보장한다고 주장하지 않는다. 새 유료 시도는 남은 한도·전송 범위·사용자 동의로 결정한다.
- 중단은 후속 호출/적용을 멈춘다. 이미 처리된 호출의 취소·환불을 약속하지 않는다. 반복 보정·모델 fallback도 추가 한도를 소비한다.

## 8. 상태·복구·오프라인

| 층 | 상태/성공의 의미 |
|---|---|
| 서버 작업 | 기존 queued/researching/planning/validating/awaiting-decision/failed/cancelled/interrupted. awaiting-decision은 결과 준비이며 브라우저 저장 성공이 아님 |
| 브라우저 반영 | 결과 미저장/근거·초안 저장 완료/기준 변경으로 저장 보류/저장 실패. 동일 결과는 안정 요청 ID로 재회수·중복 방지 |
| 사용자 결정 | 미확인/거절/확인 후 적용. 적용에 성공해야 새 현재 계획, 실제 기록은 불변 |

서버 결과는 브라우저 저장 확인 전 너무 일찍 지우지 않는다. 저장 ACK/재회수·보관 기한 정책을 구현 전에 정한다.
원본 job 파일 손상 시 초기화/덮어쓰기 대신 보존하고 실행을 차단한다. 모의 복구와 실제 프로세스 강제 종료/재시작을 구분한다.
요청 성공 직후 응답 유실, 사용 중 브라우저 종료, Stage 실패/quota, 결과 저장 뒤 ACK 유실, 실제 기록 추가 뒤 stale를 시험한다.
장시간 휴대폰 백그라운드 후 인증 갱신·job 재조회가 기존 요청을 재실행하지 않아야 한다.
오프라인은 실행 불가와 기존 읽기/기록 가능을 구분한다. 자동 업로드/자동 유료 재시도/오프라인 작업 자동 적용은 하지 않는다.
서버 job 목록이 보인다고 다른 기기에 여행/초안이 복원된 것은 아니다. 원래 DB가 없으면 복원 절차를 안내하고 무관한 공간에 자동 Stage하지 않는다.

## 9. 보관·로그·공식 API 기준

앱/브라우저 여행 DB·서버 job/요청 지문·제공자 데이터 보관은 서로 다르다. 삭제/로그아웃/백업이 어느 복사본에 영향을 주는지 표로 안내한다.
서버 보관 기한·결과 삭제/ACK·실패 로그 보관은 미결정이다. 로그에는 키·전체 prompt/요청·예약·메모를 기본 기록하지 않는다.
최소 진단은 job ID·상태·모델·usage/도구 횟수·오류 코드·기준 지문으로 제한하고 공개 보고는 가상/비식별 증거만 쓴다.

2026-10-30 공식 문서 확인 기준(실제 운영 시 재확인):
- 웹 검색 결과를 사용자에게 표시할 때 인용이 보이고 클릭 가능해야 한다. [공식 웹 검색 문서](https://developers.openai.com/api/docs/guides/tools-web-search).
- 구조화 출력은 사실/의미 검증을 대신하지 않으며 refusal·미완성 응답을 처리해야 한다. [공식 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs).
- store:false를 ‘제공자가 어떤 데이터도 보관하지 않음’으로 설명하지 않는다. 기본 abuse monitoring·응답 저장·도구별 정책과 계정별 예외를 따로 확인한다.
  실제 사용 endpoint/모델/캐시/기능의 보관 조건을 전송 동의 전에 안내한다. [공식 데이터 관리 문서](https://developers.openai.com/api/docs/guides/your-data).

## 10. 사용자 결정·완료 조건

| 결정 | 필요한 내용·시점 |
|---|---|
| U-D1 접근/운영 | A/B/C·운영 주체/기기·로그인·origin 이동. 외부 접속/자료 이동 전 확정 |
| U-D2 모델/비용 | 조사/작성 모델·요청/기간 한도·추가 시도 정책. 계정/가격 확인 후 최초 실제 호출 전 확정 |

| U-D4 실행/확장 | 가상 최초 호출→선별 실제 여행 적용 시험·기기/배포 대상. 새 콘텐츠/stay/leg AI 확장은 별도 결정 |

지금 한꺼번에 답변을 요구하지 않는다. 모의/설계 작업은 독립 진행 가능하며 외부 접속·과금·자료 전송에 의존하는 단계만 기다린다.
D 종료는 실제 v2 조사→근거/초안→거절·확인 적용→회고/복원과 실패/중단/재시작을 확정 휴대폰 환경에서 검증하고 사용자 확인한 때다.
G-03/04/05/06/07 증거를 갱신하고 G3 판정은 핵심 범위·잔여/선택 확장을 명시해 사용자 확인을 받는다.
한 번의 실제 호출·모의 통과·PC 성공·서버 결과 JSON만으로 G3를 닫지 않는다. B/C 미확인·G4·AI 확장 전체를 자동 종료하지 않는다.
