## 1. 목표·기준

새 여행에 숙박과 날짜 안의 활동 간 이동을 작성·수정·제거하고, 저장→다른 화면 조회→재실행/오프라인→복원까지 이어 읽는다.
현재 5개 기본 탐색을 유지하며 오늘/전체 일정 안의 최소 편집 화면으로 제공한다. 새 대형 탭·내부 지도·자동 길찾기는 만들지 않는다.
AGENTS.md → handoff → 개발계획 → 요구/결정 → C 설계/계획 → C-01 검토·후속 CL-05를 읽는다.
현재 커밋을 보존하고 `codex/c02-stays-legs` 브랜치에서 진행한다. worktree·reset·main 병합·배포·실제 자료 적용·API 호출은 하지 않는다.
미추적 점검 문서·사용자 DB·기존 SP-FR/ZIP·원본·백업은 보존한다. 임의로 예전 main에서 시작하지 않는다.

## 2. 단위 A · 저장 계약·공용 시간 검증

- 기존 ChangePlan에 stay/leg의 upsert/remove 최소 연산을 추가한다. 새 날짜 생성·기간/날짜 삭제는 범위 밖이다.
- 기존 planStay의 `time` 범위를 입실/퇴실 입력에 대응한다. 모델에 없는 checkin/checkout 필드를 몰래 추가하지 않는다.
  leg는 같은 날짜의 fromActivityId/toActivityId를 참조한다. 구간 이동을 날짜 간 이동 기능으로 확장하지 않는다.
- expectedDomainRevision·currentPlanVersionId를 검사하고 한 트랜잭션에서 새 계획/모든 관련 행·현재 계획 포인터·receipt를 함께 저장한다.
  이전 계획·콘텐츠 revision·실제 기록·정정은 불변이다. 동일 요청 replay·중복 ID·다른 여행 참조·비활성 콘텐츠 참조를 검증한다.
- `applyPlan`은 현재 item 전용 분기를 가정한다. 모든 소비자와 검증/재가져오기/백업/명령 receipt 경로를 조사하고 종류별로 명시적으로 처리한다.
  새 연산 추가가 StageAiProposal/provider의 허용 범위를 자동 확장하지 않도록 기존 AI 경계를 유지한다. 실제 AI 기능은 구현하지 않는다.
- CL-05의 미지원 시간대 이름 허용을 먼저 가상 회귀로 재현한다. 새 여행·TimeEditor·새 수동 저장이 같은 검증 기준을 사용하도록 정리한다.
  유효 IANA 시간대·실재 날짜/시각·시작/종료 역전·확인 상태를 검사한다. 플랫폼 차이/별칭을 고려하고 고정 허용 목록을 임의 작성하지 않는다.
- 날짜만 확인된 입력은 날짜 정밀도로, 미확인 시간대는 미확인 상태로 보존한다. 자동으로 offset/instant를 발명하지 않는다.
  DST 누락 시각은 거부하고 중복 시각은 특정 instant로 몰래 확정하지 않는다. instant를 저장할 때 기존 offset/현지 시각 일치 검증을 유지한다.
- 신규 쓰기 검증 강화가 과거 데이터·구 파일/백업 읽기를 깨뜨리지 않도록 호환 경계를 검사한다.
  검증을 건너뛰거나 기존 자료를 재작성해 통과시키지 말고, 읽기 호환과 새 쓰기 규칙을 분리해야 한다면 결과에 명시한다.

## 3. 단위 B · 수동 숙박 의미·최소 화면

- 숙박 입력: 이름/거점, 선택 지역, 입실/퇴실 날짜(필요 시 확인된 시각/시간대). 예약 실행/새 예약 작성은 추가하지 않는다.
- 수동 숙박의 명확한 지역/현지 날짜만 사용해 day.regionIds(퇴실일 포함)·overnightRegionId(퇴실일 제외)를 독립 계산한다.
  방문 장소 지역을 숙박 지역으로 합치지 않는다. 0박은 하루 지역에만 포함하고 숙박 없음/지역 미상은 야간 지역을 추정하지 않는다.
- 같은 밤 다른 지역의 숙박이 겹치면 배열 마지막을 선택하지 않고 해당 저장을 보류/거부해 입력을 유지한다.
  시차로 날짜 대응이 모호하면 자동 덮어쓰지 않고 확인할 내용을 보여준다. 정확한 같은 경계/재방문 규칙은 가상 예제로 명시한다.
- 기존 `spfr-stays`는 원천 이행 의미다. 수동 검증/계산을 분리하고 기존 SP-FR/과거 계획을 열거나 저장했다는 이유로 일괄 재계산하지 않는다.
  숙박 변경으로 실제 영향받는 날짜만 새 계획에서 일관되게 갱신한다. 무관한 source 필드·기존 맥락·첨부/예약은 보존한다.
- 이동 입력: 같은 날 출발/도착 활동과 이동 수단, 선택 소요 시간/거리 설명. 외부 경로 조회를 자동 호출하지 않는다.
  활동 제거·날짜 이동 시 고아 leg가 남지 않게 하고, 연결 삭제 영향은 사용자에게 표시한다. 조용한 무관 행 삭제는 하지 않는다.
- 편집 완료 시 변경 요약과 이유를 확인해 명시적 저장한다. 오류/충돌 시 입력을 보존하고 과거 버전은 읽기 전용으로 유지한다.
  UI의 통상 선택은 현 구조의 최소안으로 완성한다. 새 제품 정책·비용/외부 영향 결정이 필요할 때만 질문한다.

## 4. 단위 C · 필수 검사·산출물

- 순수 계산: 실재/잘못된 날짜, 0박, 숙박 없는 날, 입퇴실 경계, 재방문, 겹친 밤, 미상 지역/시간대, 시차/DST 사례를 독립 기대값으로 검사한다.
- 저장: stay/leg 추가·수정·제거, 같은 명령의 복합 변경, 잘못된 endpoint/다른 날 활동·지역 참조, stale·다른 탭 실제 기록·replay·중간 실패 전체 롤백.
- 기존 C-01 소유 연결 보호와 T-05 구 baseline/추가 필드 검증, 재가져오기 충돌/보류·승인 전 불변을 유지한다.
  새 연산 때문에 과거 계획·원천 의미나 구 파일/백업이 변하지 않음을 검사한다. 기대값 일괄 교체로 실패를 숨기지 않는다.
- PC/모바일 E2E: 가상 여행/지역/활동→숙박·이동 생성→수정/제거→다른 화면·전체 일정 재조회→재실행.
  오류 입력 보존·과거 버전 표시·두 여행 격리, 통신 차단 상태의 저장/재조회, 전체 백업→빈 review 공간 복원을 포함한다.
- 최종 `pnpm run check:deferred`. 중간은 필요한 대상 검사만 수행하고 같은 코드의 포함 검사를 중복 실행하지 않는다.
- 사용자가 볼 산출물은 숙박/이동 편집 화면, 이동일/숙박 없는 날의 표시, 모호성 오류와 입력 유지, 이전 계획·복원 후 같은 내용이다.
  결과에 확인 동작·가상 입력·스크린샷 또는 실행 가능한 테스트/로그 위치를 적는다. 모바일 에뮬레이션은 실기기 확인과 구분한다.

## 5. 제출·범위 통제

시간 검증/계약·저장, 화면, 가상 회귀를 검토 가능한 커밋으로 나눈다. 필요한 구조 분리는 별도 커밋, 광범위 리팩터링은 금지한다.
`docs/claude-task-c02-result.md`를 별도 문서 커밋으로 작성해 기준/종료 SHA·계약 결정·검사/exit code·CI·증거·미검증을 기록한다.
작업 브랜치에 push하고 Codex 검토·사용자 확인은 대기로 둔다. 핵심 구현을 마치기 전 세부 단계별 승인을 요구하지 않는다.
경미한 새 문제는 영향/재개 조건과 함께 결과 보고에 남긴다. Codex가 후속 목록을 관리한다.
데이터 손실·격리·저장/복원·충돌·보안 문제는 보류하지 않는다. 해당 흐름을 수정·검증한 뒤 진행한다.
T-C4 가이드/메타데이터 편집 UI·회고·사진/지출·지역 ZIP·예약 추정·AI·배포·사용자 실자료 적용은 범위 밖이다.
상위 설계/계획 문서는 임의로 고치지 않고 차이/제안을 결과에 남긴다. 개인 데이터·예약·백업·키를 공개 커밋하지 않는다.
