## 수용 조건

1. 여러 날짜에 같은 order 값이 있고 ID/저장 순서가 날짜 순서와 다른 가상 계획으로 재현한다.
   기존 회귀가 충분하면 재사용한다. `get()`의 order 단독 정렬과 비교 함수의 배열 민감성을 따로 조사한다.
2. 같은 의미의 계획은 같은 비교 표현을 만든다. 원본 배열/과거 계획/실제 기록은 수정하지 않는다.
   정렬 기준은 날짜 행의 ordinal/안정 ID·항목의 dayId/order/안정 ID 관계로 명시한다.
   날짜/이동/숙박 배열까지 무조건 정렬하거나 차이가 나는 필드를 제거해 오탐을 숨기지 않는다.
3. 같은 패키지 재검토가 불필요한 app-only/conflict를 만들지 않는다. 정상적인 순서·날짜 이동·제목/시간 변경은 계속 탐지한다.
4. 실제 사용자 편집과 새 원천 변경이 겹치면 충돌·보류가 유지된다. 승인 전 계획 유지·revision/replay·과거 불변을 검사한다.
5. 구 v2·새 v3 패키지의 읽기/재가져오기와 T-04의 9일 지역 변경 탐지를 유지한다.

## 검증·제출

대상 단위/재가져오기 검사 후 최종 `pnpm run check:deferred`를 실행한다.
영향 있는 가상 PC/모바일 재가져오기 UI에서 같은 입력/실제 변경/보류 결과를 확인한다.
제품 기대값을 완화하지 않는다. 정렬이 바뀐 조회 소비자의 날짜별 표시·과거 버전도 확인한다.

T-04 후보·verified는 읽기 전용으로 두고 별도 사본/가상 DB에서만 실제 오탐 제거와 계획 차이9일 유지 여부를 확인한다.
사용자 프로필·iPhone에 적용하지 않는다. 실제 원문/ZIP/사진/예약·개인 로그를 공개 커밋하지 않는다.
`docs/claude-task-05-result.md`에 시작/종료 SHA·원인·변경 범위·재현 전후·검사/exit code·원격 CI·미검증을 적는다.
