> Sonnet이 조사→구현→시험 갱신→검증→스크린샷→커밋/push까지 자율 수행하세요. 최종 20줄/2,000자와 증거 색인을 제출하세요.

## 1. 화면 수정

1. **R1 날짜 머리 고정 위치**(`content.css` `.record-day > h3`): 상단 바(`.journey-topbar`, 최소 56px) 아래에 붙도록 `top`을 상단 바 높이로 맞춘다(CSS 변수 권장). 상단 바 배경이 비쳐 글자가 겹치지 않게 한다. 모바일·PC 모두 스크롤한 상태의 **뷰포트 스크린샷**(전체 캡처 아님)으로 증거를 남긴다.
2. **R2 다른 날로 정정된 기록**(`TimelineRecords.tsx`·`field-rules.ts` `dayRecordView`):
   - 배지: 최신 기록의 발생일이 계획 날짜와 다르면 날짜를 붙인다(`방문 1/1 00:30`).
   - 실제 발생일의 타임라인에 기록 카드를 둔다. 보조 문구 `12/31 계획 항목의 기록`. 동작은 기존 기록 카드와 같다(`정정`·`기록 탭에서 보기`).
   - 단위 시험: 계획 12/31·기록 정정 1/1 → 12/31 배지에 날짜, 1/1 카드 1건, 계획 항목 수 불변.
3. **회고 `ⓘ`**: 아이콘만이 아니라 `계획 설명` 같은 글자 단추로(눌러 펼침). 접근성 이름 유지.
4. **기록 행 `⋯`**: 펼쳤을 때 `정정`과 줄바꿈되지 않게(모바일 Pixel 7 폭 기준).
5. **가이드 장소 썸네일**: 장소에 사진이 있으면 행 왼쪽에 작은 정사각형(모바일 48px)으로 복원. 사진이 없으면 자리 비움 없이 글자만. 오프라인 사진 로딩 방식은 기존과 같게.

## 2. 삿포로 대본 v2 (축약 재수행)

1. 새 문서 `docs/u4-sapporo-scenario.md`: 기존 [c07 대본](c07-sapporo-scenario.md)을 **현재 화면의 단추 글자 그대로** 다시 쓴다. 검토 공간 `review=sapporo-u4`. c07 대본·[사용자 기록](c07-user-check.md)은 고치지 않는다(사용자가 쓴 기록).
2. 축약 기준(사용자 시간 30분 이내 목표):
   - S1 새 여행: 한 줄(기간·시간대 자동 적용 확인).
   - S2 가이드: 지역 2·장소 3개로 줄이고 **지역 묶음 화면**·검색 0건 `검색어 지우기` 확인.
   - S3 계획(Q-U2): 활동 5건, 종료 시각(다음 날 확인 포함), 시간대 자동, `일정 수정`의 **변경 이유** 입력(이제 메모로 우회하지 않음), 숙박 1건.
   - S4 현장(Q-U2·Q-U3·CL-21): **방문 한 번 누르기**, 정정으로 12/31 → 1/1 00:30, `예정 외 활동 기록` 저장 직후 **오늘 타임라인 기록 카드** 확인, `기록` 날짜 머리·`정정 N회 · 원문 보기`·`기록 더 보기`.
   - S5 회고(Q-U3): 버전 이름 형식, 추가/제거/이동 배지, `계획 설명`, 날짜 변화 표시.
   - S6 백업(S6-d): 여행 있는 공간에서 복원 비활성 이유 + `새 빈 공간 열기` → 복원 → 두 여행 확인.
3. 각 단계 표는 `할 일 / 확인할 화면 / 기대 결과` 3열 유지. 기대 결과는 화면 문구 그대로.
4. 새 확인 양식 `docs/u4-user-check.md`: 단계 S1~S6 + 전체 판단 칸(`확인 / 수정 요청 / 막힘`). 상태 줄 "확인 대기".
5. E2E: `tests/e2e/c07-sapporo.spec.ts`는 그대로 두고(회귀 보존), 새 `tests/e2e/u4-sapporo.spec.ts`가 v2 대본을 PC·모바일로 따라간다. 대본의 기대 문구를 그대로 단언한다.
6. 단계별 스크린샷 `docs/design/ui-u4/s1-…png`~`s6-…png`(PC·모바일). 대본 각 절에 링크해 사용자가 화면을 비교하게 한다.
