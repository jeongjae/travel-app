## 요약

- **A1 탐색:** 접힌 영역 3개(`여행 선택·가져오기`, `예약·기록·계획 도구`, `계획 버전·이행 점검`)와 헤더 `저장소·백업`을 없앴다. 하단 탭은 Codex 권장안 `오늘 · 일정 · 가이드 · 기록 · 더보기`이며 PC·모바일이 같다. 여행 전환·새 여행·가져오기는 헤더의 여행 이름(▾)을 눌러 연다.
- **A2 활동 카드:** 보이는 버튼은 `방문 기록`(채움), 연결 장소가 있을 때 `장소`, `⋯`뿐이다. 나머지 6개는 `⋯` 메뉴로 옮겼고, `일정에서 제거`는 확인 대화상자(연결 이동 N개 경고 포함)를 거친다.
- **A3 문구:** `검증용 저장소` 배너를 헤더의 `검토 공간` 배지로 바꿨다. `FIRST`·영문 하루 유형(`TRANSFER DAY` 등)·`저장 정보`를 한국어로 바꿨다.
- **C1~C4 하루 머리:** 날짜는 `12월 31일 (목) · 1일차` 한 번만 쓴다. 날짜 선택 상자 대신 날짜 띠를 남겼다. `첫 일정` 카드는 없애고 `지금·다음` 카드는 여행 중 오늘일 때만 보인다. 하루 지역·밤 지역은 머리 아래 한 줄이고, 숙박은 머리, 이동은 타임라인 안에서 그 자리에서 수정한다. 아래쪽 `지역·숙박·이동` 중복 섹션은 추가 버튼만 남겼다.
- **D1:** Pixel 7(390×844) 삿포로 1일차 첫 화면에 활동 3개가 모두 보인다. 시험 기준은 2개 이상이다.
- **D3:** 버튼은 기본(채움)·보조(외곽선)·위험(붉은 글자) 3종이다. 색 토큰은 디자인 명세의 녹색 계열(`--green #2d6553` 등)로 맞췄고 헤더는 흰 바탕으로 본문 톤에 맞췄다.
- 저장 명령·스키마·백업/패키지 형식·검증 규칙·기록/정정/회고의 데이터 의미, v1 화면은 바꾸지 않았다. C-06·C-07 통합 시험은 단언 변경 없이 통과한다.

## 판단 근거

| 항목 | 판단 |
|---|---|
| 날짜 띠 vs 선택 상자 | 띠를 남김. 모바일에서 한 번에 누를 수 있고 현재 위치가 보인다. 긴 여행은 활성 날짜가 자동으로 보이도록 가로 스크롤한다. 선택 상자는 두 번 눌러야 하고 앞뒤 날짜를 보여 주지 않는다. |
| 준비를 탭으로 둘지 | 권장안을 유지해 `더보기 > 준비·회화`. 탭은 5개가 한계이고, 현장(오늘·기록)보다 사용 빈도가 낮다. |
| `⋯` 메뉴 접근성 | `role="menu"` 대신 disclosure 패턴(`aria-expanded`/`aria-controls`, 항목은 일반 버튼)을 썼다. Tab 이동이 그대로 되고, Esc로 닫히며 초점이 토글로 돌아온다. 토글 이름은 `{활동} 더보기 메뉴`이고 `위로/아래로`의 접근 이름(`{활동} 위로`)은 유지했다. |
| 검토 공간 진입 | 여행이 없을 때는 하단 탭이 없으므로 시작 화면에 `저장소·백업` 버튼을 두었다(복원 경로 유지). |
| 하루 상세(DayDetails) | 날짜·도시·유형·거리·피로도가 머리와 겹쳐 지웠다. 시각이 있는 날만 시각을 보인다. 소요 시간은 머리 줄로 옮겼다. |

## 남은 후보 (U1 밖, 판단은 Codex·사용자)

- 대본(`docs/c07-sapporo-scenario.md`)의 버튼 이름 갱신은 U4 몫이다.
- `가이드` 화면의 목록·검색 배치, `기록` 화면의 폼·카드 정리는 U2.
- PC 너비에서는 하단 탭이 화면 아래 가운데에 놓인다. 상단 탭이 더 나은지는 사용자 확인 뒤 판단한다.
- v1 `styles.css`의 `.day-toolbar` 규칙이 콘텐츠 화면까지 닿아 `journey.css`에서 덮었다. 이름 공간 분리는 구조 정리 후보다.
- 실기기(iPhone·Android)는 확인하지 않았다.
