## 1. 목표·기준

예정 외 활동에 장소를 선택하거나 장소 없이 기록하고, 방문/건너뜀·메모·실제 시각을 저장한 뒤
실제 기록 화면에서 다시 읽고 정정 전후를 확인한다. 계획을 바꾸어도 기록·당시 맥락이 남아야 한다.
기본 5개 탐색을 유지하고 기존 실제 기록 보조 도구를 보강한다. 회고 비교 화면(T-C6)은 이번에 만들지 않는다.

현재 커밋을 보존하고 `codex/c04-field-records` 브랜치에서 진행한다. worktree·reset·main 병합·배포·API 호출은 하지 않는다.
사용자 DB/원본/개인 ZIP/백업·미추적 점검 문서를 보존한다. 이전 main의 오래된 코드에서 시작하지 않는다.

## 2. 단위 A · 실제 기록·장소 연결

- 기존 방문/건너뜀/예정 외 활동을 재사용한다. 예정 외 활동은 같은 여행의 활성 장소 선택 또는 장소 없이 저장 가능해야 한다.
- placeRef와 contextRefs는 기존 계약대로 저장한다. 다른 여행·없는/비활성 장소의 새 연결을 거부하고 당시 본문 revision을 고정한다.
  기존 비활성 장소를 참조하는 과거 기록은 계속 읽혀야 한다.
- 새 장소가 필요하면 C-01의 장소 작성→저장 후 실제 기록의 두 명시적 저장으로 연결한다.
  장소 작성과 기록을 한 번의 원자 저장처럼 표현하지 않는다. 기록 저장에 실패해도 유효한 장소는 남으며 실패/재시도가 분명해야 한다.
- 실제 활동과 계획 항목 연결은 서로 다른 의미다. 예정 외 활동을 기록해도 계획에 항목을 자동 생성하지 않는다.
  사용자가 확인하지 않은 장소/날짜/시각을 계획·현재 위치에서 추정해 확정하지 않는다.
- 입력 오류·저장 중·충돌 때 내용 보존과 상태 표시, 중복 클릭 방지를 제공한다.
  새 recordId·requestId는 같은 입력 재시도에서 안정적으로 재사용하고 입력이 달라지면 기존 receipt를 잘못 재사용하지 않는다.

## 3. 단위 B · 추가식 정정·당시 맥락 재조회

- CorrectActual/supersedes로 새 기록을 추가한다. 원본과 이전 정정은 수정/삭제하지 않는다.
  최신 정정·정정된 원문을 구분해 타임라인에서 이어 읽게 하고 정정 체인이 길어도 연결이 유지돼야 한다.
- 메모만 정정할 때 time.end·시각 정밀도/offset/instant·sourceRefs·placeRef·계획/활동 연결·contextRefs 등
  편집하지 않은 필드를 잃지 않게 한다. 새 폼을 이전 기록 일부 필드만으로 재조립해 정보를 비우지 않는다.
- 계획 항목이 나중에 수정/제거되거나 장소 이름/본문이 바뀌어도 기존 실제 기록은 당시 맥락으로 읽혀야 한다.
  정정에서 장소/시각을 명시적으로 바꾸는 경우 새 참조/맥락을 검증하되 원본의 당시 맥락은 보존한다.
- expectedDomainRevision과 기존 supersedes 최신 여부를 검증한다. 다른 탭이 먼저 기록/정정하면 stale 저장을 거부한다.
  적용 전 입력을 보존하고 최신 상태를 검토하게 한다. 오래된 원문으로 분기 정정하거나 현재 계획 값으로 과거를 덮어쓰지 않는다.
- AddNote/기존 메모 재조회 회귀를 유지한다. 현장 기록·정정·메모 저장은 계획 버전을 만들거나 과거 계획을 바꾸지 않는다.
- 날짜가 지났다는 이유로 실제 기록/정정을 잠그지 않는다. 미상 시각은 미상으로 남기고 기존 시간 계약을 사용한다.

## 4. 단위 C · 필수 검사·산출물

- 가상 저장 검사: 장소 있음/없음, 잘못된/비활성/다른 여행 참조 거부, 실제 기록+맥락 고정, 계획 불변·두 여행 격리.
- 정정 2회 이상, 이미 정정된 원문 재정정 거부, stale·다른 탭 기록·replay·중간 쓰기 실패의 전체 롤백을 검사한다.
- 메모만 정정하는 입력에 time.end·확정 instant/offset·장소/계획 참조·sourceRefs가 있는 fixture를 써서 무관한 값 보존을 확인한다.
- 장소 본문/이름 변경·계획 변경/항목 제거 뒤에도 정정 체인·당시 내용이 읽히는지 검사한다. 현재/과거 라벨을 혼동하지 않는다.
- PC/모바일 E2E: 방문/건너뜀/예정 외 기록→다른 화면에서 찾기→열어 읽기→정정 전후 조회→재실행.
  기존 장소 선택·장소 없음·새 장소 선행 저장, 오류 입력 보존·메모 재조회·계획/실제 분리를 확인한다.
- 통신 차단 중 기록/메모/정정→재실행 조회, 두 여행 전체 백업→빈 review 공간 복원 후 정정 원문/최신/맥락 재조회를 포함한다.
  모바일은 에뮬레이션과 iPhone 확인을 구분한다. 사용자 프로필·실제 여행 자료를 테스트에 쓰지 않는다.
- 최종 `pnpm run check:deferred`. 중간은 대상 검사만 실행하고 같은 코드의 포함 검사를 중복 실행하지 않는다.
- 사용자가 볼 산출물은 예정 외 활동 장소 선택 화면·실제 타임라인·정정 전후·당시 장소 설명·복원 후 같은 기록이다.
  결과에 재현 동작과 가상 입력·스크린샷 또는 실행 가능한 테스트/로그 위치를 남긴다.
