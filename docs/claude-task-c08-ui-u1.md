## 2. 범위

1. **탐색 한 체계(A1).** 접힌 영역 3개를 없애고 하단 탭을 사용 단계 기준으로 재편한다. Codex 권장안:
   `오늘 · 일정 · 가이드 · 기록 · 더보기`. `더보기`에 준비(기존 탭), 예약·할 일, 변경안, 지도, 계획 버전, 저장소·백업을 둔다. 준비를 독립 탭으로 두는 편이 낫다고 판단되면 근거와 함께 제안한다.
   여행 전환·새 여행·가져오기는 헤더의 여행 이름을 눌러 연다. 현재 탭별 기능을 먼저 조사해 빠지는 기능이 없음을 표로 보인다.
   권장안이 기존 기능과 충돌하면 이유와 대안 1개를 함께 제시한다. 데스크톱도 같은 체계(하단 또는 상단 탭)를 쓴다.
2. **활동 카드 버튼(A2).** 보이는 버튼은 `방문 기록`과 연결 장소가 있으면 `장소`만. 나머지(건너뜀 기록·일정 수정·위로·아래로·메모·일정에서 제거)는 카드의 `⋯` 메뉴로.
   제거는 메뉴 안에서 확인 대화상자를 거친다(C4의 연결 이동 경고를 여기로 옮김). 키보드·화면낭독기 접근 이름을 유지한다.
3. **문구(A3).** `검증용 저장소` 배너는 검토 공간일 때 헤더의 작은 배지로. `FIRST`·`저장 정보` 같은 영문/내부 라벨 제거.
4. **하루 머리(C1~C3).** 날짜는 한 번만: 예) `12월 31일 (목) · 1일차`. 날짜 탭과 선택 상자 중 하나를 남긴다(모바일 기준 판단, 이유 기록).
   `첫 일정` 카드는 여행 기간 중 오늘이면 `지금/다음` 카드, 그 외 제거. 숙박·이동은 타임라인 안 한 곳에만 두고 그 자리에서 수정.
   하루 지역·밤 지역은 날짜 머리 아래 한 줄. 아래쪽 `지역·숙박·이동` 섹션의 중복 표시는 없앤다(추가 버튼은 남김).
5. **모바일 첫 화면(D1).** Pixel 7(390×844)에서 스크롤 없이 첫 활동 2개 이상이 보여야 한다.
6. **버튼·색 위계(D3).** 기본(채움)·보조(외곽선)·위험(붉은 글자) 3종과 색 토큰을 `content.css`/`journey.css`에 정리. 디자인 명세의 녹색 강조 계열과 맞추고, 헤더 색을 본문 톤과 맞춘다.

## 3. 시험·검증

- 버튼/라벨 이름이 바뀌면 기존 E2E를 고친다. **같은 동작·같은 단언을 유지**하고 단언을 지우거나 약화하지 않는다. 바뀐 선택자 대응표를 결과에 남긴다.
- 새 검사: 하단 탭으로 기존 모든 기능에 도달(기능 목록 표 기준), `⋯` 메뉴 동작과 제거 확인, 모바일 첫 화면에 첫 활동 2개 노출, 날짜 머리 1회 표기.
- 최종 `pnpm run check:deferred`. C-06·C-07 통합 시험이 그대로 통과해야 한다(데이터 의미 불변의 증거).
- 모바일은 Pixel 7 에뮬레이션이며 실기기가 아니다.

## 4. 시제품 제출(Q-U1)

- 삿포로 대본 S1~S5를 새 화면에서 수행한 상태로 **전후 스크린샷**을 `docs/design/ui-u1/`에 남긴다: 오늘(PC·모바일), 일정, 가이드, 기록 진입, 더보기, 활동 `⋯` 메뉴, 제거 확인. 진단 화면과 같은 장면을 짝지어 비교표로 만든다.
- 사용자 확인 동작: `pnpm run build; if ($?) { pnpm run preview:ui }` 후 `http://127.0.0.1:4173/?workspace=content&review=<새 이름>`에서 삿포로 대본 S1~S4를 따라 하며 메뉴·버튼을 찾을 수 있는지. 대본의 버튼 이름 갱신은 U4에서 하므로, 바뀐 이름 대응표를 결과에 함께 준다.
- 상태는 `Codex 검토 대기 / 사용자 시제품 확인 대기`. 사용자 확인 전 U2·U3를 시작하지 않는다.
