## 1. E2-A

### A1 내보내기 변환 (화면 없음, 순수 함수)

- `exportPlan(trip, plan, options)` → 양식 글. `options`: 날짜 범위(없으면 전체), 예약 메모 포함 여부.
- 형식은 [규격 §6](plan-format-v1.md)과 [예시](examples/plan-export-sapporo.md): 머리 줄 7개(여행ID·기준계획·기준revision은 내부 값 그대로), 인용 글 규칙 6줄(예시와 같은 문장 — **한 곳에서 관리**), 날짜별 일정 표(모든 줄에 ID), 숙소 표, 빈 `## 삭제` 표. `## 이동`·`## 장소`는 내보내지 않는다(E2-B에서 장소 표 추가).
- 칸 안의 `|`는 `\|`, 줄바꿈은 공백으로 바꾼다(바꾼 줄은 경고로 돌려준다 — 왕복이 깨지는 유일한 경우다).
- 시간: 내부 시간 → 규격의 4표현. 표현할 수 없는 시간(다른 날짜에 시작 등)은 내보내기를 막지 말고 그 줄 메모 끝에 원래 시간을 글로 남기고 시간 칸은 비운다. 이런 줄은 경고로 모은다.
- 날짜 범위: 그 날짜의 일정 표만, 머리에 `- 범위:` 줄, 숙소는 범위와 겹치는 것만.
- **시험의 핵심(AC-04)**: T-E1의 고정 자료 2개로 새 여행을 만든 뒤 `exportPlan` → `parsePlanFile`·`checkPlanFile` → A3의 변경 계산 = **변경 0건**. 가상 여행(자정 넘김, 시간 미정, 메모에 `|`, `[장소: …]`, `[숙소 지역: …]`, 숙소 2곳)에서도 0건.

**A1 중간 보고** 뒤 멈춘다. → **A1 통과(11/18, [검토](claude-task-e02-review.md)).**

### A1 검토 뒤 보완 (A2~A4에 적용)

1. A1 시험의 "칸이 같다" 확인을 A3의 **변경 계산 결과 0건**으로 바꾼다(고정 자료 2개 + 가상 여행 + 예약 포함).
2. A2 화면은 `exportPlan`의 경고를 복사 전에 보여 준다: "이 n줄은 그대로 다시 가져와도 수정으로 보입니다"(표현 못 하는 시간·줄바꿈). `id-format`은 "이 줄은 다시 가져올 때 오류가 됩니다".
3. A3: 장소 칸과 메모 칸은 저장 값 하나(`summary`)로 합친다. 한 칸만 바뀐 줄에서 다른 칸의 현재 값을 보존한다. 장소 칸 `(비움)` = 메모 앞 `[장소: …]` 표시를 뺀다. 연결된 장소가 있는 활동의 장소 칸이 다른 이름으로 오면 연결은 그대로 두고 메모 앞에 적으며, 미리보기에 "연결된 장소는 바뀌지 않습니다"를 붙인다.
4. A3·A4: 머리의 `- 범위:` 줄은 오류·경고 수에 넣지 않고 "범위 내보내기"라는 정보로만 보여 준다.
5. 기준revision은 여행 전체 값이라, 복사한 뒤 그 여행에 다른 저장이 있으면 붙여넣기가 막힌다. **어떤 동작이 `domainRevision`을 올리는지 조사해 결과 문서에 적는다**(계획 수정 외에 현장 기록·예약·콘텐츠 저장 등). 막혔을 때 글: "복사한 뒤 이 여행에 다른 변경이 저장됐습니다. 다시 'AI로 수정하기'로 복사해 작업하세요." 우회·자동 병합은 만들지 않는다.

### A2 "AI로 수정하기"

- 여행 화면(여행 메뉴 또는 일정 화면의 메뉴)에 **"AI로 수정하기"**. 범위(전체 / 날짜 범위)와 "예약 메모도 넣기"를 고르고 **복사**. 복사되는 글:

```text
아래는 travel-app에 저장된 최신 여행 계획이다. 이것을 기준으로 내 요청대로 고쳐 줘.
바뀐 부분만 같은 형식의 markdown 코드 블록 하나로 돌려줘. 규칙은 아래 글 안에 있다.

[요청] (여기에 고칠 내용을 적으세요)

{내보내기 글}
```

- 복사 전에 나가는 글 전체와 글자 수를 볼 수 있다. 글자 수가 40,000자를 넘으면 날짜 범위를 권한다(사용자 확정 11/18). 복사가 막히면 글을 펼쳐 보여 준다. "파일로 저장"도 둔다.
- 서버 호출 없음. 오프라인에서 동작.

### A3 변경 계산 (화면 없음, 순수 함수)

- 입력: `checkPlanFile`의 `kind: 'update'` 결과 + 현재 여행·계획. 출력: `{ target, changes[], unchanged[], skipped[], errors[] }`와 `ChangePlan`에 넣을 `planEditOperation[]`.
- 대상 확인([설계서 §4.3-3](ai-rework-requirements-design.md), AC-08·17): 여행ID가 현재 여행과 다르면 거부. 기준계획·기준revision이 현재 값과 다르면 **적용 불가**로 돌려준다("다시 'AI로 수정하기'로 복사해 작업하세요").
- 줄 맞추기:
  - ID 있는 줄: 그 활동·숙소를 찾는다(없는 ID·종류 불일치는 오류). **빈 칸은 변경 없음, `(비움)`은 지움**. 바뀌는 칸만 모아 `upsert-item`/`upsert-stay`로 만든다. 바뀌는 칸이 없으면 `unchanged`(규격 §7).
  - ID 없는 줄: 새 항목. 같은 날짜·같은 제목(숙소는 이름·체크인)의 기존 항목이 있으면 **기본 "건너뜀"** 후보로 표시한다(AC-09).
  - 날짜가 다른 표로 옮겨진 ID 있는 줄: 그 날짜로 옮긴다(미리보기에 "날짜 이동"으로 표시).
- 삭제: `## 삭제`의 종류·ID만. 종류 불일치·없는 ID는 오류(AC-10·18). 파일에 없는 항목은 그대로.
- 장소 칸: G-b와 짝이 되는 규칙 — 값이 연결된 장소의 이름과 같으면 변경 없음, 아니면 메모 앞 `[장소: 값]`으로(E2-B 전까지).
- 시간 규칙·표 제외는 T-E1과 같다. 오류가 있는 표의 줄은 변경에 넣지 않는다.
- 지워지는 활동을 가리키는 이동(`planLeg`)이 있으면 그 삭제는 **오류로 막는다**(이동은 앱 화면에서 먼저 정리 — AC-11의 참조 무결성).
- 시험: E0 2회차의 T2·T3 4개를, 예시 내보내기 글에서 만든 가상 여행에 적용 → 메모만 바뀜·새 줄 1개·링크 지움·삭제 1개가 정확히 나온다(AC-15). 오래된 기준, 다른 여행, 중복 ID, 같은 글 두 번(두 번째는 새 줄이 "건너뜀" 후보), 일부만 든 날짜 표(나머지 불변), `(비움)`을 필수 칸에.

### A4 미리보기·적용

- "AI 결과 붙여넣기"가 `update` 글을 받으면(지금은 "다음 단계에서 지원") **현재 열려 있는 여행**과 대조한 미리보기를 보여 준다. 여행ID가 다른 여행이면 그 여행 이름을 알려 주고 멈춘다.
- 미리보기 묶음: 추가 · 수정(칸별 이전 → 이후, 지워지는 값 강조) · 삭제(제목·개수) · 변경 없음(접힘) · 건너뜀 후보 · 오류 · 가져오지 않음. 항목마다 체크로 넣고 뺄 수 있다(건너뜀 후보는 기본 해제).
- **고른 결과 전체를 다시 검사**한 뒤(AC-11) "적용" → `ChangePlan` 1회. 사유(`reason`)는 "AI 결과 붙여넣기: 수정 n·추가 n·삭제 n". 성공하면 새 계획 버전, 이전 버전 조회 가능(AC-05). 실패하면 아무것도 바뀌지 않고 입력·미리보기가 남는다(AC-14).
- 미리보기 중 계획이 바뀌었으면(다른 탭 등) 적용이 거부된다 — 그 오류를 "계획이 그사이 바뀌었습니다. 다시 복사해 작업하세요"로 보여 준다.
- E2E: 내보내기 → (챗봇 대신 글을 고쳐) 붙여넣기 → 미리보기 수치 → 적용 → 일정 화면·이전 버전. 오래된 글 차단. 일부만 골라 적용. 저장 실패 주입(가능하면 `repo.execute`를 실패시키는 시험 훅 없이 — 불가능하면 단위 수준에서 확인하고 그렇게 적는다).

## 2. E2-B

### B1 장소 단계

- 내보내기에 `## 장소` 표(ID·이름·지역·설명·영업시간·링크)를 더한다: 이 여행의 활동에 연결된 장소만.
- 가져오기(새 여행·기존 여행 모두)에 **장소 단계**를 더한다([설계서 §4.3 장소](ai-rework-requirements-design.md)): ① 새 장소 후보(장소 표의 ID 없는 줄 + 일정의 장소 칸 중 기존 장소·장소 표에 없는 이름)를 보여 주고 고른 것만 `CreateContentBatch`로 만든다(한 번에 최대 20개 — 넘으면 나눠 만들고 진행을 보여 준다) ② 그 결과를 기준으로 계획 미리보기·적용. 각 단계는 따로 승인하고, 승인하지 않은 변경은 남지 않는다(AC-16).
- **새 여행**: 여행을 먼저 만들고(`CreateTrip`, 장소 이름은 메모) → 장소 단계 → 연결(`ChangePlan`) 순서다. 중간에 멈추면 여행은 있고 장소 이름은 메모에 남아 있다(조용한 손실 없음). 이 순서와 중간 상태를 화면에 알린다.
- 기존 장소와 이름·지역이 같으면 "연결" 후보로 보여 주고 자동으로 합치지 않는다.
- 장소 콘텐츠의 필수 값이 무엇인지 `src/contracts/v2/content.ts`의 `place` 스키마에서 확인하고, 양식 표로 채울 수 없는 필수 값이 있으면 **멈추고 보고한다**.

### B2 메모의 `[장소: 이름]` 살리기

- T-E1·E2-A로 들어온 활동의 메모 앞 `[장소: 이름]`을 모아 "장소로 만들기" 후보로 보여 주는 화면(여행 메뉴). 고른 것만 장소로 만들고, 연결한 뒤 메모에서 그 표시를 뺀다. `ChangePlan` 1회.

## 3. 멈추고 보고할 때

- 데이터 경계 4경로를 바꿔야 할 것 같을 때. `ChangePlan`이 필요한 연산을 거부할 때.
- 왕복이 0건이 되지 않는 경우를 규칙으로 풀 수 없을 때(추측해 맞추지 않는다).
- 같은 오류를 2번 시도해도 못 풀 때.
