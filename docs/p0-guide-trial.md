# P0 · 목적지 가이드 시험 (코드 없음)

2026-11-13 · 작성: Codex 역할 세션 · 상태: **검토 준비 / 사용자 시험 대기** · 근거: [설계서 v0.5](ai-rework-requirements-design.md) §4.8·§5, [계획 준비 제안 원문](ai-rework-prep-proposal-2026-11-13.md)

목적: 코드를 쓰기 전에 두 가지를 확인한다.
1. 챗봇이 **가이드 양식**(`travel-app-guide/1`)을 지켜 목적지 가이드를 내는가(G-1의 대안 B가 되는가).
2. 가이드에서 고른 항목이 든 **요청서**로 계획을 만들면, 고르지 않고 시작한 것보다 나은가("대화 전에 큰 그림을 정할 수 있는가").

가상 여행만 쓴다. 실제 예약·개인 정보를 넣지 않는다.

## 1. 가이드 요청문 (선 사이를 그대로 챗봇에 붙여 넣는다)

---

{목적지}를 {기간}에 여행하려고 한다. 일정을 짜기 전에 무엇을 보고, 먹고, 체험할 수 있는지 큰 그림을 보고 싶다. 아래 "가이드 양식"으로 목적지 가이드를 만들어 줘.

## 가장 중요한 규칙

A. 결과물은 **이 대화 안의 `markdown` 코드 블록 하나**다. PDF·Word·따로 만든 요약표로 내지 않는다.
B. 양식 밖의 열·구역을 만들지 않는다. 설명은 코드 블록 밖에 짧게 쓴다.
C. 항목은 25~35개. 처음 가는 사람이 큰 그림을 잡을 수 있게 고른다.
D. 영업시간·요금·예약 가능 여부처럼 **바뀌는 정보는 적지 않는다.** 대신 `확인 필요` 칸에 무엇을 확인해야 하는지만 적는다(예: "개장 시간", "예약 필수 여부"). 지어내지 않는다.
E. 확실하지 않은 장소·가게는 넣지 않는다.

## 가이드 양식

1. 첫 줄 `# 가이드: 목적지`, 이어서 `- 양식: travel-app-guide/1`, `- 기준일: YYYY-MM-DD`(오늘 날짜).
2. 구역은 `## 항목` 하나, 표 하나다. 열 이름과 순서는 아래와 똑같이 쓴다.
3. `종류`는 볼거리 · 먹거리 · 체험 · 코스 · 지역 중 하나.
   - `코스`: 가까운 곳을 묶은 반나절·하루 코스. 설명 칸에 "A → B → C"로 적는다.
   - `지역`: 숙소·관광의 거점이 되는 구역. 설명 칸에 분위기와 어떤 사람에게 맞는지 적는다.
   - `먹거리`: 특정 가게가 아니라 음식 종류나 식사 경험으로 적어도 된다.
4. 한 줄이 한 항목이다. 칸 안에서 줄을 바꾸지 않는다. 칸 안에 `|`가 필요하면 `\|`.
5. `예상 소요`는 "1시간", "2~3시간", "반나절", "하루", "식사 1회" 같은 짧은 말.

```markdown
# 가이드: 
- 양식: travel-app-guide/1
- 기준일: YYYY-MM-DD

## 항목
| 종류 | 이름 | 지역 | 한 줄 설명 | 예상 소요 | 확인 필요 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |
```

## 2. 할 일 (사용자, 약 30분)

| 시험 | 챗봇 | 하는 일 |
|---|---|---|
| G1 | ChatGPT, Claude 각각 새 대화 | 가이드 요청문의 `{목적지}`·`{기간}`을 채워 붙여 넣는다(예: 교토·오사카, 2027년 5월 3박 4일). 받은 가이드 2개를 Codex 세션에 붙여 준다 |
| G2 | 둘 중 하나 | 가이드를 읽고 항목마다 **꼭 포함 / 관심 / 제외**를 정한다(종이나 메모로). 걸린 시간과, 고르기에 정보가 충분했는지 적는다 |
| G3 | 같은 챗봇 새 대화 2개 | (가) [계획 안내문](plan-format-v1-prompt.md) + "같은 목적지·기간으로 계획을 짜 줘, 정리해 줘" (나) 같은 것 + 아래 "고른 항목" 묶음. 두 계획을 비교한다 |

G3 (나)에 덧붙이는 묶음:

```text
[꼭 포함] 항목 이름들
[관심] 항목 이름들 — 여건이 되면 넣어 줘
[제외] 항목 이름들 — 넣지 말아 줘
```

## 3. 판정 (Codex가 채움, 사용자 의견이 우선)

| 질문 | 기준 |
|---|---|
| 가이드 양식을 지키는가 | 2개 모두 머리 줄·열 이름·열 개수·종류 값이 규칙과 같다 |
| 바뀌는 정보를 지어내지 않는가 | 영업시간·요금이 본문에 없고 `확인 필요`로 갔다 |
| 고르기에 쓸 만한가 | 사용자 평가: 큰 그림이 잡혔는가, 모르는 항목을 고를 수 있었는가, 15분 안에 끝났는가 |
| 계획이 나아지는가 | (나)가 꼭 포함을 모두 넣고 제외를 넣지 않았는가. 사용자 평가: (가)보다 내 뜻에 가까운가 |
| 결론 | 넷 다 "예" → P1(가이드 붙여넣기·선택 화면) 진행 제안. 아니면 무엇이 모자랐는지 적고 방식(G-1)을 다시 본다 |
