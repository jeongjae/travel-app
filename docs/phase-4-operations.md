# 운영 설명서 — 백업·복원·전환

2026-11-23 · 현재 앱 화면 기준(단추·메뉴 이름은 실제 화면에서 확인). 이전 판: [history/phase-4-operations-2026-10-23.md](history/phase-4-operations-2026-10-23.md). AI 서버(Worker)는 [runbook-worker.md](runbook-worker.md)가 맡는다. 캡처는 가상 여행 자료로 만들었다(`design/e05-1/`).

## A. 전체 백업 만들기 → 파일 저장

1. 앱을 열고 여행 화면 아래 탭에서 **더보기** → **저장소·백업**을 누른다. (여행이 없는 첫 화면에서는 "전체 백업에서 되살리기: **저장소·백업**".)
2. **전체 백업 만들기**를 누른다. 끝나면 "전체 백업 생성 완료 · N개 여행 · 기준 순번 …"이 뜨고 **검증한 전체 백업 파일 저장** 링크가 생긴다.
3. 링크를 눌러 파일을 저장한다. 이름은 `travel-app-backup-<고유번호>.zip`. 앱 소스·`pilot.zip`(원천 패키지)과 다른 파일이다.
4. 크기·시간: 가상 여행 1개(사진 2장)로 PC에서 약 17.8 KB, 1초 미만. 실제 여행(사진·PDF 포함)은 크기와 시간이 훨씬 커진다 — **미확인**(실제 자료로 측정한 기록 없음).
5. iPhone: 파일 앱 저장 성공은 사용자가 확인했다([phase-2-prime-runbook.md](phase-2-prime-runbook.md)). 저장 위치(폴더)는 저장 창에서 고른 곳이며 정확한 기본 위치는 **미확인**.

## B. 다른 매체로 옮기기 전후에 적어 둘 것

파일 이름 · 크기(바이트) · 저장 시각 · 앱 판(배포 날짜 또는 커밋) · 보관한 매체. 옮긴 뒤 같은 이름·크기인지 비교한다. 실제 백업 파일은 Git에 올리지 않는다. `travel-app/backup/`은 같은 디스크의 사본이므로 다른 매체가 아니다.

## C. 빈 검토 공간에 복원하기

평소 공간에는 바로 복원하지 않는다. 복원은 **빈 공간에서만** 되고(여행이 있으면 앱이 거절), 검증하지 않은 파일이 평소 자료를 바꾸지 못하게 하려는 것이다.

1. 평소 공간의 **저장소·백업** 화면에서 **새 빈 공간 열기**를 누르면 새 탭이 `?workspace=content&review=restore-날짜-번호` 주소로 열린다. 다른 기기·브라우저에서는 앱 주소 뒤에 같은 형태를 직접 붙인다(`review` 값은 영문 소문자·숫자·`-`, 40자 이내). 화면 위에 **검토 공간** 표시가 보이면 평소 자료와 분리된 공간이다.
2. 빈 공간에서 (여행이 없는 첫 화면의 "전체 백업에서 되살리기: **저장소·백업**" 또는 더보기) **저장소·백업**을 연다.
3. **전체 백업 복원 (travel-app-backup-*.zip)**에서 백업 파일을 고른다(`pilot.zip`이 아니다). "백업 파일 검증 완료. 복원 내용을 확인하세요." 와 "복원 미리보기: N개 여행 · 기준 순번 …"이 뜬다.
4. **확인 후 전체 복원**을 누른다(취소는 **복원 보류**). "전체 복원 완료. 복원한 여행은 이 공간(…)에 있습니다."가 뜬다.
5. 확인할 것: 여행 수(미리보기의 N과 같은지), 한 여행의 일정·사진·메모·현장 기록, 계획 버전(더보기 → **계획 버전**의 과거 버전), 장소(일정의 **장소**).
6. 가상 여행 실측: 복원 약 0.25초.

## D. 복원이 실패했을 때

- 백업이 아닌 파일을 고르면 입력란 아래에 빨간 글씨로 오류가 뜬다. 문구: "전체 백업 파일이 아닙니다. travel-app-backup-…zip 파일을 고르세요.". **확인 후 전체 복원**은 나타나지 않는다. 캡처 [d-fail-pc.png](design/e05-1/d-fail-pc.png).
- 저장 공간 부족이면 "저장 공간이 부족해 완료하지 못했습니다. 기존 여행은 보존됩니다. …"가 뜬다(코드 기준 문구, 실제 재현은 하지 않음 — **미확인**). 취소하면 "작업을 취소했습니다. 기존 여행은 보존됩니다."
- 평소 공간 확인: 평소 주소(`review` 없는 주소)를 열어 여행 목록·일정이 그대로인지 본다. 복원은 별도 검토 공간에서만 일어난다.
- 다시 시도: 같은 파일을 다시 고르거나 **새 빈 공간 열기**로 새 공간을 만든다. 중간에 멈춘 작업이 남으면 **저장소·백업**의 "중단된 준비 작업" 목록에서 이어서 완료하거나 정리한다.

## E. 구 형식 자료가 있는 기기

- 조건: 이 기기에 옛 화면 시절(`trips` 표) 여행이 있고 아직 전환하지 않았을 때, 앱을 열면 "기존 여행을 확인해 주세요" 안내가 뜬다.
- 진행: **기존 여행 전환 검토** → "기존 여행 전환 확인"에서 "N개 여행 · 원문과 과거 계획/실제 기록을 보존합니다." 확인 → **원문 보존 후 전환**. 끝나면 "기존 여행을 전환했습니다. 옛 화면은 읽기 전용입니다."
- 전환 전에 전체 백업은 구 형식 상태에서는 만들 수 없다(**전체 백업 만들기**는 전환 뒤 활성). 원문은 전환 뒤에도 보존된다.

## F. 업데이트 뒤 확인 항목 (단계 E E-2)

| 항목 | 화면에서 보는 곳 |
|---|---|
| 여행 목록·선택된 여행 | 화면 위의 여행 이름(▾)을 눌러 목록과 현재 여행 |
| 준비 초안·지난번 답 | 여행이 없을 때 "이 기기에 준비 초안(답·가이드·고른 것)이 남아 있습니다…" 안내(**준비 초안 지우기** / **남겨 두기**). AI 작업이 남았으면 AI 계획 화면에 "이 여행의 최근 AI 작업이 있습니다…" |
| 오프라인 열림 | 통신을 끊고 새로고침 → "오프라인 · 저장된 가이드 조회와 현장 기록을 이용할 수 있습니다." 표시 |
| 패스키 로그인 유지 | AI 화면의 로그인 줄: "패스키로 로그인"이 다시 요구되면 만료, 요구 없이 쓰이면 유지(서버 쪽은 runbook-worker) |

## G. 하지 말 것

- 브라우저 "사이트 데이터 삭제"·프로필 교체: 백업 없이 하면 이 기기의 자료가 사라진다.
- 평소 공간에 검증되지 않은 파일 복원: 평소 공간에는 복원하지 말고 항상 새 검토 공간에서.
- 실제 여행 데이터·백업 파일·비밀값을 Git에 올리기.
