# 운영·복구와 선택 확장 상태

2026-10-23 · **복구 절차 준비 / 운영 검증·선택 확장 미완료**

## 복구할 때

1. 정상 데이터가 있는 브라우저에서 ‘저장소·백업 → 전체 백업 만들기’로 파일을 저장한다. 앱 소스·이행 ZIP과 편집/기록을 포함한 전체 백업은 서로 다른 산출물이다.
2. 저장한 파일의 크기·시각·앱 커밋·출처를 기록하고 사용자가 정한 다른 매체에 보관한다. `travel-app/backup/`은 같은 디스크의 로컬 사본이므로 매체 장애 대비와 구분한다. 실제 파일은 Git에 올리지 않는다.
3. 복원은 현재 데이터를 지우지 않고 별도 빈 검토 공간에서 먼저 수행한다. 다른 브라우저·origin에는 DB가 자동 공유되지 않으므로 동일 URL이라는 이유로 데이터를 가정하지 않는다.
4. 사진/본문/기존 메모·새 기록·과거 계획/변경안·재가져오기 기준을 재조회하고 원본 행/파일과 대조한다. 실패하면 정상 사본과 기존 공간을 유지하고 중단된 준비 작업·로그만 조사한다.
5. 브라우저 저장소 삭제·프로필 교체·origin 변경 전에 백업을 보관하고 빈 공간 복원을 확인한다. 실제 키는 별도 관리하며 여행 백업에 넣지 않는다. AI 서버 작업 파일에는 요청 결과가 있으므로 Git 제외 로컬 자료로 취급한다.

## 현재 범위

이번에 저장소 도구의 기기 준비 표시, 전체 원천 파일 보존, 연속 패키지 생성과 후속 일괄 검사 명령을 추가했다. 실제 복구 훈련·다른 매체 보관은 후속 확인이다.

호스팅 정식화·새 가이드 작성·사용자 사진/지출·내장 지도 조작·실시간 위치·동기화는 선택 범위가 확정되지 않았다. 사용자 ‘끝까지 진행’을 새 기능 사양이나 공개 배포 승인으로 해석하지 않는다. 기존 원천 이미지와 본문 편집은 이미 필수 이행에 포함되어 있다.
