1. **빈 `title` 결함 (중요)**: 1번째 호출에서 모델이 근거 부족을 이유로 사실상 거절하면서 `add` 연산을 `title=""`·`activityId=""`로 채워 보냈다. Worker의 T-D1 검증은 통과시켰지만 앱 계약(`title` ≥ 1자)이 저장을 거부했다("변경안을 기기에 저장하지 못했습니다 … Too small"). "다시 저장"은 같은 이유로 계속 실패한다. 서버·앱 검증 불일치 또는 "근거 없음"을 표현할 정식 경로 부재. 비용은 이미 발생했다.
2. **가상 장소로는 근거를 못 찾는다**: 가상 이름만 있는 조사 질문은 실제 출처가 없어 모델이 거절에 가깝게 답한다. 실제 장소는 "조사 질문" 칸에 넣어야 한다(요청 문구는 코드상 웹 검색 입력에 없다: `researchRequestBody`는 허용 목록 DTO만 받고, 근거에 요청 원문 장소가 새지 않았다고 본다).
3. **웹 검색 3회 기록**: 5번째 호출 usage가 `webSearchCalls=3`이다. 코드는 `max_tool_calls: 2`. 상한 초과인지, 하위 동작(열기·찾기)까지 센 값인지 미확인.
4. **출처 분류 불일치**: 모델은 "공식 안내"라고 쓰는데 앱 분류가 2번째·3번째 호출에서는 공식 0(블로그·커뮤니티·기타), 5번째에서는 공식 2다. 같은 사이트에 대한 분류가 호출마다 달라 보인다(도메인 목록 기준인지 모델 라벨 기준인지 미확인).
5. **근거 충돌**: 3번째 호출의 두 근거 페이지가 서로 다른 운영시간(평일 9~18시 / 11~20시, 브레이크 15~17시)을 보였고 모델은 09:00을 택했다. 카드는 "변하는 사실: 미확인"과 확인 필요 항목으로 표시했다(예약 활동 시각 변경이라 "예약을 직접 확인했고 이 항목도 적용" 체크 필요).
6. **검증 거부·재작성 없음**: 5건 모두 시도 1회. 연속 거부·401/403 반복 없음. 멈춤 조건 해당 없음.
