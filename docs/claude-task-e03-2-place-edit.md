## A. 기존 장소 줄의 내용 고치기

지금: `## 장소` 표에서 ID가 있는 줄은 내용이 달라도 받지 않고 "기존 장소의 내용은 글로 고치지 않습니다"만 보인다(E2-B 보완 4번).

1. ID가 있는 장소 줄에서 **설명·영업시간·지역·링크** 칸이 현재 값과 다르면 "장소 수정" 후보로 만든다. **이름 칸은 받지 않는다**(달라도 무시하고 "이름은 글로 고치지 않습니다" 안내 — 활동과 이름으로 이어져 있어서다).
2. 규칙은 활동과 같다: 빈 칸 = 변경 없음, `(비움)` = 지움. 영업시간·지역은 새 장소와 같은 방식으로 설명 끝 표시(`[지역: …]`·`[영업시간(미확인): …]`)나 `regionIds`에 넣는다. 링크는 `http(s)` 주소만.
3. 화면: 장소 단계에 "기존 장소 수정 n건" 구역을 두고 줄마다 체크(기본 **해제**), 바뀌는 칸의 전·후를 보여 준다. 고른 것만 `UpdateContent`로 저장한다. 새 장소 만들기와 **따로 승인**한다.
4. 장소를 고치면 `domainRevision`이 오른다 — 새 장소를 만들 때와 같은 기준 연결(`revisionBridge`)로 같은 글의 계획 변경이 이어서 적용되게 한다. 그사이 다른 저장이 끼면 지금처럼 막는다.
5. 이 여행에 없는 ID 줄은 지금처럼 받지 않는다. 장소가 아닌 콘텐츠(지역·가이드)는 건드리지 않는다.
6. "빈 칸 채우기" 요청문(E3-1 B)의 "ID가 있는 장소 줄은 고치지 않는다"를 "ID가 있는 장소 줄은 **비어 있는 칸만** 채운다(이름은 바꾸지 않는다)"로 바꾼다.
7. 왕복: 내보내기 → 그대로 가져오기 = 변경 0건·장소 수정 후보 0건.
