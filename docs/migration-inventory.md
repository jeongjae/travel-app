# SP-FR 기능·콘텐츠 이행표

작성일: 2026-10-21 · 상태: 검토 초안 v0.3 · 콘텐츠 DB화와 공통 프로그램 전환의 대응 항목 구체화

## 1. 목적과 확정 범위

사용자 확정: SP-FR 이행 완료는 가이드북 조회·핵심 현장 사용까지다. 신규 AI 기능의 완료와 구분한다. 최종 travel-app에는 상세 콘텐츠의 앱 내부 작성·수정을 포함한다.

이행의 중심은 기존 콘텐츠를 코드 내부의 여행 값까지 데이터화하고, 매번 다른 여행계획을 DB에 넣어 같은 조회·편집 프로그램으로 사용하는 것이다. 이 표는 각 콘텐츠/기능의 **원천→DB 대상·관계→공통 화면/동작**을 추적할 출발점이다. 상세 조사에서는 해당 세 칸을 항목별로 채우며 파일 복사나 정적 HTML 보존을 프로그램 전환 완료로 취급하지 않는다.

후속 사용자 확정:

- 기존 장소 본문 편집은 이행에 포함한다. 새 가이드 작성 기능은 이후 확장한다.
- 지도는 장소·동선 목록과 외부 지도 열기 링크를 우선 이행한다. 앱 내부 지도 조작은 이후 구현한다.
- 기존 휴대폰·PC 브라우저에 별도로 보존할 수정 데이터는 없다. 저장소 원본만 이행한다. 저장소에 반영된 현장 메모·체크·편집 결과는 조사 대상이며, 기존 기기 DB·저널·캐시·설정·자격증명 추출은 제외한다. 새 앱에서 입력할 현장 기록·백업 기능은 계속 필요하다.

이번 문서는 기존 원본의 데이터 종류와 사용 흐름을 조사하고 처리 방침을 제안한다. **개별 항목의 포함·제외, 단계 배정과 재구현 방식은 사용자 합의 전까지 제안이다.** 저장소의 실제 여행·예약 값, 개인 기기 데이터, 사진 파일은 이 문서에 복제하지 않는다.

참조 기준: [목표·이행 완료 기준](goal-and-migration-criteria.md)의 M-01~M-11, G-01~G-08 및 S-01~S-07. 해당 문서의 세부 판정 조건은 여전히 검토안이다.

## 2. 조사 근거와 한계

- GitHub 플러그인으로 원본 `jeongjae/SP-FR-guidebook`을 읽기 전용 조사했다. 조사 기준 commit은 `35498adc6413dad45922f2dab87781afeb04d898`이며, 이번에 main과 비교해 동일함을 확인했다. 실제 이행 기준본 확정은 별도다.
- 정적 가이드북과 현장 편집 앱은 함께 조사한다. `build/site.py`가 정적 페이지·지도·준비·오프라인 자료를 만들고, `build/export_app_data.py`는 그중 현장 앱에 필요한 일부만 JSON으로 내보낸다. 앱 JSON만으로 전체 조회 기능을 대표하지 않는다.
- 코드·스키마·내보내기 경로를 확인했다. 원본 전체 파일의 실측 목록·수량·해시, 실제 화면, 외부 지도·동기화 동작, XLSX 전체 시트와 사용자 기기 상태를 검증한 것은 아니다.
- 로컬 Projects 폴더에 SP-FR 체크아웃은 확인되지 않았다. 원본을 clone·빌드·수정하거나 새 앱으로 실제 데이터를 가져오지 않았다.
- 원본 README·정본 색인에는 오래된 경로·규모 설명이 섞여 있다. 정본 색인이 참조하는 `docs/content-architecture-audit.md`는 해당 commit에서 404였다. `state.js`가 언급하는 `build/apply_field_edits.py`도 해당 경로에서 404였다. 관련 처리기가 없다고 단정하지 않고 위치와 실제 적용 경로를 후속 확인한다.

## 3. 표 읽는 법

- **유지:** 콘텐츠의 의미·정보를 보존한다. 기존 파일 형식과 화면 배치를 유지한다는 뜻은 아니다.
- **변환:** 의미를 보존하며 새 데이터 구조에 대응시킨다.
- **재구현:** 사용자에게 필요한 동작을 새 프로그램 구조에서 구현한다. 기존 코드를 복사한다는 뜻은 아니다.
- **보류:** 필요성·방식·범위를 결정하지 않았다. 원본에서 삭제하거나 손실을 허용한다는 뜻은 아니다.
- **제외 제안:** 현재 이행 대상으로 삼지 않기를 제안한다. 사용자 결정 없이 확정하지 않는다.
- 단계 **이행**은 기존 핵심 가치 보존, **확장**은 그 이후 최종 목표 기능, **결정 대기**는 아직 남은 범위 검토나 후속 조사에 의존한다.

원본 수량은 현시점 참고 수치로 고정하지 않는다. 일차·숙박 거점·편집 지역·리다이렉트 페이지는 서로 다른 단위이므로 각각 기준본에서 집계해야 한다.

## 7. 확인한 차이와 해결 과제

| ID | 확인한 사실 | 이행에 필요한 대응 |

## 8. 이행 범위 묶음 — 검토안

1. **필수 포함 제안:** 여행·지역·일정·장소 장문·사실/출처·교통/준비·숙소/예약 조회, 검색·탐색, 일정 편집·체크·메모·예약 상태, 오프라인 준비, 백업·복원, 다른 여행 적용과 원본 보존.
2. **대상 목록 확인 후 포함 제안:** 현재 조회에 쓰는 이미지·카드·첨부와 크레딧, 회화 자료/상호작용, 저장소에 반영된 현장 상태. 미확인 항목은 미분류로 남긴다.
3. **후속 사용자 확정:** 기존 장소 본문 편집을 이행에 포함한다. 지도는 장소·동선 목록과 외부 지도 링크를 우선하며 내부 지도 조작은 후속이다. 이행 원본은 저장소로 한정하고 기존 브라우저 데이터 추출은 제외한다.
4. **후속 확장 제안:** 새 장소/지역 가이드 작성의 상세 기능, AI 전체 실행, 고급 계획·실제 비교. 확정된 최종 요구를 포기하거나 데이터 구조 검토를 미루는 의미는 아니다.
5. **기존 구현 방식 제외/대체 제안:** 특정 저장소에 고정된 PAT 동기화, 생성물·구판을 편집 정본으로 사용하는 방식. 기능 결과의 대체 범위를 확정한 뒤 적용한다.

## 9. 사용자 답변과 남은 정의

다음 세 답변을 사용자 결정으로 반영했다. 다른 행의 제안이나 세부 판정 조건까지 일괄 승인된 것으로 간주하지 않는다.

- Q-01 확정: 기존 장소 본문 편집은 이행에 포함. 새 가이드 작성은 이후 확장.
- Q-02 확정: 장소·동선 목록과 지도 링크 우선. 내장 지도 조작은 이후 구현.
- Q-03 확정: 별도 보존할 기존 기기 데이터 없음. 저장소 원본만 이행. 기존 기기의 토큰·설정·캐시·편집 저널 추출은 범위에서 제외.

설계와 대표 구간 이행에 앞서 남은 조사 산출물은 파일별 원천·사용처·건수/해시·변환 규칙·대상 여부가 있는 기준본 manifest와 대표 구간 선정이다. 저장소에 존재하는 현장 상태·저널은 별도 분류한다. 기기 데이터 추출은 필요하지 않다. 이 문서는 상세 조사를 시작할 수 있는 분류표이며 전수 목록이나 이행 검증 보고서는 아니다.

후속 3단계 [공통 구조·정본/편집 책임](target-architecture.md)에 논리 모델·시간·저장·첨부/백업 설계와 기술 대안을 제안했다. 여행별 독립 사본과 이행 후 앱 중심 편집은 후속 사용자 확정이다. 실제 이행·앱 구현은 재개하지 않았다.

이번 원천 필드·코드 상수의 구체 대응은 [원천 콘텐츠→DB→공통 화면](content-db-mapping.md) v0.1에 있다. P-01~25는 D-01~23의 논리 구조와 V-01~11 화면에 연결된다. 실제 전체 파일·행·첨부 manifest와 이행 검증 결과는 아직 별도 과제다.
