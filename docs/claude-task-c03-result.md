## 요약

- 지역에서 가이드를 작성해 지역 화면에서 찾아 읽고 제목·섹션을 고치고, 여행 공통 가이드를 준비 화면에서 찾아 읽고 고치며, 지역·장소의 기본정보를 고친 뒤 목록·검색·상세·연결 일정에서 최신 값을 읽는다. 재실행·오프라인·전체 백업→빈 브라우저 복원 뒤에도 같다. 모두 가상 입력이며 사용자 DB·iPhone·실제 ZIP·main·배포·API는 건드리지 않았다.

## 모델·소유자 결정

- 지역 가이드: 기존 `region-guide` + 지역 ownerRef. `CreateContentBatch`의 `updateOwners`로 가이드 생성과 지역 `guideIds`(기존 연결 뒤에 추가) 갱신을 한 번에 저장한다. C-01 R1의 "기존 활성 연결 끊기 금지"는 그대로다.
- 여행 공통 가이드: 기존 `preparation` + ownerRef `trip`(이 여행 ID). 배치는 이 조합만 새로 허용하고, 다른 여행·지역/장소 소유자·`transit`/`language-guide`/`region-essentials` 같은 구조화 종류는 거부한다. 지역·여행 가이드는 섹션 1개 이상 필수. 새 명령은 없다.
- **UpdateContent 안전 규칙**(`src/storage/content-update.ts`): 지역·장소·가이드에만 적용. 비활성 콘텐츠 수정 거부, 지역의 `guideIds`·장소의 `guideId` 변경 거부, 새로 연결하는 지역은 활성이어야 함(없는/다른 여행/비활성 거부), 가이드는 종류·소유자·섹션·Fact 바인딩·첨부 변경 거부(제목·언어만 허용, 섹션은 `EditContentSection`). Fact 등 다른 종류와 기존 사용처는 영향 없음.
- 준비 화면 노출: 앱에서 작성한 가이드는 원천 출처(`sourceRefs`)가 없다는 사실으로 구분(`src/content/guide-rules.ts`). 원천처럼 보이는 ID를 흉내 내지 않았고, 가져온 준비 문서의 분류는 이전 규칙과 동일함을 시험으로 고정했다. 편집 가능: 장소·지역 가이드와 작성한 준비 가이드(구조화 문서·가져온 준비 문서 제외).
- 요청 재시도: 폼을 연 시점에 새 ID·기준 revision을 고정하고 같은 입력은 같은 요청 ID로 재전송한다(`reuseRequest`). 입력이 바뀌면 새 요청 ID.

## 사용자가 볼 수 있는 산출물·확인 동작

`pnpm run build && pnpm run preview:ui` → `http://127.0.0.1:4173/?workspace=content`, 새 프로필/빈 검토 공간에서만. 가상 입력 예: 여행 2032-06-01~03, 지역 "가상 동네", 가이드 "동네 걷기 안내".
1. `가이드` → 지역 열기 → `지역 가이드 작성`(제목·섹션 추가) → 저장 후 `이전 안내로`로 지역 화면에서 첫 가이드는 본문, 이후 가이드는 버튼으로 찾기. `가이드 제목 수정`, `<섹션> 편집`.
2. `준비` → `여행 가이드 작성` → 같은 화면 목록에서 열기·수정.
3. 지역/장소 상세의 `기본정보 수정`. 스크린샷은 따로 만들지 않았다(시험·로그가 증거). 모바일은 Pixel 7 에뮬레이션이며 실기기 확인이 아니다.

## 미검증·한계·경미한 발견 (Codex 관리 후보)

- 사용자 화면 확인·Codex 독립 검토·iPhone 실기기 확인 대기. 원격 CI는 push 후 기록.
- 기존 가이드에 섹션 추가·삭제·순서 변경은 없다(작성 시에만 여러 섹션). 소유자 변경·가이드 물리 삭제/교체·연결 제거 명령도 없다(지시대로).
- 가져온 준비 문서와 구조화 가이드는 편집 UI를 열지 않았다. 가져온 지역 가이드는 편집 가능(장소 가이드의 기존 선례). 편집 시 앱 변경으로 기록된다.
- 장소 이름을 바꿔도 장소 가이드의 제목("OO 안내")은 자동으로 바뀌지 않는다.
- 과거 계획 화면에서 활동의 "장소 안내 · 이름" 버튼 글자는 현재 이름이고, 눌러 열린 상세는 당시 고정 내용이다(기존 동작, 이번에 바꾸지 않음). 영향: 라벨과 상세 이름이 다를 수 있음. 재개: 과거 화면 라벨을 고정 revision으로 읽을 때.
- 기본정보 편집에서 비활성 지역에 이미 연결된 장소의 그 연결은 화면에 보이지 않고 그대로 유지된다.
- 구버전 앱이 새 가이드/영수증이 든 백업을 못 읽을 수 있는 배포 순서 문제는 C-01에서 지적한 그대로다.
- 상위 설계/계획/후속 목록은 수정하지 않았다. 제안: CL-06은 이번에 해소, CL-07 중 지역/여행 가이드 UI 해소(세부 장소 연결 relation 선택은 남음).
- 미추적 `docs/status-review-2026-10-26.md`는 그대로다. main 병합·배포·실제 자료 적용·API 호출 없음.
