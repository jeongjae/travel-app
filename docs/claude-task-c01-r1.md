# Claude Sonnet C-01 R1 · 기존 소유 연결 보존

2026-10-29 · 기준 `f371ef5` 이후 Codex 검토 문서 커밋 · **전달 준비 / 보완 미착수**

C-01 주요 작성 흐름·오프라인·복원은 Codex 검증을 통과했다. [검토](claude-task-c01-review.md)의 저장 관계 1건만 보완한다.
Sonnet이 조사·수정·검사·증거·커밋/push를 끝내고 최종 20줄/2,000자와 증거 색인으로 제출한다.

1. `.cache/c01-codex/owner-link-repro.test.ts`를 읽어 정식 회귀로 정리하고 수정 전 실패를 확인한다.
   기존 P→G1을 새 P→G2로 교체할 때 기존 활성 G1.owner=P가 남는 경우를 검사한다.
   지역의 기존 guideIds 제거/교체도 검사한다. expectedRevision이 맞아도 관계가 깨지면 거부해야 한다.
2. 이번 배치가 영향을 주는 기존/신규 소유 관계의 최종 그래프를 검증한다.
   최소 범위로 기존 활성 연결의 무단 제거/교체를 거부할 수 있다. 교체/삭제용 새 명령이나 UI는 만들지 않는다.
   기존 이행 데이터의 무관한 불일치를 일괄 정리하거나 기존 가이드·과거 revision·계획 pin을 삭제/비활성화하지 않는다.
3. 정상 새 가이드 추가·기존 연결 유지, 실패 시 데이터/head/revision/receipt 전체 불변·replay·격리 검사를 유지한다.
   필드나 검사를 제거해 문제를 숨기지 않는다. 실패한 입력은 기존 오류 경로로 안전하게 반환한다.

대상 회귀 후 최종 `pnpm run check:deferred`. 같은 코드의 포함 검사를 불필요하게 반복하지 않는다.
오프라인 추가 검사는 `.cache/c01-codex/offline-authoring.spec.ts`에 있으며 정식 회귀로 보존해도 된다(원래 경로는 tests/e2e).
코드/가상 검사와 `docs/claude-task-c01-r1-result.md` 보고를 분리 커밋하고 현재 작업 브랜치에 push한다.
사용자 데이터·main·배포·API는 변경하지 않는다. 경미한 UI 개선·시간대 공용 스키마·C 후속 기능은 이번 범위 밖이다.
Codex 재검토와 사용자 확인은 대기로 남긴다. 후속 목록·상위 설계/계획은 Codex가 관리한다.
