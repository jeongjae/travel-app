## 판단이 필요했던 규격의 모호한 곳 (제 판단, 검토 요청)

1. **보이지 않는 글자**: 규격 "버린다". BOM·폭 없는 글자(U+200B~D, U+2060)는 삭제, 줄바꿈 없는 공백(U+00A0·U+202F)은 보통 공백으로 바꿔 글 중간 단어가 붙지 않게 했다.
2. **코드 블록은 있는데 양식 줄이 든 블록이 없을 때**: 규격은 침묵. 본문 밖의 계획을 추측해 읽지 않고 `not-plan`으로 거부했다.
3. **알 수 없는 머리 줄(`- 범위:` 포함)**: 규격 §2는 "경고로 보여 준다". `notImported`(kind `header`)에만 담고 `issues` 경고로는 중복 집계하지 않았다(경고 수는 겹침 등 실제 경고만). 미리보기에서 경고 칸에 함께 보일지는 C2에서 정하면 된다.
4. **`notImported.lineCount`**: 표 제목·구분 줄을 뺀 데이터 줄 수 + 구역 안의 비어 있지 않은 글줄.
5. **규격에 없는 추가 검사**(오류): 같은 날짜 제목 중복(`duplicate-day`, 뒤 것 제외), 같은 ID 줄 중복(`duplicate-id`), 삭제 종류와 같은 파일 안 ID 표의 종류 불일치(`delete-kind-mismatch`), 날짜 제목 없는 일정 표(`table-without-day`).
6. **표 오류의 범위**: §4는 열 개수만 "표 전체 제외"로 명시한다. 지시서 요구 2번에 따라 **값 오류(시간·링크·필수 공란·ID 등)가 한 줄이라도 있으면 그 표(일정은 날짜 전체)를 뺀다.** 그 표의 다른 오류도 모두 모아 보고한다.
7. **새 여행 파일의 삭제 표**: 줄이 있으면 ID가 가리킬 항목이 없으므로 `id-in-new-file` 오류로 취급.
8. **update·invalid 파일의 머리 값 오류**(기간 형식·시간대 이름): 규격 §2(기존 여행은 기간 경고만)에 맞춰 경고로 낮췄다. 새 여행 파일에서만 오류(저장 불가).
9. **`(+1)`과 12시간**: 길이는 `(+1)` 포함 실제 길이로 계산하고 정확히 12시간은 허용, 초과 거부. `10:00-12:00(+1)`처럼 24시간 가까운 값도 12시간 초과로 거부.
10. **수정 줄(ID 있음)**: 값이 있는 칸의 형식만 검사하고 빈 칸은 "변경 없음"으로 둔다. ID가 가리키는 항목의 존재·종류 일치는 기존 여행이 필요하므로 E2.
11. **일정 시간 칸이 비면** `{ start: { precision: 'date', date } }`(날짜 행과 같은 방식), 있으면 `local`(시간대 확인 시 `confirmed`, 없으면 `unknown`). 서머타임으로 존재하지 않는 시각은 저장 스키마 규칙을 그대로 써서 `time-nonexistent` 오류.
12. **머리 줄 오류의 줄 번호**: 줄이 없어 생긴 오류(기간 줄 없음, ID 3줄 불완전)는 줄 번호 0으로 적는다.
13. **같은 날 체크인하는 숙소 둘**이면 §5-1 1번대로 첫 `숙박` 활동 하나의 메모에 모두 덧붙인다.
14. **제 해석 한 가지(지시서 우선 적용)**: 초안 검토표의 "저장되지 않는 값으로 표시"와 지시서·규격 §5-1의 "메모에 남김"이 달라 후자(사용자 결정 11/16)를 따랐다.
