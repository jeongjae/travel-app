## 구현한 흐름

- 변경안 화면에 지연 로딩되는 v2 AI 도구를 연결했다. 요청·시작일·최대 7일·기록 포함 여부를 선택하고 전송 JSON을 미리 본 뒤 유료 실행에 동의한다. API 키는 서버에만 둔다.
- 예약 비공개 필드·숙소 상세·첨부 바이트는 전송하지 않는다. 요청/일정 요약에 사용자가 쓴 정보는 미리보기에 나타나며, 현장 기록·메모는 기본 제외다. 실제 요청은 1 MiB 한도다.
- `/api/ai/v2/`에서 조사 → 구조화 작성 → 날짜/장소/출처 검사 → 초안 준비를 제공한다. 웹 조사 최대 2회, 작성 최대 2회, 작업 5분, 일일 20건/보관 200건/동시 2건 제한을 구현했다. 이 수치는 작성자의 실행 기본값이며 사용자의 비용 예산 합의가 아니다.
- 작업 중단, 요청 ID/본문 지문 중복 방지, 저장 실패 시 실행 거부, 재시작 시 진행 작업 `interrupted`, 브라우저 재진입 후 결과 회수 경로를 구현했다. 로컬 작업 파일은 `local-data/ai-v2-jobs/`이며 Git 제외다.
- `StageAiProposal`은 기준 revision을 확인하고 새 근거와 초안을 한 트랜잭션에서 저장한다. 출처 추가로 revision을 한 번 올린 상태를 초안 기준으로 삼는다. API에 생략한 기존 예약/현장 메모 필드는 저장소에서 복원한다. 현재 계획·실제 기록은 초안 저장으로 바뀌지 않는다.
- 근거 링크·주장·예약 영향을 표시하고 기존 ‘확인 후 적용/거절’ 명령을 사용한다. 이후 현장 기록/다른 탭 변경이 있으면 적용을 거부한다. 승인 적용과 서버의 초안 준비 상태는 구분한다.

## 실행 설정과 미완료

기존 v1 실행기·저장소는 격리 상태로 유지한다. v2는 기본 비활성이며 `.env.example`의 `OPENAI_V2_ENABLED=0`을 따른다. 모델·비용·전송 범위를 정한 뒤 로컬 서버에서만 `1`로 켠다. 키 파일을 덮어쓰지 않는다. 현재 실행 중인 이전 API 프로세스는 재시작하지 않았다.

포맷·린트·타입·프로덕션/PWA 빌드는 통과했다. 단위/E2E·재시작/중단·중복·stale·실제 OpenAI 호출은 사용자 요청에 따라 미실행이다. 현재 JSON 생성만을 실제 AI 실행 완료로 보고하지 않는다. 실기기 인증·접속·공개 배포도 미완료다.

구현 근거: [OpenAI 웹 검색](https://developers.openai.com/api/docs/guides/tools-web-search), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs). 실제 계정의 모델 접근/가격·호출 결과는 검증하지 않았다.
