# travel-app의 AI 여행계획 연동 방식 개선 제안

## 1. 핵심 제안

현재 설계의 방향은 적절합니다. **여행계획은 범용 AI 챗봇에서 만들고, travel-app은 계획을 저장·실행·기록하는 역할**을 담당하는 구조입니다.

다만 사용자 경험 측면에서는 한 가지 문제가 있습니다.

> 사용자가 AI와 여행계획을 세우는 것보다, AI의 결과물을 travel-app에 전달하기 위해 양식을 관리하는 일이 더 번거로워질 수 있습니다.

따라서 **Markdown을 내부 교환 형식으로 유지하되, 사용자는 가능한 한 양식을 의식하지 않도록 만드는 것**을 권장합니다.

장기적으로는 다음 경험을 목표로 할 수 있습니다.

**AI에서 여행계획 수립 → travel-app으로 보내기 → 변경사항 확인 → 적용**

현재의 파일 기반 구조를 유지하면서도 단계적으로 이 경험에 접근할 수 있습니다.

---

## 2. 현재 방식의 사용자 불편 요소

설계서 v0.2의 절차를 사용자 행동 기준으로 정리하면 다음과 같습니다.

```text
① travel-app에서 양식 안내문 복사
             ↓
② ChatGPT / Claude에 붙여넣기
             ↓
③ AI와 여행계획 수립
             ↓
④ AI에게 Markdown 양식으로 변환 요청
             ↓
⑤ Markdown 파일 다운로드
             ↓
⑥ travel-app으로 이동
             ↓
⑦ 파일 선택 및 가져오기
             ↓
⑧ 변경사항 확인 및 저장
```

이 방식은 기술적으로 단순하고 안전하지만, 다음 문제가 있습니다.

| 불편 요소 | 발생 상황 | 영향 |
|---|---|---|
| 양식 안내문 관리 | 새 채팅을 시작할 때마다 안내문 전달 | 반복 작업 |
| Markdown 변환 요청 | 계획이 완성된 후 별도 요청 | 불필요한 단계 |
| 파일 다운로드·업로드 | 특히 iPhone에서 파일을 찾고 선택 | 사용성 저하 |
| 변경 시 전체 파일 재생성 | 숙소 하나만 바꾸는 경우 | 번거로움 |
| AI와 앱의 정보 불일치 | 앱에서 직접 수정한 뒤 AI와 다시 대화 | 이전 계획을 기준으로 수정할 위험 |
| 오류 발생 시 재작업 | Markdown 형식 오류 | AI에게 재출력 요청 |

이 문제는 크게 **AI와의 대화 시작, 계획 전달, 변경사항 반영**이라는 세 구간에서 발생합니다.

# 3. 개선 아이디어 7가지

## 아이디어 ① AI 대화 시작을 travel-app에서 지원

### 현재

사용자가 양식 안내문을 복사하고 챗봇에 붙여넣습니다.

### 개선

travel-app에 **「AI로 여행계획 만들기」** 버튼을 제공합니다.

버튼을 누르면 다음 정보가 포함된 프롬프트를 자동 생성합니다.

- 여행지와 여행 기간
- 여행 스타일 및 선호사항
- travel-app 양식 규칙
- 계획 작성 과정의 안내
- 최종 결과물 출력 규칙

예를 들어 사용자가 여행지와 기간을 입력하면 다음과 같은 프롬프트를 생성합니다.

> 2027년 4월 2일부터 5일까지 교토와 오사카를 여행합니다. 여행계획을 함께 세워 주세요. 숙소와 교통을 포함해 자유롭게 계획을 조정하고, 마지막에는 travel-app에서 가져올 수 있는 Markdown 형식으로 출력해 주세요.

사용자는 이를 복사해 원하는 AI 챗봇에서 대화를 시작합니다.

**효과:** 사용자가 양식 구조를 이해하거나 별도로 관리할 필요가 줄어듭니다.

**구현 난이도: 낮음**

현재 E0에서 예정된 '양식 안내문 복사'를 사용자 중심의 프롬프트 생성기로 확장하는 방식입니다.

---

## 아이디어 ② Markdown 파일 대신 복사·붙여넣기로 가져오기

가장 먼저 도입할 것을 권장하는 개선입니다.

### 현재

```text
AI → Markdown 파일 생성 → 다운로드 → 파일 선택 → 가져오기
```

### 개선

```text
AI → Markdown 결과 복사 → travel-app에 붙여넣기
```

travel-app의 가져오기 화면에 두 가지 입력 방법을 제공합니다.

| 가져오기 방법 | 사용 방식 |
|---|---|
| 파일 가져오기 | `.md` 파일 선택 |
| 텍스트 붙여넣기 | AI 답변을 복사해서 입력창에 붙여넣기 |

두 방법은 동일한 Markdown 파서와 검증 절차를 사용합니다.

**장점**

- 파일 다운로드가 필요 없습니다.
- PC와 iPhone 모두에서 사용할 수 있습니다.
- 기존 데이터 모델이나 가져오기 계약을 변경할 필요가 없습니다.
- 파일 방식도 그대로 유지할 수 있습니다.

특히 iPhone에서는 파일을 저장하고 다시 찾는 과정이 사라지는 것이 큰 개선입니다.

**구현 난이도: 낮음**

---

## 아이디어 ③ AI 결과를 travel-app에 직접 전달하는 링크

사용자 경험을 크게 개선할 수 있는 방법입니다.

### 목표

```text
AI에서 여행계획 작성
          ↓
「travel-app으로 보내기」
          ↓
travel-app 자동 실행
          ↓
가져오기 미리보기
          ↓
사용자 승인
```

이를 위해 travel-app이 **공유 링크 또는 가져오기 링크**를 받을 수 있도록 합니다.

예를 들어 AI가 만든 계획 데이터를 URL로 전달하고, travel-app이 해당 데이터를 읽어 가져오기 화면을 여는 방식입니다.

다만 중요한 기술적 제약이 있습니다.

**일반 ChatGPT·Claude 대화에서 외부 앱으로 데이터를 자동 전송하는 기능을 임의로 추가할 수는 없습니다.** 챗봇이 직접 링크를 생성하거나 공유할 수 있는 방식은 해당 서비스의 기능과 제약에 따라 달라집니다.

또한 전체 여행계획을 URL에 넣으면 길이 제한과 개인정보 노출 문제가 발생할 수 있습니다.

따라서 다음과 같이 구분하는 것이 좋습니다.

| 구현 방식 | 특징 | 권장 |
|---|---|---|
| URL에 계획 전체 삽입 | 서버 없이 가능하지만 길이·보안 제약 | 제한적 |
| 짧은 공유 코드 + 임시 저장소 | 긴 계획 전달 가능, 서버 필요 | 중장기 |
| 앱 전용 공유 기능 | 가장 자연스러운 UX, 플랫폼 연동 필요 | 장기 |

**권장:** 초기에는 복사·붙여넣기를 사용하고, 실제 사용에서 파일 전달이 불편하다는 점이 확인되면 공유 링크를 도입합니다.

## 아이디어 ④ 전체 계획 대신 변경사항만 AI에서 전달

현재 설계에서 특히 개선할 가치가 높은 부분입니다.

예를 들어 이미 travel-app에 저장된 여행계획이 있다고 가정합니다.

사용자가 AI에게 다음과 같이 요청합니다.

> 2일 차 점심을 다른 식당으로 바꾸고, 3일 차 일정을 조금 여유롭게 조정해 줘.

현재 방식에서는 AI가 전체 여행계획을 다시 출력하고, 사용자가 이를 가져오는 흐름이 기본입니다.

그러나 실제로 변경된 항목은 몇 개뿐입니다.

### 개선: 부분 변경 Markdown

AI가 변경된 일정만 출력하도록 합니다.

```markdown
# 여행: 교토·오사카
- 양식: travel-app-plan/1
- 여행ID: ...
- 기준: ...

## 일정
### 2027-04-03
| ID | 시간 | 제목 | 종류 | 장소 | 메모 | 예약 | 링크 |
|---|---|---|---|---|---|---|---|
| A102 | 12:00-13:00 | 새로운 식당에서 점심 | 식사 | 식당 B | | | |
```

이후 travel-app이 다음과 같이 표시합니다.

| 항목 | 기존 | 변경 |
|---|---|---|
| 2일 차 점심 | 식당 A | 식당 B |
| 3일 차 일정 | 기존 일정 | 변경 없음 |

이 방식은 현재 설계서의 **부분 가져오기** 기능을 적극 활용합니다.

단, 앞선 재검토에서 지적한 대로 **빈 칸을 기존 값 삭제로 해석하지 않는 계약**이 먼저 필요합니다.

**효과:** AI가 출력해야 하는 내용이 줄고, 변경사항을 검토하기 쉬워집니다.

**구현 난이도: 중간**

## 아이디어 ⑤ travel-app에서 AI에게 전달할 현재 계획을 자동 생성

아이디어 ④와 함께 구현하면 효과가 큽니다.

### 현재의 문제

사용자가 travel-app에서 직접 일정을 수정한 뒤, 기존 AI 채팅으로 돌아가면 AI는 수정된 내용을 알지 못합니다.

이 상태에서 계획을 변경하면 이전 정보를 바탕으로 작업하게 됩니다.

### 개선

travel-app에 **「AI에게 현재 계획 전달」** 버튼을 제공합니다.

누르면 현재 여행의 계획을 Markdown으로 내보내면서 AI에게 전달할 요청문도 함께 생성합니다.

예:

> 아래는 travel-app에 저장된 최신 여행계획입니다. 이 계획을 기준으로 수정해 주세요. 기존 ID와 기준 revision은 변경하지 마세요. 수정된 항목만 travel-app 양식으로 출력해 주세요.

그 아래에 현재 계획이 첨부됩니다.

이 기능은 다음 두 작업을 하나로 묶습니다.

1. 현재 계획 내보내기
2. AI에게 수정 요청하기

**효과:** AI가 오래된 계획을 수정할 위험을 줄이고, 사용자의 반복 작업도 감소합니다.

**구현 난이도: 낮음~중간**

---

## 아이디어 ⑥ 계획 전체가 아닌 특정 항목에서 AI 작업 시작

사용자가 실제로 여행계획을 수정하는 방식은 대부분 전체 계획의 재작성보다 특정 항목의 수정에 가깝습니다.

예를 들어 다음과 같은 작업입니다.

- 특정 날짜의 관광지 추천
- 식당 대안 찾기
- 이동 경로 검토
- 숙소 비교
- 하루 일정 재구성

이를 위해 각 화면에 AI 작업 버튼을 제공할 수 있습니다.

### 화면 예시

```text
┌──────────────────────────────┐
│ 4월 3일 · 교토              │
├──────────────────────────────┤
│ 09:00 기요미즈데라           │
│ 12:00 점심                   │
│ 15:00 기온 산책              │
├──────────────────────────────┤
│ [직접 수정] [AI에게 요청]    │
└──────────────────────────────┘
```

「AI에게 요청」을 누르면 해당 날짜의 일정과 필요한 맥락을 포함한 프롬프트가 생성됩니다.

사용자는 AI에서 수정 결과를 받아 붙여넣습니다.

이 방식은 AI를 앱 안에 내장하지 않고도 **맥락에 맞는 AI 사용 경험**을 제공합니다.

**구현 난이도: 중간**

---

## 아이디어 ⑦ 장기적으로 AI 챗봇과 직접 연결

궁극적으로는 다음 경험이 가능합니다.

```text
travel-app
    ↕
AI 챗봇
    ↕
여행계획 생성·수정
```

사용자가 챗봇에서 계획을 변경하면, travel-app의 가져오기 미리보기가 자동으로 준비되는 방식입니다.

구현 가능성은 사용하는 AI 플랫폼의 외부 앱 연동 기능, 인증 방식, 배포 환경에 따라 달라집니다.

현재 travel-app은 브라우저 내부 IndexedDB에 여행을 저장하므로, 외부 챗봇이 그 DB에 직접 접근할 수는 없습니다.

따라서 직접 연동하려면 별도의 인증·전달 계층이 필요합니다.

이 기능은 편의성이 높지만 다음 부담이 생깁니다.

- 인증 및 접근 권한 관리
- 기기 간 데이터 동기화
- 외부 서버 운영
- 개인정보 보호
- 실패 및 충돌 처리

**현재 개인용 앱의 초기 구현 범위에는 포함하지 않는 것을 권장합니다.**

# 4. 개선안 비교 및 우선순위

다음은 현재 설계와 개발 복잡도를 고려한 정성적 평가입니다.

| 아이디어 | 사용자 편의성 | 구현 난이도 | 기존 구조 재사용 | 권장 시점 |
|---|---|---|---|---|
| ① AI 대화 시작 지원 | 높음 | 낮음 | 높음 | **E0** |
| ② 복사·붙여넣기 가져오기 | 매우 높음 | 낮음 | 매우 높음 | **E1** |
| ③ 직접 전달 링크 | 매우 높음 | 높음 | 중간 | 장기 |
| ④ 변경사항만 가져오기 | 높음 | 중간 | 높음 | **E2** |
| ⑤ 현재 계획을 AI에게 전달 | 매우 높음 | 낮음~중간 | 높음 | **E2** |
| ⑥ 항목별 AI 작업 시작 | 높음 | 중간 | 높음 | E3 |
| ⑦ 챗봇 직접 연동 | 매우 높음 | 매우 높음 | 낮음 | 장기 |

**우선순위는 ② → ⑤ → ① → ④ → ⑥ → ③ → ⑦을 권장합니다.**

②와 ⑤는 기존 파일 기반 아키텍처를 유지하면서도 사용자가 체감하는 불편을 크게 줄일 수 있습니다.

# 5. 추천하는 최종 사용자 경험

저는 travel-app의 AI 연동을 **세 가지 사용 시나리오**로 단순화하는 것을 제안합니다.

## 시나리오 A. 새 여행 만들기

```text
travel-app
    │
    ├─ 여행지·기간 입력
    │
    ▼
[AI로 계획 만들기]
    │
    ├─ AI용 프롬프트 자동 생성
    │
    ▼
ChatGPT / Claude
    │
    ├─ 대화하면서 여행계획 수립
    │
    └─ Markdown 결과 복사
    │
    ▼
travel-app
    │
    ├─ 붙여넣기
    ├─ 계획 미리보기
    └─ 승인 후 저장
```

사용자는 Markdown 파일을 별도로 관리하지 않아도 됩니다.

## 시나리오 B. 기존 여행 수정하기

```text
travel-app
    │
    ├─ 여행 선택
    └─ [AI로 수정하기]
             │
             ▼
     현재 계획 + 수정 요청
             │
             ▼
        AI 챗봇
             │
             └─ 변경된 항목만 출력
                       │
                       ▼
               travel-app
                       │
                       ├─ 변경사항 비교
                       └─ 승인 후 저장
```

기존 여행의 ID와 기준 revision을 유지하므로, 다른 여행에 잘못 적용하거나 오래된 계획으로 덮어쓰는 위험을 줄일 수 있습니다.

## 시나리오 C. 여행 중 일부 일정 변경

```text
travel-app
    │
    ├─ 오늘 일정 열기
    ├─ 특정 활동 선택
    └─ [AI에게 대안 요청]
             │
             ▼
      해당 활동과 주변 일정
             │
             ▼
         AI 챗봇
             │
             └─ 대안 생성
                    │
                    ▼
             travel-app
                    │
                    └─ 선택한 변경만 반영
```

여행 중에는 전체 계획을 다시 내보내는 것보다 특정 활동이나 날짜만 전달하는 방식이 유용합니다.

현재 `docs/ai-rework-requirements-design.md`의 구조를 유지하면서 다음과 같이 보완하면 됩니다.

# 7. 추가로 고려할 개선: Markdown을 사용자에게 숨기기

위 아이디어를 종합하면 장기적으로 가장 바람직한 구조는 다음과 같습니다.

| 계층 | 역할 | 사용자에게 보이는가 |
|---|---|---|
| AI 대화 | 여행계획 수립·수정 | 예 |
| AI 요청 생성 | 양식 규칙·현재 계획·수정 대상 전달 | 버튼으로만 노출 |
| Markdown | AI와 앱 사이의 교환 형식 | 가능하면 숨김 |
| 가져오기 변환기 | Markdown 해석·검증 | 아니요 |
| 변경사항 미리보기 | 추가·수정·삭제 비교 | 예 |
| 여행 DB | 계획 버전·실행 기록 저장 | 앱 화면으로 노출 |

즉, Markdown은 사용자가 관리하는 문서라기보다 **시스템 간 교환을 위한 내부 계약**으로 취급하는 것이 좋습니다.

물론 사용자가 원할 때는 Markdown 파일을 내보내고 직접 수정할 수 있도록 유지합니다.

이렇게 하면 R-01~R-07의 기본 방향을 변경하지 않으면서 사용성을 높일 수 있습니다.

## 최종 제안

현재 설계를 전면 변경할 필요는 없습니다.

대신 **파일 중심의 사용자 경험을 AI 작업 중심의 사용자 경험으로 전환**하는 것이 핵심입니다.

**가장 먼저 구현할 세 가지 기능은 다음과 같습니다.**

1. **AI 결과 붙여넣기:** 다운로드·업로드 단계 제거
2. **현재 계획을 AI에게 전달:** 최신 계획과 기준 revision을 포함한 프롬프트 자동 생성
3. **AI 대화 시작 지원:** 새 여행에 필요한 정보를 포함한 프롬프트 자동 생성

이 세 가지는 개발 부담이 비교적 작으면서도 사용자가 느끼는 불편을 크게 줄일 수 있습니다.

이후 부분 변경 가져오기와 항목별 AI 요청 기능을 추가하면, 외부 AI 챗봇을 사용하면서도 **마치 travel-app에 AI 기능이 통합된 것처럼 느껴지는 경험**을 제공할 수 있습니다.
