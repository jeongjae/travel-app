## 권장 최소 구현 순서

빈 여행 생성 유지 → 지역/장소/가이드의 원자적 작성·연결 → 일정 연결·계획 변경 → 실제 기록/정정 → 회고 → 두 여행 복원.
책임 분리는 필요한 기능 범위에서 별도 커밋으로 한다. 전체 거대 파일 분해를 선행 필수로 두지 않는다.
기간 삭제·예약 작성·전체 본문 검색·새 AI 콘텐츠 변경안은 핵심 흐름 이후 별도 범위다.

문서 수정은 T-05와 독립적으로 병행 가능하다. C 기능 구현 착수나 G2/G2′ 통과를 뜻하지 않는다.

## 2026-10-29 R1 보완 결과

사용자 후속 지시로 Codex가 두 문서를 직접 수정했다. 초안의 수정 요청은 **문서 보완 완료 / 사용자 검토 준비**로 갱신한다.
구현·동작 검증 완료나 새 정책 확정을 뜻하지 않는다. 항목별 위치는 [R1 반영표](phase-c-r1.md)에 있다.

- 탐색·가이드 kind·placeLinks 등의 현 코드 용어를 대조했다.
- 빈 여행과 원자 콘텐츠 생성/연결을 분리하고 최소 계약 예시·실패/replay·domainRevision을 명시했다.

- T-C0를 선택적 책임 분리로 줄이고 계약/숙박·이동을 작은 단위로 나눴다. T-C7은 T-C6에 의존한다.
- 수동 숙박 입력의 날짜/시간대/모호성 검증과 SP-FR 원천 보존, D의 별도 승인 계약을 구분했다.
