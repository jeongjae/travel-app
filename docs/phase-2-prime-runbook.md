2026-10-26 후속: 사용자는 iPhone 15 Plus·iOS27.0.1·Chrome147.0.7727.47에서 지원 표시와 **ZIP 가져오기·일정·사진 조회까지** 확인했다. 당시 오프라인/종료/백업 복원은 미확인이었으며 후속 결과는 아래와 같다. 전달 대상은 `local-data/phase2/verified-package-20261026/pilot.zip`(84,453,766바이트)이며 [PC 검증 보고](full-verification-2026-10-26.md)에서 해시/구버전 보존을 확인한다.

10/27 사용자 수정 요청: 오늘 활동 옆 메모에 기록했지만 같은 메모 창에서 다시 보이지 않았다. [수정·재현 보고](note-visibility-fix-2026-10-27.md)의 수정본 확인 요청에 사용자가 ‘이전 메모가 보임’으로 답해 **기존 메모 재조회는 확인 완료**다. 데이터 삭제·ZIP 재가져오기는 요구하지 않았다.

같은 날 비행기 모드/Wi-Fi 차단 → 일정·사진·기존 메모 조회 → 검증용 새 메모 저장 → Chrome 앱 전환 화면 종료·재실행 후 기존/새 메모 유지 요청에 **‘오프라인 조회·저장·종료 후 유지 모두 성공’**으로 응답했다. 이 범위는 사용자 확인 완료다. 직접 기기 DB/첨부 해시를 대조한 결과는 아니며 전체43일·백업/복원·공간 부족·G2′ 전체 완료로 확대하지 않는다.

현재 확인 요청은 ‘저장소·백업 → 전체 백업 만들기 → 검증한 전체 백업 파일 저장’ 뒤 Apple 기본 ‘파일’ 앱에서 파일 존재·0바이트 초과 크기를 확인하는 단계다. 저장 성공 후 별도 빈 검토 공간의 복원을 안내하며 기존 공간은 초기화하지 않는다. 백업 파일 생성·보관·재선택·복원 결과는 아직 대기다.

실기기는 iPhone Chrome으로 확정됐다. 사용자 요청으로 테스트는 후속 일괄 단계로 모았다. PC viewport·기능 존재 여부로 G2′를 완료하지 않는다.

## 실행 전 결정

사용자의 웹 접속 요청으로 [GitHub Pages](https://jeongjae.github.io/travel-app/)에 앱 셸을 공개했다. 개인 ZIP은 사이트·릴리스에 포함하지 않는다. 파일 앱은 iPhone 기본 Apple ‘파일’ 앱이며 웹 공개만으로 개인 ZIP이 휴대폰에 전달되지는 않는다. PC의 통합 ZIP을 사용자가 관리하는 경로로 먼저 전달해야 한다. 10/26 사용자가 ZIP 가져오기와 일정/사진 조회 성공을 보고했으며 전달 경로 자체는 답변받지 않았다. [접속 안내](web-release-2026-10-25.md)를 따른다. 기존 기기 데이터는 지우지 않는다.

## 사용자와 함께 수행할 순서

1. iPhone 모델·iOS·Chrome·앱 커밋·접속 origin을 기록한다. 해당 origin에서 앱 셸을 열고 ‘저장소·백업 → 기기 이행 준비 상태’의 보안 컨텍스트·DB·OPFS·서비스 워커 표시를 본다. 표시는 지원 여부이며 동작 검증 결과가 아니다.
2. 통합 ZIP을 파일 앱에 보관하고 ‘여행 패키지 선택 → 미리보기 → 여행에 추가’로 별도 검토 저장소에 가져온다. 모든 43일·장문·사진·지도 파일·기존 메모/체크를 표본과 대조한다. 입력 실패/공간 부족이면 기존 데이터를 보존하고 오류·중단 작업을 기록한다.
3. 통신을 차단하고 날짜 이동·본문·사진·편집·현장 메모를 저장한다. 앱 종료·재실행 후 재조회한다. 외부 지도/AI 통신 실패를 오프라인 일정 손실과 구분한다.
4. 첨부 포함 전체 백업을 파일 앱에 저장한다. 별도 빈 검토 공간에서 파일을 재선택해 복원하고 원래 데이터와 행/첨부 해시를 대조한다. 취소·중단·재시도와 공간 부족은 기존 공간을 초기화하지 않고 검사한다.
5. 용량·소요 시간·실패·재실행·기기 화면과 사용자 확인 결과를 Git 제외 경로에 남긴다. M-05/06/10, R-07~09와 G2′를 증거로 갱신한다.

실제 ZIP의 경로와 수량은 [연속 구현 보고](phase-2-continuous-report.md)를 따른다. 파일 전달·수집·업로드·유료 실행을 이 문서 작성으로 승인한 것으로 해석하지 않는다.
