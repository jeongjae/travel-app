Prettier 지원 소스 JS/TS/JSX/CSS와 JSON/HTML/YAML 설정을 정리했다. 문서·Python·생성물·실제 데이터는 포맷 명령 대상에 넣지 않았다. Python 원천 도구는 기존 AST/XLSX 검사로 회귀 검증했다. 함수 책임 분리·이름 변경은 이번 변경에 섞지 않았다. 큰 컴포넌트의 추가 구조 개선 필요성은 G0 피드백과 후속 별도 변경으로 판단한다.

현재 TypeScript `7.0.2`는 확인한 TypeScript-ESLint parser `8.72.0`의 peer 범위(`<6.1.0`) 밖이다. 컴파일러를 내리거나 지원 경고를 숨기는 대신 Babel core/parser `8.0.7`의 문법 파싱만 사용했다. 타입 검사는 기존 `tsc --noEmit`이 담당한다. 린트 범위를 타입·React 전체 품질 감사로 과장하지 않는다. [Babel parser 설명](https://babeljs.io/docs/babel-eslint-parser).

pnpm `12.14.0`은 일반 프로젝트 설정을 `.npmrc`에서 읽지 않으므로 `pnpm-workspace.yaml`에 `saveExact`, `cacheDir`, `storeDir`을 두었다. 캐시/store는 `.cache/pnpm/`, 이번 Corepack 준비는 `.cache/corepack/`을 사용했다. 정책 검증을 끄지 않고 온라인 캐시 준비 후 frozen/offline 설치를 확인했다. [pnpm 설정 문서](https://pnpm.io/settings).

- **G0 확인 완료:** 2026-10-23 가독성 확인 질문에 사용자가 **“가독성 충분함”**이라고 응답했다. 상태는 `확인 완료`, Phase 1은 미착수다. 이미지 방식·키 폐기·다른 매체 백업은 별도 항목으로 남는다. 이번 확인 기록은 문서만 변경했으며 10월 22일 검사 결과를 재실행한 것으로 기록하지 않는다.
