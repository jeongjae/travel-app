## 1. 기준·입력 경계

AGENTS.md → handoff → 개발계획 → 요구/결정 → C 설계/계획 → C-01~05 검토·후속 목록을 읽는다.

worktree·reset·main 병합·배포·API 호출·사용자 DB/실기기 적용은 하지 않는다.

두 여행을 **같은 검토 공간**에 둔다.
- A: lineage를 가진 가져온 여행(SP-FR 형태의 가상 패키지). 가져온 뒤 앱에서 새 장소/가이드·일정·현장 기록을 추가/편집한다.
- B: C-01부터 앱에서 수동 생성한 독립 여행. 지역/장소/가이드·숙박/이동·실제/메모/정정·회고를 포함한다.

실제 SP-FR·사용자 기록·예약·본문·사진을 공개 fixture에 넣지 않는다.

## 2. 단위 A · 전체 백업→빈 공간 복원

- C-S1~C-S5 산출물의 통합 상태를 구성한다: 콘텐츠/소유 연결·Fact 바인딩·출처·가상 첨부, 과거/현재 계획,
  숙박/이동·실제 기록/메모·2회 이상 정정·변경안 상태/근거·회고.
  모든 기능을 새로 만들거나 기존 E2E를 복제하지 말고 기존 증거와 새 통합 검사의 대응표를 제출한다.
- 전체 백업 파일을 실제 생성/재선택하고 **빈 review 공간/새 브라우저 저장소**로 복원한다.
  기존 사용자 공간을 비우거나 덮어쓰지 않는다. 비어 있지 않은 대상은 거부되고 기존 데이터는 불변임을 확인한다.
- 복원 전후 도메인 행·ID·revision·연결·계획 이력·정정 체인·근거·가져오기 기준/receipt를 비교한다.
  새 spaceId·복원 작업 메타 같은 의도된 차이는 명시적으로 분리한다. 무관한 행 누락을 광범위 정규화로 숨기지 않는다.
- 첨부는 이름/메타 존재뿐 아니라 바이트·크기·해시를 비교한다. 실제 파일 읽기·가이드 표시/첨부 열기까지 연결한다.
- 복원 후 C-S1~S5를 화면에서 재조회하고 여행 전환·앱 재실행·오프라인 재조회 뒤에도 동일한지 확인한다.
  복원된 새 검토 공간에서 작은 편집/기록이 정상 저장되는지도 확인하되 그 후 상태를 최초 복원 비교와 혼동하지 않는다.

## 3. 단위 B · 앱 편집·현장 기록의 재가져오기 보존

- 가져온 A에 새로 작성한 콘텐츠/항목은 같은 패키지 재검토와 새 원천 변경에도 app-only로 보존한다.
  원천에 없다는 이유로 삭제/비활성화하거나 import baseline을 local로 덮어쓰지 않는다.
- 동일 패키지 배열 순서 차이는 오탐하지 않아야 한다. 새 원천만 변경/source-only, 앱만 변경/app-only,
  양쪽 변경/conflict와 defer·local·remote 선택의 의미를 검증한다. 기존 T-05 구 baseline/추가 필드 거부를 유지한다.
- 검토 준비/보류는 계획·기록을 바꾸지 않는다. 실제 선택 적용은 가상 검토 공간에서만 수행하고 명시 선택과 적용 결과를 대조한다.
  local/defer인 앱 편집과 실제/메모/정정·당시 맥락은 유지한다. remote를 명시 선택한 대상의 차이는 의도된 변경으로 분리한다.
- stale domain revision·재시도/replay·부분 실패에서 승인되지 않은 쓰기/중복/기준 갱신이 없어야 한다.
  복원한 공간에서 같은 재가져오기 검토를 반복해 기준/선택 의미가 보존됐는지 확인한다.
- B의 콘텐츠·계획·기록은 A의 검토/적용 전후 불변이다. 과거 계획/당시 본문도 그대로 읽혀야 한다.

## 4. 단위 C · 미검증 근거 UI·실제 사본 대조

- C-05에 빠진 **회고→적용 당시 고정 근거 본문→같은 날짜/선택 버전 회고 복귀**를 PC/모바일 E2E로 추가한다.
  가상 패키지/기존 테스트 구성으로 근거와 변경안/결과 계획을 준비한다. 새 근거 작성 UI·실제 AI 호출은 만들지 않는다.
  같은 근거의 최신 revision과 당시 revision 내용을 다르게 해 고정된 당시 본문이 열리는지 검사한다.
  오프라인·백업/복원 후에도 같은 근거/이유가 읽히고 조회 전후 DB·현재 계획·revision·receipt가 불변이어야 한다.
- 실제 대조는 기존 verified 또는 T-04 후보 ZIP을 **읽기 전용 입력**으로 사용해 새 local-data 검토 사본/새 프로필에서 1회 수행한다.
  원래 ZIP/해시·사용자 DB·iPhone·사용자 검토 프로필을 덮어쓰지 않는다. 실제 사본과 가상 수동 여행의 공존/백업/빈 공간 복원·수량/첨부 해시를 확인한다.
  보고에는 입력 경로/해시·버전·수량·결과만 남기고 실제 본문/예약/개인 화면·로그는 Git 제외 경로에 둔다.
  원천 패키지가 없거나 환경이 막히면 그 검증만 미실행으로 명시하고 가상 통합 검증은 끝낸다. 실제 검증을 추정해 통과 처리하지 않는다.
- 사용자에게 보여줄 산출물: 두 가상 여행 통합 상태, 빈 공간 복원 후 각 화면/정정/회고, 재가져오기 보존/충돌 선택 결과,
  당시 근거 본문·복귀. 결과에 재현 동작·가상 입력·화면/검사 증거 경로를 남긴다.

## 5. 검사·제출·범위 통제

대상 검사 후 최종 `pnpm run check:deferred`. PC/모바일은 에뮬레이션과 실기기를 구분하고, 포함된 검사를 같은 코드에서 반복하지 않는다.
제품 결함을 발견하면 가상 재현→최소 수정→관련 회귀로 처리하고 수정 이유/전후/영향을 보고한다. 기능·구조·포맷 커밋은 분리한다.
CL-08 DST·CL-14 회고 변화 표시 등 경미한 잔여는 기록 상태를 유지한다. 결함을 숨기도록 기대값/검증 범위를 완화하지 않는다.
데이터 손실·여행 격리·저장/복원·재가져오기 충돌·고정 revision/근거 연결·보안 문제는 보류하지 않는다.

통합 시험/필수 수정과 `docs/claude-task-c06-result.md` 보고를 별도 커밋으로 작업 브랜치에 push한다.
결과에 기준/종료 SHA·시나리오-증거표·검사/exit code·CI·가상/실제 대조 경계·미검증·사용자 확인 동작을 남긴다.
Codex 검토·사용자 확인은 대기로 둔다. 상위 계획/후속 목록은 Codex가 관리하므로 차이/제안은 결과에만 남긴다.
T-C7 검증을 T-C8 사용자 시나리오·C 전체·B/G2/G2′ 완료, 배포·실제 사본 적용 승인으로 확대하지 않는다.
T-06/F-2·지역 ZIP 재발행·사진/지출·AI·자동 동기화·공개 배포는 범위 밖이다.
