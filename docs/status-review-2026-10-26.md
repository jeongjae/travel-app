## 2. 문제점 — 해석

### P1. 검증 부채가 구현 속도를 따라가지 못함 (가장 중요)
10/23 09:16~10:07 **약 50분** 동안 Barcelona 이후 8개 지역·귀국일·통합본·v2 AI·운영 문서가 생성·커밋됐다(사용자 지시 "토큰 소모할 때까지 끝까지, 테스트는 나중에"). 그 결과:
- 43일 통합본은 **변환 명령의 자기 무결성 검사**(ZIP 재읽기 수량 일치)만 통과했다. 브라우저 DB 적재, 빈 저장소 복원, 원천과의 독립 대조, 화면 확인은 0건이다.
- `deferred-verification.md`에 **미작성 회귀 10개 항목**(귀국일, 복수 지역 이동일, 16 MiB 행 경계, 장문 분할, 기존 메모/체크 보존 등)이 열려 있다. 이들은 통합본에서 **실제로 발생한 경계 사례**다.
- 코드가 3배 이상 늘었지만 테스트 정의는 71→86으로 15개 증가. v2 AI(`StageAiProposal` 포함)는 테스트 0.
- CI 123/38 통과는 **10/23 이전 기능 + 10/25 보정분**의 통과다. 10/23 신규 기능의 검증 결과가 아니다(개발AI도 같은 경계를 명시함).

### P2. 2.1 GB 이행 결과물이 단일 디스크에만 존재
Git은 코드·문서만 보호한다. 통합 ZIP(84 MB), 지역 패키지 9개, 원천 사본, 사용자 확인을 거친 G1·B-01 ZIP과 검토 프로필은 **전부 `local-data/`에만** 있다. 스크립트로 재생성은 가능하지만 수 시간이 들고, **사용자가 확인한 그 파일**(해시 `3e73d4bd…`)은 재생성해도 바이트가 같다는 보장이 없다. 10/22 I-1b "별도 매체 백업"이 4일간 미실행이다.

### P3. 공개 저장소에 개인 경로 2곳
Windows 계정명이 포함된 절대경로가 push됐다. 치명적이지 않으나 10/22 사용자 결정(I-2: push 전 개인 맥락 점검)에 어긋난다. 커밋 이력에서 완전 제거는 force-push가 필요하므로 **현 파일만 정정**하는 선에서 처리한다(이력 제거는 별도 결정).

### P4. Pages가 테스트 없이 자동 재배포됨
`pages.yml`은 `src/**` 변경 push마다 format/lint/build만 통과하면 공개한다. 테스트가 미뤄진 상태에서 push가 곧 공개다. 현재 배포본(`00a546a`)은 CI를 통과한 커밋이므로 지금은 문제가 없지만, 구조상 **"검증 안 된 빌드가 공개 URL에 올라가는" 경로가 열려 있다.**

### P5. 거대 컴포넌트는 그대로 (10/22 I3 미해결)
포맷으로 **읽을 수는 있게** 됐지만 `ContentApp.tsx` 1,305줄·`content-repository.ts` 1,143줄은 책임 분리가 안 됐다. Phase 1에서 SP-FR UX 보존(5개 탐색 축)을 위해 `Journey.tsx`·`DayDetails.tsx`·`Guide.tsx` 등이 분리된 것은 진전이나, 상태·명령 조립은 여전히 한 곳에 몰려 있다. 10/22 계획대로 "Phase 1 이후 별도 범위"였으므로 지연이 아니라 **이제 할 때**가 된 것이다.

### P6. OPFS 선택의 실기기 리스크
OPFS(브라우저 전용 파일 영역)는 iPhone의 모든 브라우저가 WebKit을 쓰므로 **iOS 버전에 따라 지원 범위가 다르고**, 사이트 데이터 삭제 시 함께 지워진다. 594개 첨부(약 82 MB)를 OPFS에 넣고 iPhone에서 열어 본 적이 없다. 이것은 10/22 D4(메모리 상주 ZIP 한도)와 함께 **Phase 2′에서만 드러나는 위험**으로 남아 있다. 개발AI도 G1 종료 시 "전체 확대 전 iPhone 1차 권장"을 두 번 기록했으나 사용자 결정(PC 우선)에 따라 미실행이다.

### P7. 관문 체계가 사용자 지시로 한 번 우회됨
10/22 계획의 핵심 장치는 "단계마다 사용자가 직접 보는 산출물 + 확인"이었다. 10/23 "배치 확인 없이 끝까지" 지시로 B-02 이후 관문이 생략됐다. 이는 사용자의 정당한 선택이지만, **그 대가(P1)가 지금 쌓여 있다**는 점은 명확히 인식해야 한다. 개발AI는 이 경계를 모든 문서에 정직하게 표기했다(완료로 과장한 곳 없음).

### 잘 된 점 (인정할 것)
- 10/22 지적 I1·I2·I4·P4·D3 해결: 커밋/push, 포맷, 원격 CI, handoff 1쪽(31→현재 약 40줄), HTTPS origin.
- 사용자 확인 3회(G0·G1·B-01)와 수정 요청 1회(백업 메뉴 위치)가 **기록·반영**됐다.
- 모든 보고서가 "구현 / 자동 검사 / 독립 검증 / 사용자 확인"을 구분하고 미완료를 완료로 쓰지 않았다.
- 원본 SP-FR 미변경, 개인 데이터 미공개, 키 미노출 유지.

## 부록. 용어
- **OPFS**(Origin Private File System): 웹앱 전용 숨은 파일 저장 영역. 사용자 파일 앱에는 보이지 않고, 사이트 데이터 삭제 시 함께 지워진다.
- **관문(G0~G4)**: 단계 완료 조건. 자동 검사 + 사용자가 직접 본 산출물 + 사용자 확인 응답.
- **독립 대조**: 변환 프로그램 자신의 검사가 아니라, 원천 파일과 결과 DB를 별도 도구로 비교하는 것.
- **deployment.json**: 공개 사이트가 어느 커밋으로 빌드됐는지 적은 파일.
