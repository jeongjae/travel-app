## 1. C1 가이드 변환기 (화면 없음)

- 위치: `src/guide-import/`. 입력 글 처리(보이지 않는 글자, 코드 블록, 양식 줄 집계)와 표 읽기는 `src/plan-import/`의 것을 **재사용**한다. 양식 값만 다르게 받도록 필요한 만큼만 일반화한다(계획 변환기의 동작과 시험이 바뀌면 안 된다).
- `parseGuide(text)` → `{ destination, referenceDate?, items[], issues[], notImported[] }` 또는 거부. 항목은 `{ key, kind, name, area, description, durationText, needsCheck, line }`.
- `key`는 가이드 글의 지문(해시) + 줄 순번으로 만든다(같은 글이면 같은 key).
- 규격 §3대로 오류가 하나라도 있으면 가이드 전체를 받지 않는다. 오류는 줄 번호·이유로 모두 모은다.
- 계획 양식의 글이 들어오면 거부 코드 `is-plan`으로 구분한다.
- 시험: 고정 자료 `docs/p0-results/g1-guide-hakodate.md`(34항목, 종류별 4·15·8·4·3, 오류 0)를 `tests/fixtures/guide-format/`에 복사. 입력 변형(코드 블록·설명문·CRLF·BOM)에서 같은 결과. 모르는 종류, 열 개수 불일치, 이름 빈 칸, 양식 줄 없음·두 번, 중복 항목 경고, 계획 글 거부, 열 순서 바뀜.

**C1 중간 보고** 뒤 멈춘다.

## 2. C2 가이드 화면

위치: "AI로 계획 만들기" 화면 안의 두 번째 구역 **"목적지 가이드"**(조건·취향 → 가이드 → 요청서 순으로 보이되 순서를 강제하지 않는다). 건너뛰어도 요청서를 만들 수 있어야 한다.

1. **가이드가 없을 때**: "가이드 요청문 복사"(여행지·기간은 조건 답에서 가져온다. 여행지가 비어 있으면 단추 옆에 "여행지를 먼저 적어 주세요"), "가이드 붙여넣기"(입력 칸 + 클립보드 단추 + 파일 선택), "가이드 없이 계속". 요청문은 [가이드 요청문](guide-format-v1-prompt.md)의 두 선 사이 글을 **한 곳에서 읽어** 쓴다(T-E1 C3와 같은 방식).
2. **붙여 넣은 뒤**: 오류면 줄 번호·이유와 "챗봇에게 '가이드 양식의 코드 블록 하나로 다시 정리해 줘'라고 요청하세요" 안내. 성공이면 카드 목록.
3. **카드**: 종류 · 이름 · 지역 · 한 줄 설명 · 예상 소요 · 확인 필요. 글자로만 보여 준다(HTML로 그리지 않는다). 맨 위에 `AI가 만든 가이드 · 내용은 확인되지 않았습니다`와 기준일.
4. **고르기**: 카드마다 `꼭 포함 / 관심 / 제외` 세 단추. 같은 단추를 다시 누르면 고르지 않음으로 돌아간다. 색만으로 구분하지 않고 글자와 눌림 상태를 함께 보여 준다.
5. **거르기**: 종류 칩(전체·볼거리·먹거리·체험·코스·지역)과 "고른 것만 보기". 처음 순서는 가이드의 줄 순서.
6. **종류 단위로 한 번에**(P0 관찰): 종류 칩으로 거른 상태에서 "보이는 항목 모두 → 꼭 포함 / 관심 / 제외 / 고르지 않음". 누르기 전에 몇 개가 바뀌는지 보여 준다.
7. **비슷한 항목 알림**(P0 관찰, 규칙은 [검토 R1](claude-task-p01-review.md)로 정정): 제외한 항목의 이름이 다른 항목의 이름·지역·설명에 들어 있거나 그 반대인데 그 항목이 제외되지 않았으면 카드 아래에 "비슷한 항목이 더 있습니다: …"를 보여 준다. 자동으로 바꾸지 않는다.
8. **현황**: 꼭 포함 n · 관심 n · 제외 n. 예상 소요는 합산하지 않는다.
9. **가이드 바꾸기·지우기**: 다른 가이드를 붙여 넣으면 "고른 것이 모두 지워집니다"를 확인받는다. 취소하면 그대로 둔다. "가이드를 파일로 저장"(붙여 넣은 원문 `.md` 내려받기)을 둔다 — 나중에 다시 붙여 넣어 쓸 수 있다.
10. iPhone 폭에서 한 열, 단추는 손가락으로 누르기 충분한 크기, 주요 단추는 아래쪽.

## 3. C3 준비 초안 저장

- 저장 위치: `localStorage`의 키 하나(버전 포함). **초안은 1건**이다. 내용: 조건·취향 답(T-E1 C3의 답), 가이드(원문과 해석 결과), 고른 상태.
- T-E1에서는 답을 저장하지 않았다. 이번에 답도 초안에 함께 저장한다(가이드를 고르는 동안 화면을 떠났다 돌아오는 일이 생기기 때문).
- 화면에 "이 기기에만 저장됩니다. 백업에 들어가지 않고 다른 기기로 옮겨지지 않습니다"를 보여 준다. "준비 초안 지우기" 단추.
- 저장 실패(용량·차단)면 알리고 메모리 상태로 계속한다. 초안 형식이 다르거나 깨졌으면 버리고 알린다.
- 새 여행을 저장(가져오기 성공)해도 초안은 자동으로 지우지 않는다. 저장 성공 화면에 "준비 초안 지우기"를 제안한다.

## 4. C4 요청서 결합과 미리보기 옆 선택 목록

- `buildTravelBrief`(T-E1)에 고른 항목 묶음을 끼운다. 순서: 조건 → 취향 → `[꼭 포함]` → `[관심]` → `[제외]` → `[확인할 것]` → 부탁할 일 → 양식 안내문. 표기는 규격 §4. 고르지 않은 항목은 넣지 않는다. 묶음이 비면 그 묶음 제목도 뺀다.
- 부탁할 일에 한 줄을 더한다: "[꼭 포함]을 넣기 어렵거나 [제외]를 넣어야 한다면 먼저 나에게 알려 줘."
- 요청서 미리보기에서 들어가는 글 전체를 볼 수 있어야 한다(외부 챗봇으로 나가는 내용).
- **"AI 결과 붙여넣기" 미리보기**에 초안의 `꼭 포함`·`제외` 목록을 옆(iPhone에서는 아래)에 보여 준다. 제목: "내가 고른 것 — 계획에 반영됐는지 확인하세요". 앱이 자동으로 판정하거나 계획을 고치지 않는다. 초안이 없으면 이 구역을 보여 주지 않는다.

## 5. 시험

- 단위: 변환기(§1), 요청서 결합(같은 초안이면 같은 요청서, 묶음별 표기, 빈 묶음 생략, `확인할 것`), 초안 저장·복원·깨진 초안·저장 실패.
- E2E(`tests/e2e/`): ① 가이드 붙여넣기 → 카드 34개 → 3개 꼭 포함·1개 관심·3개 제외 → 요청서에 그대로 → 새로고침 뒤에도 유지 ② 종류로 거른 뒤 한 번에 고르기 ③ 가이드 바꾸기 확인·취소 ④ 가이드 없이 요청서 만들기 ⑤ 가이드를 붙여 넣고 고른 뒤 **여행 DB와 백업 내용이 그대로**(AC-24) ⑥ AI 결과 미리보기에 고른 목록 표시 ⑦ 오프라인.
- P0의 실제 자료로 한 번 재현한다: 하코다테 가이드에서 P0와 같은 7개를 고른 요청서를 만들고, `docs/p0-results/g3-b-with-selection.md`를 붙여 넣어 미리보기 옆 목록이 보이는지.
