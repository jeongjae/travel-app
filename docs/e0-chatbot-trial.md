# E0 · 챗봇 양식 시험 절차와 기록표

2026-11-13 · 작성: Codex 역할 세션 · 상태: **검토 준비 / 사용자 시험 대기** · 근거: [설계서 v0.3](ai-rework-requirements-design.md) §4.2·§5·AC-01·AC-15, [결정 11/13 16:49](decisions.md)

목적: 챗봇이 [안내문](plan-format-v1-prompt.md)만 보고 양식을 지키는지 확인해 **md 표(A안)를 유지할지 JSON 블록(B안)으로 바꿀지** 정한다. 코드는 쓰지 않는다. 가상 여행만 쓴다(실제 예약·개인 정보를 넣지 않는다).

## 할 일 (사용자, 약 20~30분)

챗봇 2종(ChatGPT·Claude)에서 각각 **새 대화**로 아래 3가지를 한다. 합계 6개 파일.

| 시험 | 넣는 것 | 요청 문구(그대로) |
|---|---|---|
| T1 새 여행 | 안내문 | `2027년 4월에 3박 4일로 후쿠오카 여행을 가려고 해. 일정, 숙소, 이동, 장소를 모두 채워서 파일로 줘. 하루는 밤 11시 반에 시작해 자정을 넘기는 일정을 하나 넣어 줘.` |
| T2 메모만 수정 | 안내문 + [내보내기 예시](examples/plan-export-sapporo.md) 전문 | `첨부한 계획에서 "점심: 스프카레"의 메모만 "13시 이후가 덜 붐빔"으로 바꾸고, 1월 1일 저녁에 새 식사 일정을 하나 추가해 줘. 바뀐 부분만 파일로 줘.` |
| T3 삭제·비움 | 안내문 + 같은 내보내기 예시 | `첨부한 계획에서 "카페 휴식"을 없애고, "저녁: 징기스칸"의 링크를 지워 줘. 바뀐 부분만 파일로 줘.` |

받은 결과 6개를 이 대화에 붙여 주면 Codex가 아래 기준으로 판정한다(파일 이름에 챗봇·시험 번호를 적어 주면 좋다).

## 판정 기준 (Codex가 채움)

| 구분 | 기준 |
|---|---|
| 형식 통과 | 구역·열 이름과 순서, 열 개수, 날짜·시간 표현, 양식 줄이 규칙과 같다. 사람이 고치지 않고 읽을 수 있다 |
| 조용한 데이터 손실 | 오류로 잡히지 않는데 값이 빠지거나 바뀌는 경우. 예: T2·T3에서 ID가 바뀜, 요청하지 않은 칸의 값이 달라짐, `(비움)` 대신 다른 표현, 삭제를 줄 삭제로 처리(→ 삭제가 안 됨), 머리의 여행ID·기준 줄 변경 |
| 결론 | 형식 통과 6개 중 5개 이상 **그리고** 조용한 데이터 손실 0건 → A안 유지. 아니면 B안 전환을 사용자에게 제안 |

## 1회차 결과 — ChatGPT (사용자 전달 2026-11-13 17:24, 안내문 v1.0)

| 시험 | 받은 것 | 형식 통과 | 어긴 점 |
|---|---|---|---|
| T1 새 여행 | PDF·Word "여행 실행 가이드"(4쪽, 자유 형식). 원본 PDF는 저장소에 넣지 않음 | **아니오** | 양식을 전혀 쓰지 않음. 머리 줄·구역·표 없음. 자정 넘김 일정 자체는 계획에 들어 있음(23:30~00:40) |
| T2 메모만 수정 | [md](e0-results/chatgpt-t2-run1.md) | **아니오** | 자기 형식("변경 필드/변경 값" 표, "적용 날짜")을 만듦. `- 양식:`·여행ID·기준계획 줄 없음. **새 항목에 ID를 지어냄**(…0007). 수정 대상 ID와 내용은 정확 |
| T3 삭제·비움 | [patch](e0-results/chatgpt-t3-run1.patch.txt) | **아니오** | diff 패치로 냄. 삭제를 줄 삭제로, 링크 지우기를 빈 칸으로 표현(`## 삭제`·`(비움)` 미사용). 요청 의도 자체는 정확 |

- 사실: 3개 모두 형식 미통과. **조용한 데이터 손실은 0건**이다 — 셋 다 앱이 읽으면 "양식 아님"으로 거부될 형태이고, 잘못 읽혀 저장될 형태가 아니다. T2의 지어낸 ID는 "없는 ID" 오류로 걸린다.
- 해석(Codex): 실패 원인은 표 문법(`|`, 열 개수)이 아니라 **결과물의 형태를 챗봇이 스스로 고른 것**(PDF, 패치, 자체 요약표)이다. "파일로 줘"·"바뀐 부분만"이라는 요청 문구가 이를 유도했다. JSON 블록(B안)으로 바꿔도 같은 실패가 난다. 따라서 이 결과만으로 A→B 전환을 판단하지 않고, 안내문을 고쳐 다시 시험할 것을 제안한다(결정 1의 기준에서 벗어나므로 사용자 승인 필요).
- 미확인: 세 대화에서 안내문 전문을 먼저 붙여 넣었는지. T1 결과에는 안내문을 본 흔적이 없다.
- 조치: [안내문 v1.1](plan-format-v1-prompt.md) — 출력은 대화 안 md 코드 블록 하나로 고정, PDF·Word·patch·diff 금지, 자체 형식 금지, 수정 요청 출력 예시, 출력 전 점검표.

## 1회차 결과 — Claude (사용자 전달 2026-11-13 17:27)

| 시험 | 받은 것 | 형식 통과 | 어긴 점 |
|---|---|---|---|
| T1 새 여행 | Word 일정표(.docx). Codex는 파일을 열지 않고 챗봇의 설명으로 판단 | **아니오** | 양식을 쓰지 않음 |
| T2 메모만 수정 | [md](e0-results/claude-t2-run1.md) | **예** | 머리 줄 7개·구역·표 제목 그대로, 수정 줄은 전체 값 유지 + 메모만 변경, 새 줄은 ID 비움. 현재 규칙으로 그대로 읽힌다 |
| T3 삭제·비움 | [md](e0-results/claude-t3-run1.md) | **아니오** | 삭제 표의 열이 다름(`ID·구분·날짜·제목`, 종류 값 "일정"). 링크 지우기를 빈 칸으로 표현(→ 규칙상 "변경 없음"). 이름 줄에 "(변경분)" 추가, 모르는 머리 줄 `- 범위:`, 구역 안 설명 글 1줄 |

- **이번 1회차는 안내문 시험으로 볼 수 없다(Codex 판단).** 근거: Claude가 답에서 "원본 양식에는 삭제를 나타내는 규칙이 없어서 `## 삭제` 섹션을 새로 만들었다", "부분 파일용 양식이 따로 있는지 몰라", "ID가 필수라면 알려 달라"고 했다. 안내문에는 이 규칙이 모두 있으므로 안내문이 전달되지 않은 것으로 보인다. ChatGPT 결과도 같은 조건이었을 가능성이 높다(사용자 확인 필요).
- 그래도 얻은 사실:
  1. **안내문 없이 내보내기 파일만 줘도** Claude는 표 형식을 유지했고 ID를 보존했다(T2는 그대로 통과). ChatGPT는 자체 형식·패치로 갔다.
  2. 규칙을 모르면 두 챗봇 모두 "지우기 = 칸 비우기", "삭제 = 줄 빼기 또는 자기 방식의 표"로 표현한다. 현재 규칙에서는 **지우기가 반영되지 않는데 오류도 나지 않는다**(T3 Claude의 링크). 값이 사라지는 손실은 아니지만 사용자가 모르고 지나갈 수 있다.
  3. 새 여행(T1)은 두 챗봇 모두 PDF·Word 문서로 냈다. 양식을 모르면 당연한 결과다.
- 조치(설계서 §4.2·§4.3에 [제안]으로 반영): ① **내보내기 파일 안에 규칙 요약 6줄과 빈 `## 삭제` 표를 넣는다**([예시](examples/plan-export-sapporo.md) 갱신) — 안내문을 잊어도 규칙이 따라간다. ② 미리보기에 "ID는 있는데 변경이 없는 줄"을 따로 보여 준다. ③ 여행ID가 있는 파일의 이름 줄은 읽지 않는다.

## 2회차 결과 — ChatGPT (사용자 전달 2026-11-13 17:38, 안내문 v1.1·규칙 내장 예시)

| 시험 | 받은 것 | 형식 통과 | 내용 |
|---|---|---|---|
| T1 새 여행 | [md](e0-results/chatgpt-t1-run2.md) — 일정 25줄·숙소 1·이동 7·장소 12 | **예** | 머리 줄·구역·열 이름과 순서, 열 개수, 시간 표현(자정 넘김 `23:30-01:00(+1)`, 시간 미정 빈 칸), 종류 권장값, `https` 링크, ID 빈 칸 모두 규칙대로. 간이 스크립트 대조에서 위반 0건. 미확인 정보는 비우거나 "미확인"으로 적음 |
| T2 메모만 수정 | [md](e0-results/chatgpt-t2-run2.md) | **예** | 머리 줄 7개 유지, 고친 줄은 ID + 메모 칸만, 새 줄은 ID 비움 |
| T3 삭제·비움 | [md](e0-results/chatgpt-t3-run2.md) | **예** | 링크 칸 `(비움)`, `## 삭제`에 `활동`·ID·제목 |

- 사실: ChatGPT 3/3 형식 통과, 조용한 데이터 손실 0건. 1회차(0/3)와의 차이는 안내문·규칙 전달뿐이다.
- 한계: ① T2·T3에 안내문 v1.1을 함께 넣었는지 미확인. 넣었다면 안내문의 수정 예시가 T2·T3과 같은 삿포로 항목이라 **답을 미리 보여 준 셈**이어서 시험의 독립성이 낮다(안내문 예시를 다른 여행으로 바꿔야 함). ② 변환기가 없어 "통과"는 규칙 대조 기준이다.
- **실제 출력에서 드러난 설계 빈 곳 2건**(양식 위반이 아니라 변환 규칙이 없는 곳):
  1. **이동 표**: 챗봇은 출발·도착을 지명·역 이름("후쿠오카 공항", "하카타역")으로 쓴다. 내부 이동(`planLeg`)은 **두 활동을 잇는 구조**(`fromActivityId`·`toActivityId`)라 지명만으로는 만들 수 없다. 또 같은 이동이 일정 표의 `이동` 종류 줄과 이동 표에 **두 번** 나온다.
  2. **일정의 장소 칸**: "하카타역 근처 호텔", "다자이후 참배길"처럼 장소 표에 없는 이름이 온다. 내부 활동에는 장소 이름을 글자로 담는 칸이 없고 장소 연결(`placeLinks`)만 있다.
