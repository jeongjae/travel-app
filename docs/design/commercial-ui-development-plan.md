## 1. 시작 조건과 담당

작성 시점에 확인한 D 작업 브랜치에는 T-D1 결과 커밋 `abc311c`가 있다. 이는 관찰한 개발 위치다. **UI 착수 기준은 나중에 사용자가 의뢰하는 시점의 D 종료 인계**다. T-D1 결과만으로 D가 끝났다고 판정하지 않는다. 현재 Claude에게는 이 계획을 전달하거나 작업을 요청하지 않는다.

| 시점 | 담당 | 산출물·판정 |
| --- | --- | --- |
| 의뢰 전 | 사용자·Codex | 사용자 지정 D 작업 종료와 UI 의뢰 확인. Codex가 최종 브랜치·SHA, 병합 여부, 잔여 결함, 수정 중 파일, 인계 문서를 대조한다. 설계 브랜치의 문서는 GitHub에서 별도로 읽을 수 있다. |
| 착수 | Claude | 합의한 제품 기준에서 UI 전용 브랜치를 사용한다. 최신 D 화면·테스트와 설계를 대조해 충돌하는 요구·변경 경로를 결과서에 기록한다. 기존 공용 체크아웃의 미커밋 작업이 섞이면 쓰기를 시작하지 않는다. |

## 2. 구현 순서

의존 순서는 **UI-01 → UI-02 → UI-03 → UI-04 → UI-05 → UI-06**이다. A는 시제품, B는 화면별 적용, C는 통합 확인이다. 한 단위당 최대 세 하위 작업으로 진행하고, 같은 화면 파일을 여러 작업자가 동시에 고치지 않는다. B의 화면 변경은 같은 기준으로 검증하되 사용자가 후속 확인을 묶도록 지정하면 범위와 미확인 항목을 기록한다.

| 단위 | 구현 범위와 소유 영역(현 기준 파일) | 제출할 산출물과 판정 조건 |
| --- | --- | --- |
| **A · UI-01 오늘·회고 시제품** | ① 하루 정보와 이동 행 ② 회고 결과와 비교 ③ 가상 시나리오·증거. `ContentApp.tsx` 해당 분기, `Journey.tsx`, `DayDetails.tsx`, `Retrospective.tsx`, 관련 CSS. | 같은 여행으로 조작 가능한 두 화면. 인접·비인접 이동, 장소 복귀, 첫 화면의 방문 집계, 과거 버전·정정 기록의 의미를 확인. [첫 지시서](../claude-task-ui01-day-retro.md) 기준. |
| **B · UI-02 여행 시작·전체 일정·작성** | ① 생성·체험·패키지 시작과 여행 전환 ② 날짜 직접 선택과 하루 복귀 ③ 활동·숙박·이동 폼 정리. `ContentApp`, `Journey`, `Authoring`, `StayLegEditors`, `TimeFields`. | 첫 여행 생성 후 날짜 선택. 43일 가상 여행에서 날짜 선택기로 마지막 날에 바로 진입. 다음 날 종료 확인·연결 이동 제거 안내·변경 이유 유지. 다른 여행에서 이전 선택 잔류 0건. |
| **B · UI-03 가이드·자료 읽기** | ① 지역·장소 탐색 ② 준비·회화·예약·할 일·지도 ③ 가이드 작성과 출처/당시 본문. `GuideList`, `Guide`, `GuideAuthoring`, `PhraseContext`, `ContentApp`. | 긴 한글 제목·목차·본문·첨부/사진 없음·여러 장을 확인. 장소/준비 화면에 각각 복귀. 오프라인에서도 로컬 안내가 열리고 외부 링크는 인터넷 필요를 표시. |
| **B · UI-04 현장 기록·정정·메모** | ① 방문과 예정 외 기록 ② 날짜별 목록·회고 전환 ③ 정정과 메모. `Field`, `TimelineRecords`, `Notes`, `quick-time`의 기존 동작 참조. | 확인된 시간대에 한 번 눌러 한 건 저장, 미확정은 폼. 자정·날짜 미상·날짜 정정·원문 조회·저장 실패/재입력을 확인. 오프라인 새로고침 뒤 가상 기록 유지. |
| **B · UI-05 더보기·데이터·변경안** | ① 더보기 및 가져오기 기록, 계획 버전 ② 백업·빈 공간 복원·첨부 복구 ③ D 종료본의 변경안/AI 안내. `Recovery`, `Workflows`, `AiPlanner`, `ContentApp`. | ZIP 세 경로와 잘못된 입력·빈 공간 요구 확인. 모의 AI에서 전송 동의·항목 검토·적용 순서, 예약 영향·충돌·응답 유실 표시를 대조한다. 서버·인증·모델 변경이 필요하면 별도 지시로 돌린다. |
| **C · UI-06 통합 회귀·사용자 확인** | ① 격리된 두 여행으로 전체 여정 ② 반응형·접근성·오프라인·복원 ③ 사용자 확인 대본·미해결 목록. | 아래 검증표, 기존 [U4 대본](../u4-sapporo-scenario.md), D 종료본의 모의 회귀를 연결한다. PC는 실제 클릭, 모바일은 에뮬레이션과 사용자 iPhone 확인을 분리해 기록한다. |

## 3. 공통 검증표

| 검증 대상 | 자료·행동 | 기대 결과 |
| --- | --- | --- |
| 가독성·접근성 | 320px·390×844·PC 1280px, 200% 확대, 키보드로 탭/날짜/폼/복귀 | 본문 가로 넘침 0, 날짜 띠 안의 의도된 스크롤만 허용. 44px 주요 조작, 본문 명암비 4.5:1, 표시되는 포커스, 하단 탭과 키보드에 가려지지 않는 저장. |
| 기능·데이터 보존 | 가상 A/B와 43일 가상 일정, 동명 활동, 서로 다른 계획 버전·시각 정밀도, 사진 0/1/복수 | 다른 여행·버전 참조 혼입 0. 날짜 이동 및 정정 후 원문과 발생일 미상 보존. 스키마·백업 형식을 UI 변경에 포함하지 않는다. |
| 실패와 복구 | 오프라인 재시작, 두 탭의 오래된 revision, 다중 누름, 잘못된 ZIP, 빈/사용 중 공간 | 조회·현장 기록 유지. 기존 버전 덮어쓰기·중복 적용·실패 성공 표시 0. 백업 복원 전후 여행 수·기록·연결을 비교. |
| AI 경계 | D 종료본의 모의 제공자와 가상 자료로 동의 철회·충돌·응답 불명 시나리오 | 전송과 적용이 별개이며 확인 없이 호출·재호출·적용하지 않는다. 실키·유료 호출·배포 없이 검증한다. |

각 UI/저장 변경 단위에서 프로젝트 지정 pnpm으로 `pnpm run check`(포맷·린트·유닛·빌드) 및 `pnpm run test:e2e`를 수행한다. 우선 재현할 기존 시험은 `u4-sapporo`, `ui-c15`, `retrospective`, `offline-authoring`, `c06-integration`과 D 종료본의 AI 시험이다. 기능·보존 요구를 낮춰 기존 시험을 통과시키지 않는다. 실행 불가·건너뜀·실기기 미확인은 각각 결과에 남긴다.

## 4. 인계와 변경 관리

Claude는 각 단위 결과를 `docs/claude-task-uiNN-result.md`에 남긴다. 20줄/2,000자 이내 요약, 기준·결과 SHA, 검사 명령·결과·미실행, 화면 경로·재현 순서, 회귀 차이·후속 항목을 포함한다. Codex는 별도 검토 기록에 독립 확인과 사용자 판정을 구분한다. 검토 공간은 단위별 새 이름을 사용하고 실제 여행·백업·개인 프로필은 증거에 포함하지 않는다.

저장 계약·D 정책·데이터 이전이 필요한 경우에는 영향과 재현을 제출한 뒤 범위를 다시 정한다. 같은 오류를 두 번 시도해도 해결하지 못하면 해당 작업을 중단한다. 문제 단위는 검토 브랜치에서 독립적으로 되돌릴 수 있도록 유지한다. 병합·Pages 배포·실기기 사용은 별도 지시에 따른다. 일정은 일수 추정보다 의존 단계와 화면 판정으로 관리한다.
