# 첫 화면 검증 기록

2026-10-21. 가상 예시 여행으로 검증했다. 구현 참조는 `itinerary-concept.png`이며 사용자 승인 시안이라고 기록하지 않는다. 생성 도구는 기본 Imagegen, 최종 프롬프트는 `prompt.txt`다.

내장 브라우저(IAB)에서 실제 앱 `http://127.0.0.1:4173`을 열었다. 초기 sandbox 서버는 연결 거부/시간 초과였고, 허용된 확장 실행으로 서버를 시작한 뒤 IAB가 정상 작동했다. PC·모바일의 반복 가능한 저장 흐름 검사는 별도로 프로젝트 Playwright Chromium에서 수행했다. IAB를 포기하고 검증 성공으로 처리하지 않았다.

시안 크기 1505×1045와 동일한 PC viewport, 모바일 390×844를 확인했다. resize 직후의 이전 compositor frame은 증거로 쓰지 않고 다음 관찰에서 실제 viewport와 body 너비를 확인한 뒤 재촬영했다. `view_image`로 시안과 마지막 구현 화면을 직접 비교했다. 임시 viewport override는 복원하고 미리보기 탭은 결과로 남겼다.

| 비교 항목 | 시안 | 구현과 판단 |
|---|---|---|
| 정보 구조 | 여행 rail + 제목 + 탭 + 타임라인 + 안내 | 같은 구조 유지. 날짜·버전 선택과 변경 이유 조회는 데이터 보존 흐름에 필요한 추가 |
| 문구 | 지정한 가상 여행명·일정 3개·동일 4개 탭 | 제목·탭·일정·방문/건너뜀·주요 CTA 일치. 기간에는 종료 연도를 포함하고 실제 저장 상태 표시 |
| 색상·컨테이너 | 흰 배경, 녹색 강조, 열린 행과 얇은 경계 | 같은 토큰 사용. 타임라인을 카드 격자로 변경하지 않음. 사진·장식 이미지 추가 없음 |
| 글꼴 위계 | 한국어 sans, 제목/행/보조문구 구분 | 로컬 한국어 시스템 글꼴로 구현. UI 및 본문 크기를 명시. 생성 이미지의 글리프를 그대로 복제한 것은 아님 |
| 간격·밀도 | 넓은 rail, 단순한 날짜 제목 | rail은 224px로 줄이고 실제 날짜·버전 선택 UI를 추가. 시안 픽셀 단위 복제와는 구분되는 기능상 조정 |
| 반응형 | 모바일 단일 열 방향 | 여행 선택을 상단 가로 목록, 타임라인을 단일 열, 안내를 아래로. body 폭이 viewport를 넘지 않음 |
| 아이콘·미디어 | plus/chevron, 일부 sidebar 아이콘 | plus/chevron SVG 일치. 가져오기/백업은 텍스트 버튼으로 단순화. 래스터 중앙 에셋은 없음 |

첫 화면 문구 비교에서 핵심 여행명·탭·3개 일정·메모·CTA의 누락/변경은 없다. 날짜/계획 버전/변경 이유 제어와 빈 화면·에러·저장 알림·AI 미연결 안내는 명세에 기록한 기능상 확장이다. 시안 대비 rail 폭·일부 글자 크기·안내 위치·sidebar 아이콘은 위 표의 의도적 차이다. 픽셀 단위 동일 구현을 주장하지 않는다.

| 실제 앱 검사 | 결과 |
|---|---|
| 페이지 식별 | 제목 travel-app · 여행 계획과 기록, URL 일치 |
| 빈 화면/프레임워크 overlay | 정상 본문·일정 렌더링, overlay 없음 |
| 콘솔 | IAB 오류·경고 목록 비어 있음 |
| 상호작용 | 예시 불러오기·날짜별 일정 확인·앱 닫고 다시 열어 복원 확인 |
| 자동 사용자 흐름 | 실제 기록·정정→계획 수정→재로드→원본 보존, 두 여행 격리, 변경안 승인·충돌, 오프라인 기록·복원, 백업, SP-FR 변환 12개 통과 |
| 입력 접근성 보완 | 기존 값이 있는 메모와 실행 결과 제어에 명시적인 접근성 이름 추가. 정정 흐름 재검증 |

최종 스크린샷은 세션 visualization 폴더의 `travel-desktop.png`, `travel-mobile.png`에 저장했다. 저장소에는 QA trace·스크린샷을 추가하지 않았다. 실기기/iOS·Safari 검증은 후속이다.

## 앱 내부 AI 후속 검증

기존 녹색·흰 배경·열린 레이아웃 안에서 변경안 화면에 시작 날짜, 요청 입력, 조사 실행, 상태 재확인·중단을 추가했다. 입력·버튼·알림·근거 링크의 기존 스타일을 재사용했다. 모든 변경안 확인 적용 정책과 OpenAI 전송 범위·요금·실행 한도를 화면에 설명한다.

- 단위/HTTP 통합 26개, PC/모바일 브라우저 14개 통과. 브라우저의 AI 결과는 모의 응답으로 만들어 비용 없이 자동 초안 저장→재로드→승인 적용을 검증했다.
- 별도 가상 여행 실 API 검사에서 웹 출처 16개, operation 1개, 작성 시도 1회로 검증 통과했다. 해당 결과를 가상 여행으로 가져와 실제 근거·이전/이후·승인 대기 화면도 확인했다. 실제 사용자 예약·여행 데이터는 쓰지 않았다.
- IAB 콘솔 오류·경고 없음. PC 1504×1040·모바일 390×844에서 가로 넘침을 검사한다. 소스·동작·브라우저 모의 검증과 실제 제공자 검증은 구분한다.
- PWA 업데이트가 대기하면 편집을 강제 재로드하지 않고 안내한다. 최신 코드에는 사용자가 입력을 저장한 뒤 선택하는 '저장 후 새 버전 열기' 버튼도 추가했다. 개발 서버는 SW를 설치하지 않는다.

AI 화면의 폼·완료 상태는 기존 시안의 기능상 확장이다. 초기 일정 화면을 새로운 래스터 시안으로 재디자인하지 않았다. 본문/컨트롤 크기·탭/버튼 형태·녹색 강조·얇은 경계·모바일 단일 열을 검토했다.
