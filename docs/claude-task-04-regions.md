## 1. 기준과 기술 판단

AGENTS.md와 handoff → development-plan → product-requirements → decisions를 읽는다.
T-03 결과 §3·Codex T-03 검증·원천 `build/model.py::load_days`를 필요한 범위만 확인한다.
원천은 읽기 전용이며 사용자/기존 검토 프로필을 테스트에 재사용하지 않는다.
시작 HEAD·dirty·포트·원천/패키지 해시를 확인하고 `codex/t04-regions` 작업 브랜치에서 수행한다.
기존 같은 이름의 브랜치가 있으면 상태를 확인한다. worktree·reset·강제 push는 하지 않는다.

Codex의 구현 판단은 T-03의 **C안**이다. 원천 의미 보존을 위한 기술 선택이며 새 사용자 제품 정책으로 기록하지 않는다.

- `day.regionIds`: 원천 숙박에서 `checkin <= 날짜 <= checkout`인 지역 key. 이동일의 출발·도착과 숙박 종료일을 보존한다.
- `overnightRegionId`: `checkin <= 날짜 < checkout`인 숙박의 마지막 key, 없으면 미설정한다.
- 야간 지역을 `regionIds.length === 1`로 추정하지 않는다. 출발 지역 추가로 숙박 지역이 사라지면 안 된다.
- 원천 `return` 센티널과 종료 숙박을 야간 지역으로 쓰는 폴백은 도입하지 않는다. 없는 지역/숙박을 만들지 않는다.
- 활동 장소 지역의 임의 합집합(B안)을 사용하지 않는다. 원천의 순서·반복 숙박/지역 처리 방침을 명시한다.

## 2. 변경 범위

`src/transfer/spfr-candidate.ts`, `spfr-pilot.ts` 및 필요 최소 공통 helper·관련 가상 검사/fixture,
검토 패키지 생성/독립 대조 도구와 계약 설명 문서가 대상이다. 기존 repository 저장·revision 계약은 유지한다.
새 의존성·server·workflow·공개 샘플·사용자 DB 자동 변환은 범위 밖이다.

1. 지역/숙박 계산을 명시적인 원천 값에서 분리한다. 코드·스키마 전체 리팩터링이나 포맷 변경을 섞지 않는다.
2. 기존 T-01의 미확정 관찰/todo와 숙박 종료일 `regionIds=[]` 기대값을 새 기술 기준에 맞게 정리한다.
   변경 이유를 assertion별로 기록하고 무관한 기대값·보존 검사를 완화하지 않는다.
3. `tests/spfr-reg01-source-model.test.ts`의 실패 재현을 정상 CI에서 실행되는 회귀로 전환한다.
   환경변수 gate로 수정 검사를 계속 숨기지 않는다. 일반 검사에서 실제 원천 파일을 읽어서는 안 된다.
4. 어댑터/정규화 식별의 현재 용도를 먼저 조사하고 변경 산출물을 식별할 최소 버전 정책을 정한다.
   새 변환이 기존 어댑터와 같은 의미라고 표기하지 않는다. 파일/명령 계약 v2를 무조건 올리거나 구 패키지를 거부하지 않는다.
5. `content-db-mapping.md`의 두 필드 의미와 decisions의 작성자 기술 판단을 갱신한다.

## 3. 필수 회귀·호환

- 이동일의 두 지역·야간 도착 지역, 종료일의 종료 지역·야간 미설정, 숙박이 전혀 없는 날을 각각 확인한다.
- 같은 날짜 checkout/checkin·다중 숙박/반복 지역·잘못된/누락된 숙박 값은 기존 입력 계약에 따라 명확히 처리한다.
- ZIP 생성/읽기·새 빈 검증 DB 조회·백업/복원 후 의미가 유지되는지 가상 사례로 확인한다.
- 구 버전 패키지 읽기/가져오기를 유지하고 기존 DB/불변 과거 계획을 자동 수정하지 않는다.
- 새 원천 재가져오기는 계획 차이 검토를 거치며, 앱에서 계획/현장 기록이 바뀌었으면 기존 충돌/보존 규칙을 따른다.
  무확인 적용을 만들지 않는다. 사용자 계획 편집과 새 지역 변경이 함께 있을 때를 가상 검사한다.

## 4. 실제 43일 사본의 확인

기존 verified ZIP·원본·지역 ZIP·백업은 덮어쓰지 않는다. 새 Git 제외 폴더에 통합 검토 후보를 생성한다.
생성 경로·크기·해시·어댑터 식별자를 기록한다. 실제 자료를 공개 fixture/문서/릴리스에 넣지 않는다.

- 원천에서 독립적으로 계산한 하루 지역과 새 후보를 대조한다. 기대값을 새 변환 helper로 만들지 않는다.
- T-03의 영향9일(이동8일·종료1일)을 재확인한다. 다른 차이가 있으면 숨기지 말고 원인을 분류한다.
- 기존 후보와 비교해 활동/이동/숙박·콘텐츠·첨부 바이트·현장 상태·과거 맥락이 불필요하게 바뀌지 않았는지 검사한다.
  어댑터/manifest·해시·대응표 등 예상 메타 변경은 따로 설명한다.
- 읽기 검증 도구의 구 버전 의미와 새 의미를 구분하고, 새 REG-01 검증이 실패하면 비정상 종료하게 한다.
  구 패키지를 새 의미로 조용히 재해석하지 않는다. 출력 경로/실패 신호 보호 검사도 유지한다.
- 후보는 검토용이다. 사용자 프로필/iPhone에 가져오거나 기존 여행을 재가져오기하지 않는다.
