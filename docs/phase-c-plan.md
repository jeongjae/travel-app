# C단계 개발계획 · 별도 여행의 작성·현장 기록·회고

2026-10-30 · 개정 R3: Codex · 초안: Claude(10/28) · **C-02〔T-C3.2〕주요 검토 통과 / C-03〔T-C4〕전달 준비 / 사용자 미확인**

[설계서](phase-c-design.md)를 구현·검증 가능한 단위로 나눈다. [실행계획](development-plan.md)·[요구](product-requirements.md)·[결정](decisions.md)이 상위 기준이다.
역할은 Codex 계획/검토·Claude Sonnet 구현/자체 검사·사용자 실제 확인이다. 이번 R1 문서는 사용자 요청에 따라 Codex가 직접 보완했다.

현재 제출의 [Codex 검토](claude-task-c01-review.md): T-C1/T-C2/T-C3.1은 소유 관계 R1 보완 후 독립 검토 통과했다. 사용자 검토 준비이며 C 전체 완료로 확대하지 않는다. [C-02〔T-C3.2〕](claude-task-c02-review.md)도 주요 기능 검토 통과했다. CL-05는 잘못된 추론을 정정하고 역전 검증을 보강했으며 DST 경계 오탐은 CL-08에 남겼다. 다음 [C-03〔T-C4〕](claude-task-c03-guides.md)는 가이드와 CL-06 기본정보 편집이며 전달 준비·구현 미착수다.

## 1. 착수와 범위

- 10/29 사용자 요청에 따라 경미한 잔여를 [후속 목록](change-log.md)에 기록하고 C 작성 흐름을 우선한다. B 이행 마감은 C 착수 선행 조건에서 분리하되 G2/G2′ 미완료 상태는 유지한다.
- 첫 지시는 [C-01](claude-task-c01-authoring.md): T-C1→T-C2→T-C3.1을 하나의 검토 가능한 작성 흐름으로 묶는다. 세부 기능 커밋은 분리한다.
- T-05는 독립 검토 통과했다. T-06/F-2·F-3은 보류하고 B 확인·운영 관문은 후속 목록에서 추적한다. 저장/복원·충돌·격리·보안 결함은 보류 대상이 아니다.
- 지역 필수화·물리 삭제·새 예약/할 일·기간/날짜 삭제·사진/지출·전체 본문 검색·수동 ZIP·AI 콘텐츠 제안은 기본 C 밖이다.
- 같은 체크아웃의 다른 작업과 문서/구현을 동시에 수정하지 않는다. 대상 파일·커밋을 고정하고 서로의 작업물을 임의 포함하지 않는다.

## 4. 계약·검사 체크포인트

### 콘텐츠 생성

- 설계 §4의 가상 계약 예시를 실행 가능한 fixture로 전환한다. 기존 fixture를 재사용하고 실자료를 공개 테스트에 넣지 않는다.
- 신규 장소/guide의 상호 참조를 같은 트랜잭션에 반영하고 기존 소유자 revision을 검사한다.
- 필수 섹션 누락·잘못된 owner·다른 여행 참조·중복 ID·중간 쓰기 실패에서 전체 상태와 receipt가 보존돼야 한다.
- 같은 requestId/입력 replay, 다른 입력 재사용 오류, 정상 저장 후 정확히 한 번의 여행 revision 증가를 검증한다.

### 계획·실제·시간

- 현재 계획 ID가 같아도 다른 탭의 현장 기록으로 domainRevision이 증가하면 오래된 저장을 거부한다.
- item 제거와 leg 참조, 숙박 갱신과 날짜 지역 계산은 하나의 계획 변경 안에서 검증한다. 과거 버전은 변경하지 않는다.
- 잘못된 달력 날짜·미확인 시간대·DST 모호성·0박·이동일·겹친 밤·숙박 미상 예제를 별도 기대값으로 검사한다.
- 수동 규칙을 추가해도 기존 SP-FR v2/v3 읽기·원천 지역 모델·출처가 재해석되지 않음을 확인한다.

### 재조회·복원

- 모든 작성·기록 흐름에 저장→다른 화면에서 찾기→열어 읽기→재실행/오프라인 재로드를 포함한다.
- 두 여행은 같은 공간에 공존시키고 본문/계획/기록/출처/첨부의 격리를 확인한다.
- 백업/복원은 별도 빈 review 공간만 사용한다. 사용자 DB 초기화·재가져오기로 결함을 숨기지 않는다.
- T-05 이후 재가져오기에서 저장 순서 차이는 오탐하지 않으면서 실제 app-only·원천 변경·충돌·보류는 보존한다.

## 5. 검증·제출·사용자 확인

Sonnet은 지정 단위를 조사→구현→대상 검사→필요한 전체 검사→증거 정리→커밋/push까지 자율 수행한다.
중간 단계별 질문은 미결정 정책·비용/외부 영향이 필요한 경우로 한정한다. 요약은 20줄/2,000자 이내와 증거 색인으로 제출한다.

- 의미 있는 구현 후 `pnpm run check`, UI/저장 흐름 변경 시 build·`pnpm run test:e2e`를 실행한다.
  단위 최종 검증은 `check:deferred`로 묶을 수 있다. 같은 코드에서 이미 포함된 검사를 중복 실행하지 않는다.
- Codex는 제출 커밋을 고정하고 요약→실패/범위→저장/보존·보안·충돌 diff→필요한 독립 검사 순서로 검토한다.
- 코드/검사와 계획·결과 문서는 분리 커밋한다. 공개 앱 배포·사용자 사본 적용·유료 API는 별도 범위다.
- 각 보고서 사용자 상태는 `검토 준비 / 확인 대기 / 수정 요청 / 확인 완료` 중 하나다. 무응답·보고서·테스트 통과를 사용자 확인으로 바꾸지 않는다.
- 10/23 연속 구현·후속 일괄 확인 허용은 유지한다. 기존 범위 안의 의존 작업은 자동 검사를 거쳐 이어갈 수 있으나,
  미확인 산출물을 완료 처리하거나 미결정 정책을 새 기본값으로 확정하지 않는다. 화면 선택이 필요한 작업은 시제품 확인 후 진행한다.
