# C단계 개발계획 · 별도 여행의 작성·현장 기록·회고

2026-10-28 · 상태: **제안(사용자 미확정)** · 작성: Codex 역할(검토 실행: Claude 세션) · 설계 근거: [C단계 설계서](phase-c-design.md) · 상위 계획: [실행계획](development-plan.md) §6

이 문서는 C단계를 Claude Sonnet이 구현할 수 있는 작은 단위로 나누고, 각 단위의 의존·검증·Codex 검토·사용자 확인 관문을 정한다. 기간·커밋 수는 약속하지 않는다. 역할과 제출 형식은 실행계획 §2·§3을 따른다.

## 4. 검증 방식

- **가상 fixture**: 기존 T-01 fixture 경로를 재사용한다. 실제 날짜·예약·본문을 공개 fixture에 넣지 않는다.
- **4단계 E2E 패턴**: 모든 작성·기록 기능은 "저장 → 다른 화면에서 찾기 → 다시 열어 읽기 → 앱 재실행(또는 오프라인 재로드) 후 읽기"를 한 테스트로 묶는다. DB 행 존재만 단언하는 검사를 완료 증거로 쓰지 않는다.
- **SP-FR 사본과 공존 검사**: 새 여행 검사는 항상 SP-FR 가상 여행(또는 local-data 사본)이 같은 공간에 있는 상태에서 실행하고 전환·누출을 단언한다.
- **독립 계산**: 하루/야간 지역·계획 버전 번호·정정 체인은 변환 함수가 아닌 별도 기대값으로 검사한다.
- **전체 회귀**: 각 단위 종료 시 `pnpm run check:deferred`(check·E2E·pilot). 중간 하위 단위는 대상 검사만.
- **Codex 독립 검사**: 제출 커밋 고정 → 요약 → 범위 이탈/실패 → 위험 diff(저장 계약·revision·격리) → 필요한 검사만 재실행.
