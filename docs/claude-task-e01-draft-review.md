## 사용자 결정과 착수 순서

1. E1 범위를 확정한다. M-1은 이동을 일정 표로 받고 `## 이동`이 오면 미리보기에 제외 사유를 표시한다. M-2는 E1에서 장소 이름을 활동 메모에 남기고 장소 생성은 E2에서 다룬다. 위 표의 숙소 지역·예약 원문 처리도 함께 확인한다.
2. E2로 이어지는 규격 가정 3건을 확인한다. 내보내기 파일에 수정 규칙 포함, 변경 없는 줄 별도 표시, 기존 여행 수정 파일의 이름 줄 무시다. E1 붙여넣기·요청서 UX도 같은 확인에서 확정한다.
3. 확정한 내용으로 규격과 지시서를 맞춘 뒤 Claude Code에 C1을 전달한다. C1 제출물은 두 T1 파일의 새 여행 변환, 네 T2/T3 파일의 수정용 해석, 두 1회차 파일의 거부 근거, 위 표의 C1 사례다. C1 확인 뒤 C2~C4, Codex 독립 검토, PC·iPhone 사용자 확인 순으로 진행한다.
4. 목적지 가이드 P0와 G-1·G-2는 가이드 작업 결정으로 관리한다. UI-01은 별도 승인 시 [UI 작업 지시서](https://github.com/jeongjae/travel-app/blob/13ec6442e3e812fc01a8d41ba2644539b1fc9a4f/docs/claude-task-ui01-day-retro.md)의 화면 범위와 최신 제품 기준을 대조한다.

## D 종료 후 발견한 호환성 항목

개발용 Node 서버에 D1 이전 형식인 `result: { proposal, evidence }`의 가상 작업 파일을 넣고 `AiV2Jobs.init()`을 실행했다. 디스크에서 `result`가 제거되면서 상태는 `awaiting-decision`으로 남았다. 이 동작은 `src/ai-v2-jobs-core.ts`가 `output`과 `scope` 또는 `planning`이 있는 형식만 보존하고 `server/ai-v2-jobs.ts`가 초기화 중 파일을 다시 쓰기 때문에 발생한다. 실제 사용자의 파일과 운영 Worker는 검사하지 않았다. 재현 범위는 개발용 Node의 구형 작업 파일이며, D 종료 판정은 기존 기록대로 유지한다. Node 서버 정리 때 이 파일의 읽기·만료·폐기 처리를 명시하고, 기존 여행 DB의 제안과는 별도로 검증한다. T-E1의 작업 범위에는 포함하지 않는다.
