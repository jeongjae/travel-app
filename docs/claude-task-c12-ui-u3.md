## 1. 바꾸지 않는 것

## 2. 범위

### C5 실제 기록 목록 (`Field.tsx`)
1. **날짜별 묶음.** 현재 세 그룹(`확인된 발생 시점`·`날짜·현지 시각·원문`·`발생일 미상`)을 **날짜 머리(예: `12월 31일 (목)`) 아래 시각 순**으로 바꾼다. 발생일 미상만 맨 아래 별도 묶음. 정밀도 용어(`원문`·`미상`)는 각 행의 작은 보조 문구로.
2. **정정 체인 접기.** 같은 체인은 **최신 정정본 1행**만 보이고 `정정 2회 · 원문 보기` 접기로 원문·중간본을 편다. 현재 `정정 1/3단계 · 이후 정정본 있음` 식 문구는 접기 안으로. 정정 버튼은 최신본에만(현행 유지).
3. 행 형식: 제목 → 결과·시각(한 줄) → 메모 → 작은 보조(기록 당시 계획·정정 여부). `기록 당시 내용`·`앱에 남긴 시각`은 `⋯` 또는 접기.
4. 상단 버튼은 U1·C-11 상태 유지(`날짜별 회고 보기` 기본 버튼, `예정 외 활동 기록`, `여행 메모 쓰기`).

### C6 날짜별 회고 (`Retrospective.tsx`, 필요 시 `retro-rules.ts` 출력 추가)
1. **버전 이름(CL-19).** `과거 계획 13 · 근교 당일치기 이동(가상)` → `11/02 14:30 · 근교 당일치기 이동(가상)`(저장 시각 + 이유, 번호는 보조). 선택 상자와 열 머리 모두. `현재 계획 15` → `현재 계획 (11/03 09:10)`.
2. **변경 표시.** 두 열(선택 계획 / 현재 계획) 비교에서 항목별 `추가`·`제거`·`이동(날짜)`·`시각 변경` 배지. 같은 항목은 배지 없음. 계산은 `retro-rules.ts`에 순수 함수로 추가하고 단위 시험을 둔다.
3. **CL-14 날짜 변화 판정.** `dayChange`가 활동만 비교해 날짜 제목·숙박·이동 변경을 놓친다. 판정에 숙박·이동·날짜 메타를 포함하거나, 문구를 "이 날짜의 **활동**은 직전 버전과 같습니다"로 한정한다. 둘 중 전자를 권장하며, 재현 검사 `.cache/c05-codex/day-change-label-repro.test.ts`(Codex 보관)를 정식 시험으로 옮긴다.
4. **설명문 정리.** `읽기 전용입니다. 날짜와 계획 버전을 바꿔도…`, `아래 이유는 계획 전체에 대한 것이며…`, `변경안 없음 · 직접 변경 등으로…`는 각각 한 줄 도움말(ⓘ 접기)로. 본문에는 사실만 남긴다.
5. 모바일: 두 열을 세로로 쌓되 열 머리를 고정(`position: sticky`)해 어느 계획을 보는지 잃지 않게.

### C7 가이드 화면 (`ContentApp.tsx` 가이드 탭, `Guide.tsx`)
1. **지역별 묶음.** 카드 격자 대신 `지역 머리(이름·설명 한 줄·지역 가이드 N개) → 소속 장소 목록 → 지역 없는 장소`. 지역 머리를 누르면 지역 상세(가이드 작성 포함).
2. **진입 버튼.** `지역 작성`·`장소 작성`은 상단 유지하되 보조 버튼으로. `지역 가이드 작성`은 지역 머리 안에서만.
3. **검색.** `이름·지역 검색`은 지역 묶음을 필터링(일치하는 장소가 있는 지역만 남김). 결과 0이면 "일치하는 장소가 없습니다 · 검색어 지우기".
4. 장소 상세의 섹션(한 줄 요약·왜 가는가·실용 정보·사진 등)은 현행 유지.

### D2 데스크톱 폭 (검토만)
본문 폭 약 600px 고정을 `오늘`·`기록`·`회고`에서 **최대 880px**로 넓히는 것만 시험한다(2열 배치는 E-3 지도 결정 뒤). 가독성이 나빠지면 되돌리고 이유를 적는다.
