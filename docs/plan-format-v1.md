# travel-app 여행계획 양식 v1 (`travel-app-plan/1`) 규격

2026-11-13 · 작성: Codex 역할 세션 · 상태: **초안 v1-draft2 / 사용자 추가 개선 제안 대기**
근거: [설계서 v0.3](ai-rework-requirements-design.md) §4.2·§4.3·§8.1 · [결정 11/13 16:49](decisions.md) · [E0 시험](e0-chatbot-trial.md)(2회차 6/6 통과)
쓰임: 변환기 구현(E1~E2)의 기준 문서. 챗봇에게 주는 글은 [안내문](plan-format-v1-prompt.md), 내보내기 모습은 [예시](examples/plan-export-sapporo.md).

**가정 표시**: `[가정]`은 Codex 제안으로 쓴 것이며 사용자 확인 전이다(M-1·M-2·보완 1~3, [결정 11/13 17:45](decisions.md)의 대기 항목). 사용자가 바꾸면 이 문서와 지시서를 고친다.

## 1. 파일 전체

- 글자 인코딩 UTF-8, 확장자 `.md`. 줄 끝은 LF·CRLF 모두 읽는다. 상한: 200,000자·3,000줄 `[가정]`.
- **표만 읽는다.** 표 밖의 글(설명 문장, 인용 글 `> `, 코드 블록 표시)은 읽지 않는다.
- 파일 전체가 ```` ```markdown ```` 코드 블록으로 싸여 있으면 블록 안을 읽는다(챗봇 출력을 그대로 저장한 경우).

## 2. 머리 줄

| 줄 | 필수 | 형식 | 비고 |
|---|---|---|---|
| `# 여행: 이름` | 새 여행 파일에 필수 | 첫 번째 `# ` 줄 | 여행ID가 있는 파일에서는 **읽지 않는다** `[가정: 보완 3]` |
| `- 양식: travel-app-plan/1` | **필수** | 글자 그대로 | 없거나 다른 값이면 가져오기 거부 |
| `- 기간: YYYY-MM-DD ~ YYYY-MM-DD` | 새 여행 파일에 필수 | 시작 ≤ 끝 | 기존 여행 파일에서는 현재 기간과 다르면 경고만(기간 변경은 앱 화면에서) `[가정]` |
| `- 시간대: IANA 이름` | 선택 | 예: `Asia/Tokyo` | 없으면 "시간대 미확인". 잘못된 이름은 오류 |
| `- 여행ID: <내부 ID>` | 내보내기 파일만 | 내부 ID 그대로 | 아래 두 줄과 함께 셋 다 있거나 셋 다 없어야 한다 |
| `- 기준계획: <계획 버전 ID>` | 내보내기 파일만 | 내부 ID 그대로 | |
| `- 기준revision: <정수>` | 내보내기 파일만 | 0 이상 정수 | |

- 모르는 머리 줄(`- 범위: …` 등)은 읽지 않고 경고로 보여 준다.
- 여행ID 3줄이 **없으면 새 여행 파일**, **있으면 기존 여행 수정 파일**이다.

## 3. 구역과 열

구역 이름과 열 이름은 글자 그대로다. 열은 **이름으로** 읽고 순서에 의존하지 않는다. 필수 열이 빠진 표는 오류다.

| 구역 | 열(필수는 굵게) | 내부 대응 |
|---|---|---|
| `## 일정` → `### YYYY-MM-DD 그날 제목` 아래 표 | **ID · 시간 · 제목 · 종류** · 장소 · 메모 · 예약 · 링크 | 활동(`planItem`): 제목→`title`, 종류→`category`, 메모→`summary`, 예약→`reservationText`, 링크→`officialUrl`, 장소→§5 |
| `## 숙소` | **ID · 체크인 · 체크아웃 · 이름** · 지역 · 예약 | 숙박(`planStay`) |
| `## 장소` | **ID · 이름** · 지역 · 설명 · 영업시간 · 링크 | 장소 콘텐츠(`place`) |
| `## 삭제` | **종류 · ID** · 제목 | 삭제 요청 |
| `## 이동` | — | **v1에서는 가져오지 않는다** `[가정: M-1]`. 구역이 있으면 "가져오지 않음" 경고와 함께 줄 수를 보여 준다. 이동은 일정 표의 `이동` 종류 줄로 적는다 |

- 날짜 제목 줄: `### ` 뒤 첫 낱말이 날짜다. 나머지는 그날 제목(요일 등 자유). 끝에 `(시간대: IANA 이름)`을 붙이면 그날만 그 시간대로 본다.
- 모르는 구역·모르는 열은 읽지 않고 "가져오지 않음" 경고로 보여 준다.

## 4. 칸 규칙

| 항목 | 규칙 |
|---|---|
| 한 줄 = 한 항목 | 칸 안 줄바꿈 금지. 칸 안의 `|`는 `\|`. 앞뒤 공백은 버린다 |
| 열 개수 | 제목 줄과 다르면 그 줄은 오류이고, **그 표 전체**를 적용에서 뺀다(일정은 날짜별 표 단위) |
| ID | 비어 있으면 새 항목. 값이 있으면 기존 항목(형식: 영문·숫자로 시작, 영문·숫자·`._:-`, 최대 160자). 새 여행 파일에 ID가 있으면 오류 |
| 빈 칸 | 새 줄: 값 없음. **ID 있는 줄: 변경 없음** |
| `(비움)` | ID 있는 줄에서만 뜻이 있다: 그 칸의 값을 지운다. 필수 값(제목·종류·이름·체크인·체크아웃)에는 쓸 수 없다(오류). 글자 그대로의 값은 `\(비움)` |
| 시간 | 빈 칸 · `HH:MM` · `HH:MM-HH:MM` · `HH:MM-HH:MM(+1)`만. 24시간제. 그 밖은 오류 |
| 시간 검사 | 시작 = 끝(길이 0) **거부**. `(+1)` 없이 끝 < 시작(역전) **거부**. 길이 12시간 초과 거부(기존 결정). 같은 날 겹침은 **경고** |
| 종류 | 권장: 관광·식사·이동·숙박·쇼핑·기타. 다른 값도 그대로 저장 |
| 링크 | `https://`로 시작하는 주소 하나, 공백 없음. 아니면 오류 |
| 날짜 | `YYYY-MM-DD`, 실제 있는 날짜. 여행 기간 밖이면 오류 |
| 숙소 | 체크아웃 > 체크인. 둘 다 여행 기간(끝 날짜 포함) 안 |
| 삭제 | 종류는 `활동`·`숙소`만 `[가정: M-1로 이동 제외]`. 장소·그 밖은 오류. 종류와 ID가 가리키는 항목이 맞지 않으면 오류 |
| 순서 | 표의 줄 순서가 그날 활동 순서다(시간 미정 항목 포함) |

## 5. 일정의 장소 칸 `[가정: M-2]`

1. 값이 장소 표(이 파일) 또는 기존 장소의 이름과 **정확히 같으면** 그 장소에 연결한다.
2. 같지 않으면 "이름만 있는 새 장소" 후보다. 사용자가 고른 것만 장소 단계에서 만든다.
3. 고르지 않았거나 장소 단계가 없는 경우(E1) 값은 버리지 않고 메모 앞에 `[장소: 값]`으로 남긴다.

## 6. 내보내기 파일 `[가정: 보완 1]`

- 머리 줄 7개, 그 아래 인용 글로 "이 파일을 고치는 규칙" 6줄([예시](examples/plan-export-sapporo.md)와 같은 문장), 구역 표(모든 줄에 ID), 끝에 빈 `## 삭제` 표.
- 예약 메모·현장 기록은 기본으로 넣지 않는다(결정 6). 예약 칸은 사용자가 고를 때만 채운다.
- 왕복: 내보낸 파일을 그대로 다시 가져오면 변경 0건이어야 한다.

## 7. 가져오기 결과의 분류 (미리보기가 보여 줄 것)

| 분류 | 뜻 |
|---|---|
| 추가 | ID 없는 줄. 기존 항목과 날짜·제목이 같으면 기본 "건너뜀" |
| 수정 | ID 있는 줄에서 바뀌는 칸이 1개 이상. 지워지는 값은 따로 표시 |
| 변경 없음 | ID는 있는데 바뀌는 칸이 없다 `[가정: 보완 2]` |
| 삭제 | `## 삭제`의 줄. 제목·개수 확인 |
| 오류 | 적용에서 빠진 표와 줄 번호·이유 |
| 가져오지 않음 | 모르는 구역·열·머리 줄, `## 이동` |
