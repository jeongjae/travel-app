# P-05 중간보고: 현장 기록·변경안·재가져오기

2026-10-22 · P-05 범위 구현·검증 완료

## 구현

- 미상/날짜/원문/local/instant의 발생 시각을 가진 방문/건너뜀/예정 외 실제 기록, 원본을 남기는 정정, 메모와 의미 fingerprint에 연결된 작업 완료·예약 상태 수정 UI를 repository 명령으로 연결했다.
- 수동 계획 편집/제거는 새 불변 계획을 만들고 실제 기록과 과거 콘텐츠/context를 보존한다. 정확한 instant 입력은 확인된 오프셋을 요구하고 DST 결손/불일치를 거부한다.
- 모의 변경안 생성→별도 초안 저장→이유/예약 영향/이전·이후 검토→명시적 적용/거절을 구현했다. 최신 domain/proposal revision과 pending을 저장 트랜잭션에서 다시 검사한다. 동일 요청 replay는 기존 결과를 반환한다.
- 원본 계보별 불변 기준 B와 현재 mapping head를 저장한다. B/L/R의 콘텐츠 필드·가이드 안정 section key·계획/여행 메타 차이를 검토하고 원본만/앱만/양쪽/같은 값/원본 제거를 구분한다.
- 선택한 원본 값만 콘텐츠/새 계획/기준 B/패키지/결과 receipt와 함께 원자 저장한다. 앱 유지·보류는 B를 유지하고 원본 제거는 비활성화한다. 실제 기록/메모/작업 상태를 원본 상태로 다시 덮어쓰지 않는다.

## 자율 선택·근거

| 항목 | 실행한 방안 |
|---|---|
| 모의 AI | P-05는 모의 변경안으로 승인 저장 경계를 검증한다. 유료 API 호출·자동 조사 완료로 보고하지 않는다. 기존 v1의 AI 실행 경로는 보존한다. |
| B/L/R 추천값 | 원본만 수정/양쪽 같은 값은 원본 반영, 앱만 수정은 앱 유지, 양쪽 다른 수정은 보류를 추천한다. 제품 안에서는 모든 선택을 보여 주고 최종 적용 버튼으로 확인한다. 구현 위임을 실제 여행의 무확인 자동 승인으로 확대하지 않는다. |
| 삭제·새 콘텐츠 | 삭제는 head 비활성화로 과거 내용을 보존한다. 새 콘텐츠/연결의 적용 결과가 완전한 참조를 만족하지 않으면 전체 저장을 취소한다. |
| 대응 키 변경 | 같은 원천 키의 대상 ID/kind가 바뀌면 자동 병합하지 않고 오류로 남긴다. 이름·목록 순서로 새 대응을 추정하지 않는다. |
| 계획 재가져오기 | 계획 자체는 한 검토 단위로 처리하고 승인 시 새 버전을 만든다. 가이드 섹션은 안정 key별로 선택해 다른 섹션의 앱 수정을 보존한다. |

- 신규 B/L/R 통합 검사 **5개 통과**: 원본/앱/양쪽 수정 분류와 보류 B/실제 보존, L=R 기준 갱신, 원본 제거·과거 콘텐츠 보존, 오래된 검토 거부, 계획 새 버전과 주입 실패 시 B/도메인/영수증 원자 취소.
- P-02의 두 연결 충돌·정정·초안 승인/거절·정확 replay 검사도 전체 **94개** 검사에서 재통과했다. 실제 저장 영수증을 공유 receiptSchema로 검사하고, v1 승인/실제/원문·미확인 근거 보존도 확인했다.
- 최종 E2E **26/26 통과**(PC 13, 모바일 13). 오프라인 재실행·미상 기록/정정·계획 제거 후 실제 보존·초안의 재로드/확인 적용·다중 탭 충돌/입력 보존·B/L/R의 섹션 선택 적용·예약/작업/메모·기존 데이터 전환을 확인했다.
