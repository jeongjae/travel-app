# 대표 구간 이행·검증 계획

작성일: 2026-10-21 · 상태: 실행 전 검토안 v0.1

> 실행 갱신(2026-10-22): P-01~P-06의 대표 가상 구현·검증 완료. [단계별 인계](handoff.md), [P-06 검증](p06-report.md)을 참조한다. [P-07](p07-report.md)은 고정 실제 원천 추출·공유 v2 후보 검증까지 진행했고, [P-08](p08-report.md)은 잠정 판정이다. pnpm 전환 후 check 110/E2E 30을 통과했으며 실제 원천 전체 대응·실기기 판정은 남아 있다. 아래는 원래 계획과 판정 조건이다.

## 1. 목표와 범위

**기존 파일·코드 콘텐츠가 구조화된 DB 데이터가 되고, 같은 프로그램에서 조회·편집·현장 기록·백업·복원까지 이어지는 작은 전체 흐름**을 먼저 검증한다. [저장·교환 계약](storage-and-exchange-contracts.md), [원천·DB·화면 대응](content-db-mapping.md), [기술 선정안](technology-selection.md)을 구현 가능한 순서로 묶는다.

이번 문서는 구현·실제 이행·실행 테스트가 아니다. 전체 SP-FR 이행과 최종 AI 기능 달성을 선언하지 않는다. 기존 프로토타입은 재사용 후보이며 새 범위의 통과 증거로 삼지 않는다. 기존 원본은 읽기 전용이고 실제 여행 패키지·예약·미디어·백업은 커밋하지 않는다.

|---|---|---|

| F-02 | 가상 여행 B · 1일·다른 언어 | 별도 일정/문서·같은 원천 slug의 장소 사본. 여행 길이·언어·필드 값이 달라도 같은 빌드·UI로 처리, 여행 A 편집이 B에 전파되지 않음 |

가상 표본에는 실제 예약·개인 데이터·원본 사진을 복제하지 않는다. 테스트용 이미지·PDF는 작고 출처가 명확한 가상 자산을 만든다. 실제 원천 F-03은 로컬 무시 경로에서만 다루며 저장소에는 코드·가상 fixtures·비식별 검증 집계만 남긴다.

F-03의 원천 기준은 기존 조사 commit `35498adc6413dad45922f2dab87781afeb04d898`이다. 실행 전에 원본 commit·파일 해시를 다시 확인한다. main을 무조건 따라가거나 원본 빌드를 실행하지 않는다. 파일별 전수 manifest가 없으므로 현재 문서의 일수/장소 수를 실제 적재 실측이라고 해석하지 않는다.

## 3. 구현 순서와 종료 조건

| 단계 | 작업 단위 | 완료 시 남길 증거·다음 단계 조건 |
|---|---|---|
| P-01 | 계약·가상 표본과 프로젝트 의존성 준비 | 공유 TS schema/TimeSpec/참조 규칙, F-01/02/04, 새 npm 버전/lockfile·전용 Python 환경. 외부 AI·공개 서버 없이 실행 가능 |
| P-02 | 새 물리 저장소·조회·명령 | store·키/인덱스, 현재/과거 root 조회, revision/receipt 트랜잭션, 부분 실패/정정/여행 격리. 기존 v1 보호·변환/전환 경로 |
| P-03 | 읽기 전용 추출→정규화→패키지 | Python AST/XLSX 표본, TS 정규화·manifest·ID 대응·미해결 보고, 첨부 해시. 원본 해시 불변,원본 모듈 실행 없음 |
| P-04 | 앱 미리보기→DB→공통 조회/편집 | 지역·장소 본문·Fact·예약/작업·지도 링크·일정/이동·언어 자료. 본문 저장이 계획/실제를 바꾸지 않음. A/B 전환에 코드 수정·재빌드 없음 |
| P-05 | 현장 기록·변경안·재가져오기 | 오프라인 기록/정정, 계획 변경 후 기록 유지, B/L/R 검토·승인·거절, 오래된 변경안·두 탭 충돌·중복 요청. AI 연동은 모의 변경안으로 저장 경계부터 검증 |
| P-06 | 첨부·오프라인·전체 백업/복원 | 필요한 바이트 확인, 누락/공간 부족/중단 처리, 편집 중 일관된 백업, 빈 저장소 복원·영수증 replay, 활성화 전 실패 비노출 |
| P-07 | 실제 대표 원천·휴대폰 대조 | F-03의 원문/행/관계/첨부·표시 대조, iOS Safari/Android Chrome 후보와 사용자 실기기, 성능/용량/파일 보관 흐름 실측 |
| P-08 | 대표 구간 판정·전체 이행 계획 갱신 | 아래 R 기준 결과·미해결·한도 조정·원본 확대 범위·공통 규칙 변경을 기록. 통과한 표본만 근거로 전체 이행 착수 범위를 정함 |

순서는 의존 관계다. 각 단계에서 필요한 검사를 수행하고, 통과한 검사를 이유 없이 반복하지 않는다. UI/저장 변경은 `npm run check`와 `npm run test:e2e`를 수행한다. Python 도구는 리터럴·XLSX 원천 경로·수식/미지원 표현 처리를 검증한다. 공개 배포·유료 AI 호출·실제 예약 실행은 이 대표 이행의 선행 조건이 아니다.

## 5. 성능·용량과 미정 운영 결정

초기 측정 목표안은 대표 여행에서 목록/하루 열기 1초, 본문 열기 2초, 일반 본문/현장 기록 저장 1초 이내다. 목표 휴대폰의 온라인 최초 로드와 오프라인 재시작을 구분해 여러 번 측정하고 실제 분포·첨부 크기를 기록한다. 이 수치는 아직 실측·사용자 합의가 아니다.

전체 백업/복원은 시간을 임의 보장하지 않고 전체 바이트·행 수·최대 첨부·처리 시간·최대 메모리와 취소/실패 보존을 측정한다. 대표 데이터보다 큰 자료도 기술 한도 내에서 시험한다. 모의 저장소 공간 오류 검사와 실제 기기의 브라우저 용량 검사는 구분한다. 파일이 생성돼도 사용자가 다른 위치에 보관·재선택할 수 있는지 확인한다.

지원 실기기/브라우저의 구체 버전·실제 원천 규모·백업 분할 필요성은 P-07 전에 정한다. 호스팅/AI 서버 인증·휴대폰 HTTPS 경로는 후속 운영 결정이다. 오프라인 조회·기록·백업 검증을 서버 결정 때문에 미루지 않는다.

## 6. 실행 기록과 대표 구간 완료 판정

실행 시 단계별로 코드/패키지 버전, 원본 commit/manifest digest, 가상·실제 자료 구분, 장치/브라우저·측정값, R별 통과/실패/미검증, 미해결 sourceKey와 손실 여부를 남긴다. 실제 여행 원문·예약 값·백업 파일은 기록 저장소에 복제하지 않는다. 상세 로컬 보고서는 무시 경로, 비식별 요약과 미검증 외부 연동은 `docs/handoff.md`에 기록한다.

대표 구간 완료는 R-01~09의 해당 검증을 통과하고 미해결 중단 조건이 없을 때다. 실제 표본의 필수 본문/코드 콘텐츠·참조·첨부·기록 보존 실패나 휴대폰 복구 실패가 남으면 다음 원천으로 범위를 확대하지 않는다. 검토 후 제외한 항목은 근거와 제외 권한을 명시한다. 표본 통과만으로 SP-FR 전체 이행·최종 제품 완료·공개 운영 준비 완료라고 보고하지 않는다.

현재 상태: **P-01~P-06 대표 가상 구현 완료, P-07 실제 추출·공유 v2 후보 검증, P-08 잠정 판정**. 다음은 실제 F-03의 남은 필드/XLSX/첨부·표시 대응과 격리 DB/UI·휴대폰 검증이다. [최신 R 기준 판정](p08-report.md)과 [기존 구간 증거](p02-p05-verification.md)를 따른다. 실제 SP-FR 전체 이행·실기기·최종 AI·공개 운영 완료로 확대 해석하지 않는다.
