## 1. 의뢰를 받은 뒤 사용할 기준

1. [현재 인계](handoff.md), [D 개발계획](phase-d-plan.md), D 최종 결과·Codex 검토, [C-15 결과](claude-task-c15-result.md), [U4 사용자 대본](u4-sapporo-scenario.md)을 읽는다. D 종료 후 인계된 제품 SHA, 실제 작업 브랜치, 설계 문서 버전을 기록한다. 설계 브랜치는 문서 참고용이다. 제품 코드는 종료 인계가 지정한 기준에서 시작한다.
2. `git status --short --branch`, 포트 5173/4173의 실제 소유 프로세스, `package.json`의 지정 pnpm과 기존 테스트 환경을 확인한다. 타 작업이 진행 중이거나 기준이 불명확하면 조회한 사실과 필요한 인계를 보고한다. 작업 중인 브랜치 전환·stash·reset 또는 동일 체크아웃 공유는 하지 않는다.
3. 최신 소스에서 아래 기능의 소유 위치를 확인한다. UI 전용 브랜치 제안명은 `codex/ui01-day-retro`. 접근 가능한 샘플을 **새 검토 공간**에 넣는다. 기본 경로는 `?workspace=content&review=ui01-day-retro-01`; 이미 사용 중이면 새 접미사를 쓴다. 평소 공간·기존 U4 공간·실여행은 사용하지 않는다.
4. 기존 PC·390px 화면을 같은 가상 표본으로 먼저 캡처한다. 기존 D 경로와 충돌하거나 저장 계약 수정이 필요하면 근거와 영향을 제출한다. 경로명만 이동했다면 최신 동등 컴포넌트에 적용한다.

## 2. 구현 범위 · 세 하위 작업

**① 오늘.** `src/content/Journey.tsx`, `DayDetails.tsx`, `ContentApp.tsx`의 하루 상세·장소 복귀 분기, 관련 CSS부터 본다. 날짜 띠 → 날짜·지역·활동 수 → 기존 현재/다음 안내와 하루 타임라인으로 읽게 한다. C-15 대표 사진·사진 띠는 활동보다 먼저 둔다. 한 날짜의 표시 순서에서 바로 이웃한 A→B는 수단·시간을 중심으로 한 연결 행(‘도보 약 10분’)으로 표시한다. A→C·역방향·다른 일자 등 단순 인접으로 해석할 수 없는 연결은 양 끝을 표기한다. 모르는 수단은 원문 그대로, 거리/소요 시간이 없으면 추정하지 않는다. 이동 수정·외부 지도·활동별 방문과 `⋯`는 계속 접근 가능해야 한다. 장소를 열고 돌아오면 같은 활동이 보이고 키보드 포커스도 돌아와야 한다.

**② 날짜별 회고.** `src/content/Retrospective.tsx`와 `src/content/retro-rules.ts`의 `buildRetrospective` 결과를 사용한다. 날짜·계획 버전 선택기 바로 뒤에 실제 결과 집계를 표시한다. 선택한 날짜의 활동별로 ‘계획 / 실제’를 한 그룹으로 읽게 하되 ‘당시 계획 N’, 당시 장소 본문, 근거 열기, 기존 과거↔현재 비교를 유지한다. 동일 여행의 활동 ID로 연결하고 당시 버전 ID를 표시한다. 제목 일치는 근거로 쓰지 않는다. 활동·버전 연결이 없으면 별도 실제 기록으로 표시한다. 실제 날짜가 다른 항목을 선택일의 방문 건수로 올리지 않는다. 원래 날짜의 이동 안내와 최신 날짜의 대표 기록을 구별한다. 390px은 세로, PC는 공간이 충분할 때 같은 행의 두 열로 표시한다. 회고 열람·날짜/버전 선택은 읽기 전용이다.

**③ 검사와 제출.** 기존 UI·회고·사진 시험을 우선 사용한다. 새 회귀 시험은 인접/비인접 표시, 정정의 이중 집계, 복귀 포커스 등 기존 시험이 놓치는 위험에 한정한다. 접근성 이름이나 화면 의미가 바뀌면 기대값 변경 이유를 남긴다. 앱에 데모 전용 홈·탭·저장 방식을 추가하지 않는다. DB/백업 스키마, 저장 명령, 변환기, D의 서버·AI 정책, 다른 탭 전면 개편은 이 단위 밖이다.

## 3. 합격 시나리오

| ID | 가상 표본과 실행 | 기대 결과 |
| --- | --- | --- |
| A1 | 하루에 활동 A·B·C. A→B 도보 약 10분, A→C 사용자 입력 이동. 장소를 열었다가 복귀 | 인접 행은 이름 반복 없이 이동을 읽는다. 비인접 행은 A·C가 구분되고 원문을 보존한다. 복귀 후 원래 날짜·활동이 보이고 포커스가 복구된다. |
| A2 | 여행 중 오늘, 종료 여행, 시각 미정, 활동 0건, 사진 0/1/복수 | ‘지금·다음’은 기존 조건에서만 표시. 없는 시각을 채우지 않는다. 사진 규칙과 빈 날의 ‘활동 추가’ 경로가 유지된다. |
| A3 | 한 날짜에 방문 1·건너뜀 1과 예정 외 기록. 날짜·버전 선택 후 회고 진입 | 기본 글꼴 390×844에서 스크롤 없이 선택 날짜와 실제 건수 요약을 읽는다. 계획 시각과 실제 결과를 같은 활동 안에서 구분한다. |
| A4 | 같은 제목의 다른 ID, 두 실제 방문, 정정으로 날짜 이동, 발생일 미상, 선택/현재/기록 당시 버전이 다른 표본 | 다른 활동 혼합 0, 독립 방문 누락 0, 정정 이중 집계 0. 원래 날짜에는 이동 안내, 최신 날짜에는 한 대표 기록. 당시 본문과 변경 근거의 고정 참조를 확인한다. |
| A5 | PC에서 키보드로 날짜 선택→장소→복귀, 회고 날짜·버전 전환. 320px·200% 확대 확인 | 날짜/탭/버튼의 이름과 포커스가 보이고, 본문 넘침·고정바 가림 0. 열람 전후 여행 revision·계획 수·실제 기록 수가 같다. |

고정 시각 가상 표본은 기존 fixture·시험 시계로 만들고 재현 절차를 남긴다. 사용자 브라우저 시계나 기존 자료를 바꾸지 않는다. `pnpm run check`(빌드 포함) → `pnpm run test:e2e`. 원인 분리 시 `node scripts/playwright.mjs test tests/e2e/retrospective.spec.ts tests/e2e/ui-c15.spec.ts tests/e2e/u4-sapporo.spec.ts`로 대상 실행이 가능하다. 전체 결과와 대상 결과를 따로 적는다.

## 4. 제출 형식과 종료

- `docs/claude-task-ui01-result.md`에 20줄/2,000자 이내 요약과 증거 색인을 제공한다. 기준·결과 SHA, 커밋·push, 명령별 성공/실패/미실행, A1~A5 판정과 파일 링크, PC 재현 URL·가상 데이터 준비 동작을 적는다.
- `docs/design/ui01/`에 동일 표본의 PC·390px 전후 ‘오늘’과 ‘회고’ 각 한 장씩(총 8장)을 둔다. 추가 경계 사례는 필요한 부분만 캡처한다. 기존 인계에는 현재 상태와 보고서 링크만 남긴다.
- 검사 통과 뒤 구현 단위만 커밋·push한다. 같은 오류가 두 시도 후에도 지속되거나 저장 계약·D 기능 충돌이 발견되면 증거·차단 이유를 보고한다. 자동 검사, Claude 자체 판정, Codex 독립 판정, 사용자 화면 확인은 각각 기록한다.
- 사용자가 볼 첫 동작은 **오늘에서 A→B를 읽고 장소에서 원위치로 돌아오기**, **회고에서 날짜를 바꿔 계획과 실제를 비교하기**다. 제출 상태는 ‘검토 준비’다. UI-02 착수·main 병합·배포는 이번 지시로 진행하지 않는다.
