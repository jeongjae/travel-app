# E3 범위안 (Codex 제안 — 사용자 결정 전)

- 작성 2026-11-20. 근거: [설계서](ai-rework-requirements-design.md) §3·§4.4·§4.6·§4.8·§5, E1·P1·E2 구현 결과.
- 이 문서의 구분·추천은 Codex 제안이다. 사용자 결정은 [결정 기록](decisions.md)에 따로 적는다.

## 1. 설계서의 E3 네 항목과 지금 상태

| # | 항목 | 지금 | 남은 일 | 크기 |
|---|---|---|---|---|
| a | 날짜 화면의 "AI에게 요청" | 내보내기가 날짜 범위를 이미 받는다(E2) | 날짜 화면에 단추를 두고 그 날짜로 범위를 미리 채워 연다 | 작음 |
| b | 직접 입력 화면 보완 | C단계의 편집 화면이 있다 | 무엇이 부족한지 목록이 없다 — 써 봐야 나온다 | 미정 |
| c | 세부 자료 채우기 1·2단계 | 1(직접 입력)은 있다. 2(챗봇이 채운 글 다시 가져오기)는 E2로 메모·링크·새 장소까지 된다 | c-1 "빈 칸을 채워 달라"는 요청문 / c-2 **기존 장소의 내용**(설명·영업시간)을 글로 고치기 — 지금은 받지 않는다 | c-1 작음, c-2 중간 |
| d | 프로필 재사용·스타일 프리셋 | 조건·취향 답은 기기에 "준비 초안" 1건으로만 남는다 | d-1 스타일 프리셋 단추 / d-2 지난번 답을 새 여행의 기본값으로 불러오기 | 작음 |

## 2. 제안: 두 번에 나눈다

| 묶음 | 내용 | 이유 |
|---|---|---|
| **E3-1** (먼저) | a, c-1, d-1, d-2 | 모두 "요청문을 만들어 주는" 화면 쪽 일이다. 저장 구조를 건드리지 않고 작다 |
| **E3-2** (실사용 점검 뒤) | b, c-2 | b는 부족한 점 목록이 있어야 한다. c-2는 장소 내용 수정이라 저장 명령·승인 화면이 더 필요하다. 사용자의 실사용 점검 결과로 범위를 정하는 편이 헛일이 적다 |

## 3. E3-1에서 사용자가 정할 것

| # | 질문 | 선택지 | Codex 추천 |
|---|---|---|---|
| 1 | 날짜 화면의 "AI에게 요청"이 담는 범위 | A 그 날짜만(창에서 넓힐 수 있음) / B 앞뒤 하루씩 함께 | A — 글이 짧고, 고칠 대상이 분명하다 |
| 2 | 스타일 프리셋 종류 | 설계서 예: 첫 방문 핵심 관광 · 여유로운 휴식 · 미식 중심. 더하거나 뺄 것 | 세 가지로 시작 |
| 3 | 지난번 답 불러오기 | A 새 여행 준비를 열 때 "지난번 답 불러오기" 단추 / B 자동으로 채워 둠 | A — 다른 여행의 조건이 모르게 섞이지 않는다 |
| 4 | "빈 칸 채우기" 요청문 | "AI로 수정하기"에 요청 종류를 고르는 칸을 둔다: 자유 요청 / 빈 메모·링크·장소 채우기 | 넣는다 |

## 4. 하지 않는 것(E3-1)

- 프로필·가이드의 DB 저장과 기기 간 이동(P2), 앱 안 AI 조사(§4.4 3단계), 기존 AI 정리(E4).
