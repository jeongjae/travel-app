# 활동 메모 재조회 수정

2026-10-27 · **수정·로컬 검증 통과 / iPhone 기존 메모 재조회 사용자 확인 완료**

사용자 보고: iPhone에서 오늘 일정의 활동 옆 ‘메모’에 기록했지만 다음에 같은 메모를 열면 비어 있고 다른 곳에서도 찾을 수 없었다. 오프라인 테스트의 **수정 요청**으로 기록한다. ZIP 가져오기·일정/사진 조회 성공은 유지하며, 오프라인 기록/종료/복원·G2′ 전체 통과로 표시하지 않는다.

## 원인과 보호 범위

- 시작 HEAD=`8c9ba6c`, main. 원격 HEAD 일치, 5173·4173·8787 리스너 없음. 전일 미커밋 검증 문서와 다른 검토의 `docs/status-review-2026-10-26.md`는 구분해 보존했다.
- 기존 `NoteEditor`는 새 `AddNote` 입력칸만 제공하고 대상의 저장 메모를 읽어 표시하지 않았다. 일정 카드에도 표시가 없었다. 전체 메모 목록은 접힌 ‘예약·기록·계획 도구 → 실제 기록’ 안에만 있었다.
- 수정 전 `tests/e2e/notes.spec.ts`의 가상 활동에서 메모 저장 후 DB에 본문1건이 있는 것을 확인한 다음, 같은 메모 창의 본문 표시 검사가 실패했다. 이 증거는 **DB 저장 후 조회 UI 누락**의 재현이며, 사용자의 iPhone DB에 그 메모가 실제 남았다는 직접 검증은 아니다.
- 사용자 DB/브라우저·실제 여행 ZIP·원본 SP-FR을 테스트에 사용하거나 초기화하지 않았다. 저장 스키마/명령·backup 형식·원문은 변경하지 않는다. 키·실제 API도 사용하지 않았다.

## 바뀐 동작

1. 오늘 활동 카드와 같은 활동의 메모 창에서 ‘저장된 메모’를 읽는다. 줄바꿈과 저장 시각을 표시한다.
2. 메모 창은 기존 메모 목록과 ‘새 메모 추가’를 구분한다. 빈 입력칸을 기존 메모가 사라진 것으로 오해하지 않게 설명하고, 이전 내용을 덮어쓰거나 읽기만으로 중복 저장하지 않는다.
3. 이미 반응형으로 조회한 `records`를 재사용한다. 여행/대상 종류/ID로 구분하고 계획 버전이 바뀌어도 동일 활동의 메모를 찾는다. 정정된 기록은 최신 것만 표시하며 원본을 삭제하지 않는다. 다른 여행의 같은 ID는 섞지 않는다.
4. 저장 중 재제출을 막고 공백뿐인 새 메모를 거부한다. 저장은 기존 `AddNote`·repository 트랜잭션·revision 검사를 통과한다. 오래된 입력을 무확인 덮어쓰는 경로는 추가하지 않았다.

`src/content/Notes.tsx`의 조회/표시, `ContentApp.tsx`의 대상 연결과 저장 상태, `content.css`의 작은 메모 영역이 변경 대상이다. 포맷·구조 리팩터링을 묶지 않았다. 기존 사용자 데이터 이행이나 ZIP 재가져오기가 필요한 변경은 아니다.
