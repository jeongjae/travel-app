# Phase 2 B-01 · Barcelona 확인 안내

2026-10-23 · **B-01 사용자 확인 완료**

사용자가 아래 실제 산출물 확인 요청에 **‘확인 완료’**로 응답했다. B-01 확인을 닫고, 확인 동작과 다시 여는 방법은 재점검용으로 보존한다. 전체 G2와 iPhone 실기기 확인은 별도다.

기존 파리 검토 창과 다른 Chromium 전용 프로필에 Barcelona 실제 표본을 열었다. URL은 `http://127.0.0.1:4173/?workspace=content&review=phase2-b01`, 여행 이름은 **SP-FR 대표 구간 Day 1·2·3**이다. ‘검증용 저장소’ 표기를 확인한다. 평소 DB와 파리 표본을 초기화하거나 덮어쓰지 않았다.

## 확인할 동작

1. **오늘·전체 일정:** 8/29·8/30·8/31의 도착/관광/독서·도시 일정과 활동17개·이동14개를 본다. 첫/다음 일정과 원천 예약 안내, 활동 옆 이동, 아래쪽 하루 사진·식사/교통·숙박을 확인한다.
2. **가이드:** 일정의 장소 안내→목차→‘일정으로 돌아가기’로 같은 날짜에 복귀한다. 지역 안내와 장소/주제22개를 둘러본다. 그중 독립 본문12개와 없는10개를 구분한다. 부재 안내는 변환기 누락이 아니라 고정 tree의 원천 상태다. 빈 원천 절의 설명을 창작하지 않았다.
3. **Fact·사진:** 가격/시간 값과 확인 상태를 본다. 다른 장소를 참조하는 Fact도 연결했으며 꺾쇠 전시명·배지 라벨이 사라지지 않는지 확인한다. 사진은 본문 아래쪽과 하루 안내에 있고, 준비의 ‘사진·관광 지도 · 오프라인 자료’에서도 볼 수 있다. 51파일은 독립 사진51장을 뜻하지 않는다.
4. **예약·준비:** ‘예약·기록·계획 도구’→예약 화면에서 출처별3건을 본다. 새 확정 예약3건으로 해석하지 않는다. ‘준비’에서 자료/회화를, 접힌 원천 대조에서 통합문서와 전체 대응표를 연다.
5. **편집·기록:** 기존 본문의 ‘실용 편집’이나 검증용임을 적은 현장 메모를 저장하고 재조회한다. 자동 검증 데이터는 다른 DB에만 있다. 실제 방문으로 오해할 기록을 테스트로 만들지 않는다.
6. **백업:** 상단 오른쪽 ‘저장소·백업’→전체 백업 만들기→파일 저장. 빈 복원 공간은 `http://127.0.0.1:4173/?workspace=content&review=phase2-b01-user-restore`다. 기존 검토 공간을 지우지 말고 다른 탭의 빈 공간에 복원해 사진/본문/기록을 본다. 이미 여행이 있으면 짧은 다른 review 이름을 사용한다.

자동 검증은 PC에서 파일52개의 해시·전체 행·편집·오프라인 기록·빈 저장소 전체 복원을 통과했다. iPhone Chrome 실기기·전체43일 이행 완료는 별도다. [실행/검증/남은 차이](phase-2-report.md).

## 창을 다시 열기

같은 폴더·프로필을 사용한다. 4173에서 이 프로젝트의 preview가 동작해야 하며, 기존 창의 입력은 저장한 뒤 닫는다.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.cache/ms-playwright'
node scripts/open-pilot-review.mjs --package local-data/phase2/b01-barcelona/final-02/pilot.zip --output-dir local-data/phase2/b01-barcelona/user-review --review phase2-b01
```

다른 브라우저에는 DB가 자동 공유되지 않는다. 빈 검증 공간에서 ‘여행 선택·가져오기’를 펼치고 위 `pilot.zip`을 선택해 미리보기 후 여행에 추가할 수 있다. 실제 ZIP은 GitHub에 없다.

**B-01 확인 완료를 기록했다.** 추가 수정 요청은 날짜/화면/내용으로 추적한다. 다음 배치도 별도 산출물을 제시하고 사용자 확인을 받으며 문서·검사 통과·무응답을 확인으로 간주하지 않는다.
