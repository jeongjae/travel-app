# Claude Sonnet T-03 · 이행 잔여 원천·의미·지역 ZIP 대조

2026-10-28 · **전달 준비 / 구현 미착수** · T-02 main 반영 후 문서 커밋을 기준으로 시작

## 전달할 요청

> Sonnet을 유지하고 아래 세 단위를 자율적으로 수행하세요. 상세 조사·검증 도구·검사·증거 정리를 맡깁니다.
> 목적은 SP-FR 이행에 남은 원천/의미/지역 패키지의 실제 미처리 범위를 식별하고 재현 가능한 증거를 만드는 것입니다.
> 최종 요약은 20줄·2,000자 이내와 증거 색인으로 제출하세요. 같은 로그를 여러 번 보고하지 마세요.
> 제품 데이터/코드 수정·원본 변경·실제 AI·공개 배포는 하지 말고, 필요한 수정은 재현·최소 제안으로 제출하세요.

## 1. 시작·보호·수정 범위

AGENTS.md, handoff → development-plan → product-requirements → decisions를 읽는다.
이어 deferred-verification, full-verification-2026-10-26, phase-2-continuous-report,
claude-task-01-r1-regionids의 요약·증거 색인부터 읽고 관련 원문만 추가 확인한다.
시작 SHA·브랜치·dirty·포트 소유와 데이터/manifest 위치를 확인한다. 기존 프로세스·프로필 상태를 가정하지 않는다.

main의 최신 문서 커밋에서 `codex/t03-source-audit` 작업 브랜치를 만든다. 같은 이름이 있으면 상태를 확인한다.
worktree·reset·강제 push·main 직접 push·원격 설정 변경을 하지 않는다. 미추적 기존 점검 문서를 보존한다.

- 고정 원천과 기존 개인 ZIP/manifest는 **읽기 전용**이다. 원천 revision·SHA/해시를 기록하고 변경하지 않는다.
- 실제 검증은 새 Git 제외 출력/DB·가상 프로필에서만 한다. 사용자 PC 검토 프로필·iPhone 저장소는 열거나 초기화하지 않는다.
- 실제 원문·예약·키·메모·사진·백업·스크린샷·개인 ZIP을 공개 보고서/fixture/커밋에 넣지 않는다.
  공개 보고는 항목 ID·수량·결과·제약 중심으로, 민감한 locator/값은 Git 제외 대응표에 둔다.
- 필요한 원천이 없으면 정확한 누락 범위를 보고한다. 원본 전체를 새로 내려받거나 다른 저장소를 수정하지 않는다.
- 수정 가능: 익명 가상 회귀/fixture, 재사용 가능한 읽기 검증 도구, 해당 결과/잔여 목록/handoff 문서.
  제품 `src/`·`server/`, 스키마/정규화 버전·실제 데이터·의존성·배포 workflow는 이번 수정 범위 밖이다.
- 테스트는 명시 인자로 지정한 사본을 읽는다. 일반 check/CI가 자동으로 개인 자료를 탐색/읽지 않게 한다.

## 2. T-03a · 잔여 콘텐츠와 의미 근거표

1. 고정 원천·manifest·기존 대응표·선택 추출의 실제 조사 범위를 먼저 고정한다.
   ‘추출한 범위의 미대응0’과 ‘원천 전체 미처리0’을 구분한다. 기존 독립 대조의 범위를 그대로 인정하고 새 검증과 섞지 않는다.
2. 원천 코드의 공통 준비/비상·화면 콘텐츠·남은 참조를 조사해 DB 필드/본문/첨부/일반 UI/보류/제외 제안으로 대응한다.
   일반 UI/알고리즘까지 여행 DB에 넣지 않는다. 설명 없는 누락과 사용자 미승인 제외를 완료로 분류하지 않는다.
3. REG-01은 실제 이동일·귀국일 원천의 숙박/장소/도시와 DB 값을 대조한다.
   day.regionIds·overnightRegionId의 현상, 원천에 명시된 관계, 향후 필요한 질의를 구분한다.
4. 원천 근거가 충분한 기술 권고안 하나와 호환/재가져오기/과거 계획 영향을 제출한다.
   A(숙박 전용)를 현 코드만으로 확정하거나 B(관련 지역 전체)를 적용하지 않는다. 미해결이면 판단에 필요한 근거를 적는다.
5. 각 미처리 항목에 대상·영향·차단 여부·다음 검사·담당(Claude/Codex/사용자)을 붙인다.
   Fact65개 근거/권리는 원천 보존 검사와 별도다. 이번 조사만으로 사실·권리 확인 완료로 승격하지 않는다.

## 3. T-03b · 지역별 ZIP 독립 검사

기존 지역별9배치·귀국일·통합본의 실제 패키지 목록/버전/해시를 확인한다. 보고 수량을 파일 검증 없이 확정하지 않는다.
기존 읽기/스키마/검증 함수를 재사용하되, 다음 의미 기대값은 원천/manifest에서 독립적으로 만든다.

- ZIP 읽기·필수 참조·날짜/일차·명시 활동/이동·숙박 경계·첨부 길이/해시를 대조한다.
- 지역별 선택 필터의 허용된 제외와 실제 누락을 구분한다. 서로 다른 범위의 단순 수량 차이를 손실이라고 단정하지 않는다.
- 없는 본문/장소/첨부를 발명하지 않고 미상/미확보 상태가 원천과 일치하는지 확인한다.
- 기존 통합본·G1/B-01·백업은 덮어쓰지 않는다. 재생성·재가져오기·수정 적용은 이번 작업에 포함하지 않는다.
- 최소 증거표: 패키지 식별·해시·대상 범위·수량·참조/해시/의미 결과·실패·미검증·로컬 증거 경로.

전체 PC/실기기 복원을 같은 코드라는 이유로 반복하지 않는다. 새 실패나 기존 증거 공백이 있으면 해당 범위만 조사한다.

## 4. T-03c · 잔여 회귀와 다음 수정안

조사에서 드러난 데이터 손실/의미 오인 위험을 우선해 최대3개 사례를 가상 회귀로 만든다.
이미 충분한 검사는 재사용하고 assertion 위치만 적는다. 원천의 실제 개인 내용을 가상 fixture에 복사하지 않는다.
제품 결함이 재현되면 실패 증거·원인 후보·최소 수정 파일·보존/호환 영향·필요 검사를 제출한다.
기대값을 약화하거나 TODO를 제거해 완료로 만들지 않는다. 제품 수정은 다음 Codex 지시로 분리한다.

## 5. 검사·산출물·중단

- 도구/테스트 변경은 대상 검사 뒤 `pnpm run check`, 저장/화면 흐름에 영향이 있으면 관련 E2E·pilot을 수행한다.
- 가상·로컬 실데이터·사용자 확인·원격 CI를 구분한다. 문서/읽기 조사만 바뀌면 무관한 전체 회귀를 반복하지 않는다.
- 검토 산출물: 로컬 독립 대응표/검증 JSON, 사람이 실행할 명령, 조사 범위/미처리 표,
  REG-01 권고, 다음 수정 지시 초안(최대3건). 실제 화면 결함이면 가상 재현 화면을 함께 둔다.
- 원천 부족·기존 자료 불일치·새 계약/실제 적용/외부 API가 필요하면 해당 부분을 미완료로 보고하고 다른 독립 단위를 진행한다.
- 결과는 `docs/claude-task-03-result.md` 첫머리 요약/증거 색인과 상세 로컬 파일로 나눈다.
  구현/자동 검사/실데이터 대조/Codex 검토/사용자 확인을 각각 기록한다. G2/G2′를 종료하지 않는다.
- 검증된 도구/가상 검사와 보고 문서를 커밋 단위로 나누어 작업 브랜치에 push한다.
  실패 재현만 있는 diff는 상태를 밝히고 정상 검사에 섞어 성공으로 보고하지 않는다. 원격 CI는 실제 결과만 적는다.

이 지시서는 T-03 범위의 조사·도구/회귀·증거 제출이다. 새 제품 정책·실데이터 변경·실제 방문·이행 완료 승인을 뜻하지 않는다.
