# UI 정리 계획 · 진단과 단계

2026-11-02 · 작성: Codex · **제안 / U1 지시 발행 / 사용자 시제품 확인 전**

C단계 종료(10/30, PC·가상 기준) 뒤 사용자 의견 "UIUX는 다듬을 필요가 있음"([CL-20](change-log.md))과 11/02 답변을 근거로 한다.
사용자가 고른 불편 영역: **메뉴·버튼 찾기 / 입력 폼 / 일정·회고 화면 읽기 / 전체 디자인·모바일** (네 개 모두).
진단 화면은 C-07 삿포로 리허설을 그대로 돌려 Codex가 캡처한 것이다(가상 자료, Chromium 1504px·Pixel 7 에뮬레이션): [`design/ui-audit-2026-11-02/`](design/ui-audit-2026-11-02/).
화면 표기: d1 오늘(PC) · d2 기록 폼(PC) · d3 실제 기록 목록 · d4 회고(PC) · d5 가이드·접힌 메뉴 · m1 오늘(모바일) · m2 활동 추가 폼(모바일) · m4 회고(모바일).

## 1. 원칙

- **기능·데이터는 그대로, 보이는 구조만 바꾼다.** 저장 명령·스키마·백업 형식·검증 규칙은 바꾸지 않는다. 확인 결과 CL-17(변경 이유)·CL-18(종료 시각)도 UI만으로 가능하다(`ChangePlan.reason`, `time.end` 기존 지원).
- **현장 우선.** 휴대폰 한 손 사용 기준으로 첫 화면에 오늘 일정이 보이고, 가장 잦은 동작(방문 기록)은 한 번에 닿는다.
- **드문 동작은 한 단계 안으로.** 순서 변경·제거·고급 시각 설정은 숨기되, 숨긴 위치가 예측 가능해야 한다.
- **내부 용어를 화면에서 뺀다.** 버전 번호·`IANA`·`정밀도`·`검증용 저장소`·`이행 점검` 같은 말은 필요한 곳(검토·고급)에만.
- **시제품 확인 후 확대.** 탐색 구조는 사용자 선택이 필요한 결정이라 U1 시제품을 보고 확정한다([C 계획](phase-c-plan.md) §5 원칙 유지).
