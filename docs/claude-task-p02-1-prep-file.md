## A. 양식 `travel-app-prep/1` (순수 함수, `src/guide-import/` 아래)

1. 사람이 읽는 md 글 하나. 구성: 머리(`# 준비 자료: <목적지>` · `- 양식: travel-app-prep/1` · `- 만든 날: YYYY-MM-DD`) → `## 취향 답` 표(항목 | 값) → `## 고른 것` 표(선택 | 종류 | 이름 | 지역) → `## 가이드 원문` 아래에 지금 저장된 가이드 글 그대로.
2. 취향 답은 "지난번 답"과 같은 8칸만 담는다(`pickLastAnswers` 재사용). 여행지·날짜·방문 경험·메모는 넣지 않는다. 빈 칸은 줄을 만들지 않는다.
3. 고른 것은 항목 key가 아니라 **종류·이름·지역**으로 적고, 읽을 때 파일 안 가이드의 항목과 그 세 값으로 맞춘다. 맞는 항목이 없으면 버리고 건수를 돌려준다. 같은 세 값의 항목이 여럿이면 모두에 적용한다.
4. 읽기는 관대하게: 줄바꿈(CRLF), 줄 끝 공백, 둥근 따옴표, 글 전체가 코드 블록(```)에 싸인 경우를 받아들인다. 크기 한도는 가이드와 같다.
5. 거절: 양식 판이 다르다 / 가이드 원문이 가이드로 읽히지 않는다 / 표가 깨졌다 → 이유를 한글 문장으로. 거절하면 현재 초안은 그대로다.
6. **기존 가이드 변환기의 결과가 바뀌면 안 된다**: 순수 가이드 글(양식 `travel-app-guide/1`)의 고정 자료 시험은 수정 없이 통과해야 한다.

## B. 화면 — 가이드 구역("AI로 계획 만들기" 안)

1. 저장: 가이드가 있을 때 **준비 자료 저장**(파일 `준비자료-<목적지>.md`)과 **준비 자료 복사**를 둔다. 옆에 한 줄 안내: "가이드, 고른 것, 취향 답(예산·동행 포함)이 글 그대로 들어갑니다." 기존 "가이드를 파일로 저장"(가이드만)은 그대로 둔다.
2. 불러오기: 새 입력 칸을 만들지 않는다. **기존 가이드 입력(붙여넣기·클립보드 단추·파일 선택)** 이 준비 자료 양식을 알아보게 한다.
3. 준비 자료이면 반영 전에 미리보기: 목적지, 가이드 항목 수, 고른 것 n건(꼭 포함 a · 관심 b · 제외 c, 맞지 않아 버린 것 k건), 취향 답 m칸. 체크 2개 — **고른 것도 가져오기**(기본 체크), **취향 답도 가져오기**(기본 해제). 가이드는 항상 가져온다.
4. 지금 초안에 가이드나 고른 것이 있으면 "지금의 가이드와 고른 것 n건을 바꿉니다"를 확인받는다(기존 "가이드 바꾸기"의 확인 방식 재사용). 취향 답을 가져오면 그 8칸만 덮어쓰고 나머지 답(여행지·날짜 등)은 건드리지 않는다.
5. 엉뚱한 곳에 넣었을 때: 계획 붙여넣기 화면에 준비 자료가 오면 "준비 자료입니다. 'AI로 계획 만들기'의 가이드 칸에 넣어 주세요" 뜻의 안내(`is-guide` 안내와 같은 방식).
6. 순수 가이드 글을 넣었을 때의 동작·문구는 지금과 같다.

## 시험·보고

- 단위: 만들기 → 읽기 왕복(가이드·고른 것·답 일치), 고른 것 없음/답 없음, 4번의 변형 글 4종, 5번의 거절 3종, 맞지 않는 고른 것 건수, 기존 가이드 고정 자료 불변.
- E2E(desktop·mobile): 가이드에서 2건을 고르고 준비 자료 저장 → 초안 지우기 → 그 글을 가이드 칸에 넣기 → 미리보기 → 반영하면 같은 2건이 골라져 있다 / "고른 것도 가져오기"를 끄면 고른 것 0건 / 초안이 있을 때 확인 창 / 계획 화면 안내.
- `pnpm run check`, `test:e2e:all`(포트가 막혀 있으면 CI로 대체한다고 적는다). push 뒤 CI 통과 확인. `docs/claude-task-p02-1-result.md`와 캡처(PC·390px: 저장 단추, 미리보기, 확인 창)를 붙여 보고한다. 하지 않은 검사는 "미실행"으로 적는다.
- 멈춤: 데이터 경계를 고쳐야 한다 / 기존 가이드 변환 결과가 달라진다 / 준비 자료와 순수 가이드를 안정적으로 구분할 수 없다.
