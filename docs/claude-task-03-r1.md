## R1-1 · 실패 신호

- package audit의 JSON 보고서를 저장한 뒤, 어느 패키지든 검증 실패가 있으면 exit code를 비정상으로 반환한다.
- 정상 검사는0, 검증 실패/입력 오류는 비정상으로 구분하고 문서에 적는다.
- 미선택 파일·REG-01 관찰 등 조사상 미결정과 실제 검증 실패를 구분한다. 실패 기대값을 약화하지 않는다.
- 가상 정상/변조 ZIP으로 subprocess 종료 코드와 보고서 failureCount를 함께 검증한다.
  기존 실제 변조 사본을 재사용하면 결과 로그만 로컬 보존하고 개인 내용을 공개 검사에 복사하지 않는다.

## R1-2 · 원천·입력 보호

- 두 도구 모두 출력 경로를 쓰기 전에 검증한다. source 내부/동일 경로와 입력 ZIP·참조 ZIP·selection 등
  읽을 입력 파일을 덮어쓰는 경로를 거부한다. source renderer의 파일 인자가 source 밖으로 빠지는지도 점검한다.
- 단순 문자열 prefix 대신 정규화한 경로 관계를 사용한다. Windows 대소문자·상대 경로·기존 symlink/별칭을 고려한다.
  같은 파일의 별칭을 지원 환경에서 안전하게 검사하되 권한 없는 링크 생성이 필요하면 제약을 명시한다.
- 모든 위험 경로 시험은 임시 가상 파일/디렉터리로만 한다. 시험 전후 입력 길이/해시가 유지됨을 단언한다.
- 최소 사례: 정상 별도 출력 성공, 입력 ZIP와 같은 출력 거부, 참조/selection 덮어쓰기 거부,
  원천 내부 출력 거부, 경로 별칭/대소문자 경계, 실패 후 원본 보존.

## 검사·제출

Python 가상 도구 검사를 실제 실행하고 명령·exit code·결과를 보고한다. CI에서 개인 파일을 자동 탐색하지 않는다.
자동 검사 연결이 필요하면 기존 환경에서 동작하는 최소 경로를 제안하되 의존성/workflow는 이번에 변경하지 않는다.
제품 코드는 같으므로 무관한 UI/전체 회귀는 반복하지 않는다. TS 검사 파일을 추가하면 포맷·린트·타입 포함 check를 수행한다.
수정된 도구로 verified ZIP과 변조 사본 각1개를 새 출력에 재검사하고 실패 코드/원본 해시 보존을 기록한다.

도구/가상 검사와 보고는 별도 커밋으로 나눠 작업 브랜치에 push한다. main 병합·배포·실제 자료 적용은 하지 않는다.
