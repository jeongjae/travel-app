## 1. 목표·기준

기존 실제 기록의 날짜 보기 확장을 기본안으로 사용한다. 현재 5개 탐색과 실제 기록 보조 도구를 유지하고,
새 대형 회고 탭·분석 대시보드·AI 회고문 생성·실제 기록 재작성은 하지 않는다.
사용자가 날짜를 골라 계획/실제 차이를 읽고, 기록 당시 계획·장소 본문·정정 원문·계획 변경 이유/근거로 이동해 돌아올 수 있어야 한다.

AGENTS.md → handoff → 개발계획 → 요구/결정 → C 설계/계획 → C-01~04 검토·후속 목록을 읽는다.
현재 커밋을 보존하고 `codex/c05-retrospective` 브랜치에서 진행한다. worktree·reset·main 병합·배포·API 호출은 하지 않는다.
가상 입력/별도 review 공간만 사용한다. 사용자 DB/원본/ZIP/백업·미추적 점검 문서를 변경하거나 공개 커밋하지 않는다.

## 2. 단위 A · 읽기 전용 회고 모델

- 기존 plan/history·field_records·proposal revisions·content revisions 조회를 재사용한다.
  회고를 열거나 날짜/계획 버전을 바꿔도 DB·domainRevision·현재 계획 포인터·receipt·과거 기록을 쓰지 않는다.
  새 저장 명령/파일 스키마·자동 마이그레이션을 만들지 않는다.
- 날짜별 현재 계획과 선택한 과거 계획을 명확히 표시하고 실제 기록은 별도 열/구역으로 구분한다.
  항목의 순서/시각·숙박/이동은 해당 계획 버전에서 읽는다. 현재 값을 과거 버전의 값처럼 표시하지 않는다.
- 실제 기록의 당시 계획은 기록의 명시 planVersionId/activityId로 연결한다. 날짜 하나에 서로 다른 당시 계획이 있을 수 있다.
  계획 링크 없는 예정 외 활동은 ‘계획 연결 없음’으로 읽고 기록 시각/commitSeq만으로 당시 계획을 임의 확정하지 않는다.
- 실제 날짜는 기록에 있는 날짜/시간대/정밀도를 따른다. 날짜/시각 미상은 별도 영역에 남긴다.
  계획 날짜와 실제 날짜가 다르면 구분 표시하며 계획일을 실제 방문일로 대체하지 않는다. 기기 시간대로 몰래 날짜를 바꾸지 않는다.
- 최신 정정본을 대표 기록으로 보이고 원본/중간 정정은 이어 읽게 한다. 시각/날짜를 바꾼 정정의 원문도 연결해서 찾을 수 있어야 한다.
  건수 요약을 제공한다면 정정본을 중복 방문으로 집계하지 않고 미상·예정 외·건너뜀을 구분한다. 통계 자체는 필수 아님.

## 3. 단위 B · 이유·근거·당시 내용 연결

- 계획 version의 reason/parentId/proposalId와 해당 결과 계획을 만든 적용 변경안 revision을 연결한다.
  proposalId만 보고 최신 pending/rejected revision을 적용 당시 변경안으로 잘못 사용하지 않는다.
  수동 변경·가져오기 등 변경안이 없는 계획은 저장된 reason만 보여준다.
- 이유가 계획 전체에 대한 것이면 그렇게 표시한다. 바뀌지 않은 날짜/활동에 그 이유를 개별 원인인 것처럼 붙이지 않는다.
  없는 이유·조사 출처·방문 시각·예약 상태를 생성하지 않는다. 연결 데이터가 없으면 명시적으로 ‘연결 없음/근거 없음’ 표시한다.
- evidenceRefs와 contextRefs는 고정 revision을 따른다. 장소 이름/가이드 본문이 이후 바뀌거나 비활성이 돼도 당시 내용을 읽는다.
  활동이 현재 계획에서 제거돼도 기록이 참조한 과거 계획/항목을 읽을 수 있어야 한다.
- 정정 체인·당시 장소 조회는 C-04를 재사용한다. 회고→당시 계획/본문/변경 이유→회고의 날짜/선택 버전으로 복귀한다.
- 오프라인/연결 부족 상태도 읽을 수 있어야 한다. 회고를 열기만 해도 외부 URL 조회·AI 호출·자동 확인/적용이 실행되면 안 된다.
  당시 내용 화면에서는 기존 읽기 전용 규칙을 유지하고 과거 데이터를 수정하는 버튼을 노출하지 않는다.

## 4. 단위 C · 필수 검사·사용자 산출물

- 가상 모델: 같은 날짜의 복수 계획, 실제 날짜와 계획일 차이, 날짜/시각 미상, 계획 링크 없는 예정 외 활동,
  건너뜀, 2회 이상 정정 및 정정 날짜 이동, 변경안 없는 수동 reason을 검사한다.
- 적용/대기/거절 변경안과 revision을 섞은 fixture로 정확한 결과 계획/이유/고정 근거 연결을 검사한다.
  의미가 없는 경우 조회 결과를 추정으로 채우지 않는다. 실제 Fact/첨부가 있는 가상 본문의 당시 revision 읽기도 유지한다.
- 회고 조회 전후 DB snapshot·현재 계획·domainRevision·receipt·기록이 불변임을 확인한다. 여행/공간 간 누출도 검사한다.
- PC/모바일 E2E: 계획 생성→기록/정정→계획/장소 변경→회고 날짜 선택→당시 계획/실제/원문/이유/당시 본문→회고 복귀.
  날짜 미상 접근·현재/과거 표시·이미 제거된 활동 재조회, 오프라인·재실행, 두 여행 전체 백업→빈 review 공간 복원 후 같은 회고를 확인한다.
- 기존 C-01~04·T-05 회귀를 유지한다. 최종 `pnpm run check:deferred`, 중간은 대상 검사만 실행하고 같은 코드의 포함 검사를 중복 실행하지 않는다.
- 사용자가 볼 산출물: 날짜 1~2개와 날짜 미상 기록의 회고 화면, 정정 원문/최신·선택 계획 버전 표시, 변경 이유/근거 이동·복귀,
  복원 후 같은 회고. 결과에 확인 동작·가상 입력·스크린샷 또는 실행 가능한 검사/로그 경로를 남긴다.
  모바일 에뮬레이션은 iPhone 확인과 구분한다. 읽기 UI 배치를 새 사용자 정책 확정으로 기록하지 않는다.

## 5. 제출·범위 통제

조회/모델·회고 화면/이동·가상 회귀를 검토 가능한 단위로 나누고 필요한 구조/포맷 변경은 별도 커밋으로 한다.
`docs/claude-task-c05-result.md`에 기준/종료 SHA·조회/날짜/버전 연결 결정·검사/exit code·CI·증거·미검증을 기록한다.
결과 보고는 별도 문서 커밋으로 작업 브랜치에 push하고 Codex 검토·사용자 확인은 대기로 둔다.
통상적인 구현 선택마다 확인을 요청하지 말고 위임 범위를 끝까지 처리한다. 새 제품 정책·비용/외부 영향이 필요한 경우만 질문한다.
경미한 표시/편의 문제는 영향/재개 조건과 함께 결과에 남긴다. 기록 훼손·격리·저장/복원·보안 결함과 잘못된 고정 revision 연결은 해결한다.
상위 계획·설계·후속 목록은 Codex가 관리하므로 차이/제안은 결과에만 남긴다.
C-06〔T-C7〕전체 마감 검증을 완료한 것으로 확대하지 않는다. CL-08 시간 계산·T-06/F-2·지역 ZIP·사진/지출·AI·공개 배포·실제 사본 적용은 범위 밖이다.
