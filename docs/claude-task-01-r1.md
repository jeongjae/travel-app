## R1-1 · 사람이 바로 확인할 가상 화면

- 기존 귀국일/이동일·Fact fixture를 패키지로 생성하는 실제 실행 명령을 제공한다. 새 의존성은 설치하지 않는다.
- 가상 ZIP/manifest·스크린샷은 `.cache/`나 OS 임시 경로에 둔다. 공개 샘플에 추가하지 않는다.
- 기존 preview/빈 가상 전용 프로필로 패키지를 여는 명령 또는 정확한 가져오기 절차를 제시한다.
  사용자 검토 프로필을 열거나 기존 저장소를 초기화하지 않는다. 단순 URL만으로 데이터가 공유된다고 하지 않는다.
- PC·모바일에서 마지막 귀국일과 복수 지역 이동일의 날짜·활동·이동·장소/지역 관계를 직접 볼 수 있는 화면을 남긴다.
- 날짜/가이드 선택·기대 문구·스크린샷/패키지 위치·프로필 유지 여부를 보고한다. 표시하지 않는 DB 필드를 화면 증거로 주장하지 않는다.
- Fact 화면은 이미 있는 증거를 재사용한다. 검토에 쓰는 가상 패키지와 테스트 fixture가 같은 입력인지 식별한다.

## R1-2 · regionIds 의미와 회귀의 구분

1. 관련 계약 문서·생성 코드·조회 소비자를 좁게 조사한다. `regionIds`와 `overnightRegionId`의 의미 근거를 표로 적는다.
   숙박/장소/지도/원천 명시 지역을 구분하고, 코드의 현재 동작만으로 의도된 계약을 확정하지 않는다.
2. 어떤 요구가 실제로 검증됐는지 명시한다. 장소/지역 콘텐츠 보존과 하루 regionIds 복수 지역 보존은 별도다.
   원 지시서 T-01b의 하루 지역 필드 조건에 증거가 부족하면 그 부분을 미검증/판단 대기로 남긴다.
3. 숙박만 담는 현재 값의 assertion은 계약 검증과 명확히 구분된 현 동작 관찰로 표시한다.
   fixture를 약화하거나 제품 코드를 수정해 통과시키지 않는다. 단순 삭제만으로 요구 완료를 주장하지 않는다.
4. 기술 판단 후보를 최대2개로 정리하고 필드 의미·영향·기존 패키지/과거 계획 호환·필요 수정/검사를 제시한다.
   근거가 충분하면 하나를 추천한다. 새 의미·스키마·이행 정책은 Codex 판정 전 적용하지 않는다.

## 검사·제출

- fixture/단위 검사가 바뀌면 해당 검사, 테스트 코드가 바뀌면 `pnpm run check`를 실행한다.
- 화면/도구 경로가 바뀌면 관련 PC·모바일 검사를 실행한다. 최종 변경에 해당하는 필수 검사만 수행한다.
  문서/로컬 산출물만 바뀌면 기존 전체 회귀를 반복하지 않고 그 이유와 새 산출물 검증 결과를 적는다.

  handoff를 제한 안에서 갱신한다. Codex 검토는 대기, 사용자 확인은 검토 준비로 둔다.
- 테스트/도구 변경과 보고 문서는 검토 가능한 커밋으로 나누고 push 결과를 보고한다.
  커밋별 파일·명령/exit code·산출물·미해결 의미 판단을 제출한다. 실제 자료/키/백업은 포함하지 않는다.
