## 1. 고칠 것

### A. 전송 허용 목록 (G1~G4)
1. **조사 DTO(웹 검색)**: 자유 요청 원문을 보내지 않는다. 선택 활동의 장소 이름·날짜·요청 종류(추가/수정/제거)로 **조사 질문을 자동 생성**하고, 전송 미리보기에서 사용자가 고칠 수 있게 한다. 장소는 선택 날짜 활동이 참조하는 것만. 모델 지시로 정제하는 방식은 쓰지 않는다.
2. **작성 DTO**: 제외 목록이 아니라 **허용 목록**으로 다시 쓴다. 기본 제외: `executionMarkers`·`bookingIds` 원값·`menuText`·`backupText`·`needsReview`·`sourceFlags`·`sourceStatus`·사진 캡션·여행 이름·계획 사유·무관한 장소. 예약은 원값 대신 `fixed: true`와 시간대만. 꼭 필요한 필드를 남기면 결과에 이유를 적는다.
3. **기록**: 전체/없음 대신 **날짜·항목 선택**, `supersedes` 체인의 최신 유효값만. 기본은 꺼짐.
4. 화면 문구 "예약의 비공개 필드는 보내지 않습니다"가 실제와 맞게.

### B. 동의 (G5)
- 빌더의 `consent: true` 고정을 없앤다. 동의는 **전송 내용 지문 + 서버·모델 + 한도**에 묶고, 입력·선택·정책이 바뀌면 동의를 무효로 한다. 서버는 지문이 맞지 않는 요청을 거부한다.
- 전송 미리보기: 조사 질문(편집 가능), 작성에 보내는 항목 요약, 제외된 것 목록, 상세 JSON은 접기.

### C. 의미 검증 (G6~G8, BM-1·2·3·5·6)
1. **BM-2**: 선택 날짜의 도착/출발 시각과 고정(예약) 활동 시간대를 제약으로 보낸다. 도착/출발은 그날 leg 시각에서 얻고, 없으면 요청 화면에서 입력(요청에만, 저장 데이터는 바꾸지 않음). 제약 밖 시간대 제안은 로컬 검증이 **거부**.
2. 종료 < 시작 거부(G7). 03시 같은 비현실 시각은 경고.
3. 예약 활동의 시각 변경·제거는 자동 적용 불가 → **"확인 필요"** 표시로 사용자가 따로 확인(G6).
4. **BM-5**: 제거·이동으로 leg가 끊기거나 앞뒤 시각과 충돌하면 충돌 표시. 적용 시 사라질 leg를 미리 보인다(G8). leg 재계산은 하지 않는다.
5. **BM-1**: 요금·운영 상태·휴무·계절 폐쇄 같은 변하는 사실은 공식 출처+확인 시각이 없으면 '미확인'으로 고정(모델이 '확인됨'이라 해도).
6. **BM-3·6**: 변경안 항목별 요약 카드 — 사유 한 줄, 출처 종류(공식/언론/블로그·커뮤니티)와 개수, 확인 시각, 영향(예약·이동). 전체 근거는 상세.

### D. 응답 처리 (G10, G18)
- `refusal`·`status: incomplete` 처리, `usage` 읽어 작업에 기록(표시는 T-D2), 429를 `project_spend_limit_exceeded`와 일반 속도 제한으로 구분해 안내.

### E. 시험 기반
- `docs/d00/send-surface.probe.ts`를 정식 시험으로 승격: **표식 전수 방식**으로 조사·작성 body에 허용 밖 값이 0인지 단언.
- 간헐 실패 대응: 작업 저장 시험 폴더를 OS 임시 폴더로(시험 전용 조정, 앱 동작 불변). 단독 20회 재실행으로 효과 확인.

## 2. 시험·검사
- 단위: DTO 허용 목록, 기록 최신값 선택, 동의 지문 무효화, 제약 밖 거부, 종료<시작, 예약 활동 확인 필요, leg 끊김, 미확인 고정, 429 구분.
- E2E(가상, 모의 provider): 미리보기에서 조사 질문 편집 → 전송 body가 편집값과 같음, 기록 선택, 요약 카드, 확인 필요 항목은 일괄 적용에서 빠짐. 기존 단언 약화 금지.
- `pnpm run check` exit 0. 전체 E2E는 GitHub CI로 갈음 가능.
- 스크린샷 `docs/design/ui-d01/`: 전송 미리보기, 요약 카드, 확인 필요·충돌 표시(모바일·데스크톱).
