## 1. C1 변환기 (화면 없음, 순수 함수)

위치: 새 폴더 `src/plan-import/`. 브라우저 API·DB에 의존하지 않는다(Node 단위 시험 가능).

| 함수(이름은 제안) | 입력 → 출력 |
|---|---|
| `parsePlanFile(text)` | 붙여 넣은 글 또는 파일 글(규격 §1: 코드 블록 찾기, 앞뒤 설명문·보이지 않는 글자 처리 포함) → 중간 구조 `{ header, days[], stays[], places[], deletions[], issues[] }`. 저장 스키마와 무관한 자체 타입 |
| `checkPlanFile(parsed)` | 중간 구조 → 오류·경고 추가(규격 §4의 날짜·시간·링크·숙소 검사) |
| `toNewTrip(parsed)` | 오류 없는 새 여행 파일 → `CreateTrip`에 넣을 `{ header, initialPlan }` |

요구:
1. 규격 §1~§4·§7을 그대로 구현한다. 열은 이름으로 읽는다. 오류는 `{ 줄 번호, 구역, 코드, 사람이 읽는 문장 }`으로 모으고, **첫 오류에서 멈추지 않는다**.
2. 오류가 난 표는 통째로 결과에서 빼고(일정은 날짜별) `issues`에 남긴다. 값을 조용히 버리거나 추측해 고치지 않는다.
3. 분류: 머리 줄에 여행ID 3줄이 있으면 `kind: 'update'`, 없으면 `kind: 'new'`. `update` 파일도 **해석·검사까지는** 한다(적용은 T-E2).
4. `## 이동`, 모르는 구역·열·머리 줄은 `notImported`로 모은다(구역 이름, 줄 수).
5. 시간: 규격의 4가지 표현만. 길이 0·역전·12시간 초과는 오류, 같은 날 겹침은 경고. 내부 시간 값은 기존 코드의 만드는 방식을 재사용한다(`src/content/quick-time.ts`·`TimeFields.tsx`·`trip-factory.ts`가 쓰는 함수). 새 시간 형식을 만들지 않는다.
6. `toNewTrip`: 날짜 행은 `buildNewTrip`(`src/content/trip-factory.ts`)과 같은 규칙으로 만들고 그 위에 활동·숙박을 얹는다. 가능하면 `buildNewTrip`을 호출해 재사용한다. 날짜 제목은 `### ` 줄의 그날 제목. 활동 순서는 표의 줄 순서. 장소 칸 값은 규격 §5-3대로 메모 앞에 `[장소: 값]`으로 남긴다(`placeLinks`는 빈 배열). 숙소는 `planStay`로. 결과는 `validateCommand`를 통과해야 한다.
7. 압축 코드 금지(AGENTS.md I-7). 함수는 작게, 이름은 뜻이 드러나게.

시험(`tests/plan-import-*.test.ts`):
- **고정 자료**: `docs/e0-results/`의 2회차 6개(`chatgpt-t1~3-run2.md`, `claude-t1~3-run2.md`)를 `tests/fixtures/plan-format/`에 복사해 쓴다. T1 2개는 오류 0건으로 `kind: 'new'`, 활동·숙소 줄 수가 파일과 같아야 한다(`## 이동`은 `notImported`). T2·T3 4개는 `kind: 'update'`로 해석되고 수정 줄·`(비움)`·삭제 줄이 중간 구조에 정확히 들어 있어야 한다.
- 1회차 자료(`chatgpt-t2-run1.md`, `claude-t3-run1.md`)는 **거부 또는 오류**가 나와야 한다(양식 줄 없음, 삭제 표 열 다름 등). 무엇으로 걸렸는지 단언한다.
- 입력 글: 같은 본문을 ① 그대로 ② ```` ```markdown ```` 블록으로 싸서 ③ 앞뒤에 챗봇 설명 문장을 붙여서 ④ CRLF·BOM·폭 없는 공백을 섞어서 넣어도 **결과가 같다**(AC-19). 양식 줄이 두 번 있으면 거부.
- 경계: 빈 시간, `HH:MM` 단독, `(+1)`, 길이 0, 역전, 겹침, 칸 안 `\|`, 열 개수 불일치, 빈 칸, 모르는 열, CRLF, 코드 블록으로 싸인 파일, 양식 줄 없음, 기간 밖 날짜, `http://` 링크, 새 여행 파일의 ID 값.
- 성질: 같은 글을 두 번 해석하면 결과가 같다.

**C1 중간 보고**: 고정 자료 8개의 해석 결과 표(파일 · kind · 활동/숙소/장소/삭제 수 · 오류 수 · 경고 수 · notImported)와 판단이 필요했던 규격의 모호한 곳 목록을 결과 문서에 적고 push한 뒤 멈춘다.

## 2. C2 AI 결과 붙여넣기 → 새 여행

위치: 여행 메뉴(`ContentApp.tsx`의 `trip-library` 영역, "새 여행" 옆)에 **"AI 결과 붙여넣기"**. 새 컴포넌트 파일로 분리한다(`ContentApp.tsx`에 본문을 넣지 않는다).

흐름:
1. 입력 두 가지, 같은 처리:
   - **붙여넣기(기본)**: 큰 입력 칸 + "클립보드에서 붙여넣기" 단추(`navigator.clipboard.readText`, 막히면 입력 칸에 직접 붙여 넣으라는 안내). iPhone Chrome에서 길게 눌러 붙여넣기가 되어야 한다.
   - **파일 선택**: `<input type="file" accept=".md,.txt,text/markdown,text/plain">`. 드래그는 필요 없다.
2. "미리보기" → 해석·검사 결과: 여행 이름·기간·시간대, 날짜별 활동 수와 목록(시간·제목·종류), 숙소, 경고, 오류(줄 번호·이유), 가져오지 않는 것(`## 이동` n줄, `## 장소` n줄 — "장소는 다음 단계에서 지원, 이름은 메모에 남깁니다").
3. "양식 아님"이면 사용자가 다음에 할 일을 알려 준다: "챗봇에게 '앱 양식의 코드 블록 하나로 다시 정리해 줘'라고 요청한 뒤 그 블록을 복사해 붙여 넣으세요."
4. `kind: 'update'` 글이면 저장 단추 없이 "기존 여행을 고치는 글입니다. 이 기능은 다음 단계에서 지원합니다"를 보여 준다.
5. 오류가 있어도 나머지를 저장할 수 있다. 단, **빠지는 표를 목록으로 보여 주고** 사용자가 확인란을 체크해야 저장 단추가 켜진다. 머리 줄 오류(양식·기간)면 저장할 수 없다.
6. "새 여행으로 저장" → `CreateTrip` 1회. 성공하면 그 여행으로 전환하고 결과(활동 n·숙소 n)를 보여 준다. 실패하면 아무것도 저장되지 않고 오류를 보여 준다.
7. 미리보기 상태와 붙여 넣은 글은 저장하지 않는다. 닫으면 사라진다. 같은 이름·같은 기간의 여행이 이미 있으면 저장 전에 "같은 이름의 여행이 있습니다. 새 여행으로 하나 더 만듭니다"를 확인받는다(기존 여행은 건드리지 않는다).
8. 네트워크 요청을 하지 않는다. 오프라인에서 동작해야 한다.

시험: 단위(미리보기 계산)와 E2E 2~3개(`tests/e2e/`) — `chatgpt-t1-run2.md` 글을 **입력 칸에 붙여 넣기** → 미리보기 수치 → 저장 → 일정 화면에 첫날 활동이 보임 → 다시 넣으면 7번의 확인이 나옴. 같은 글을 **파일로** 넣어 미리보기 수치가 같음. 양식 아닌 글은 3번 안내가 나오고 저장 단추가 없음. 오프라인 상태에서 붙여넣기.

## 3. C3 "AI로 계획 만들기" 요청문 생성

- 같은 화면(또는 "새 여행" 옆)에 **"AI로 계획 만들기"**. 입력: 여행지(글), 기간(시작·끝 날짜), 바라는 점(선택, 글). 인원·예산 같은 칸은 만들지 않는다(바라는 점에 적는다).
- "요청문 복사"를 누르면 아래 틀의 글을 클립보드에 넣는다. 복사가 막히면 글을 펼쳐 보여 준다. 여행은 이 단계에서 만들지 않는다(AI 결과를 붙여 넣을 때 만든다).

```text
{여행지}를 {시작} ~ {끝}에 여행하려고 해. {바라는 점}
나와 대화하면서 일정, 숙소, 식사, 이동을 함께 정해 줘. 내가 "정리해 줘"라고 하면 아래 양식으로 내 줘.

{양식 안내문}
```

- 양식 안내문은 [안내문](plan-format-v1-prompt.md)의 두 `---` 선 사이 글이다. **한 곳에서만 관리한다**: 빌드 때 그 문서에서 읽어 오거나(`?raw` 가져오기), 소스에 두고 문서가 그것을 가리키게 한다. 두 벌을 손으로 맞추지 않는다. 어느 쪽으로 했는지 결과 문서에 적는다.
- 안내문만 따로 복사하는 작은 단추("양식 안내문만 복사")도 둔다.
- 시험: 입력값이 요청문에 들어가는지, 바라는 점이 비면 그 문장이 빠지는지, 기간이 뒤집히면 막는지.

## 4. C4 기존 AI 변경안 적용 차단 (별도 커밋)

근거: [결정 11/13 16:49](decisions.md) 5번 — 기존 AI는 남기되 **AI 변경안의 적용만 막는다**.

- 대상: `origin: 'ai'` 변경안의 "적용"(`Workflows.tsx`의 `onApply` 경로). 단추를 끄고 "AI 변경안 적용은 개편 중이라 막아 두었습니다. 내용 확인과 거절은 가능합니다"를 보여 준다. `origin: 'user'`·`'import'`와 직접 편집은 그대로다.
- 조사·변경안 생성·보기·거절·작업 기록·패스키는 바꾸지 않는다. Worker는 바꾸지 않는다.
- 이 변경으로 깨지는 기존 시험은 **지우지 말고** "차단됨"을 단언하도록 고친다. 고친 시험 목록과 이유를 결과 문서에 적는다. 5개를 넘으면 멈추고 보고한다.
- 되돌리기 쉽게 차단 조건은 한 곳(상수 또는 함수 하나)에 둔다.

## 7. G-E1 사용자 확인 (병합 뒤, Codex가 안내)

PC와 iPhone Chrome에서: "AI로 계획 만들기"로 요청문 복사 → 챗봇(ChatGPT·Claude)에 붙여 넣고 가상 여행 계획 → "정리해 줘" → 답의 코드 블록 복사 → "AI 결과 붙여넣기" → 미리보기 확인 → 저장 → 일정 화면 확인. **iPhone에서 챗봇 앱의 복사 단추로 복사한 글이 그대로 읽히는지**가 핵심 확인 항목이다. AI 변경안 적용 단추가 꺼져 있는지 확인.
