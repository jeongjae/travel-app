# Claude Sonnet C단계 문서 보완 R1

2026-10-29 · **전달 준비 / 제품 구현 없음**

> [C단계 검토](phase-c-review.md)의 항목을 phase-c-design.md·phase-c-plan.md에 반영하세요.
> Sonnet이 필요한 코드/계약을 직접 조사하고 설계·계획을 정합하게 수정하세요. 제품 코드는 바꾸지 마세요.
> 최종20줄/2,000자 이내와 검토 항목별 반영 위치·남은 결정만 보고하세요.

- AGENTS.md와 현재 요구·결정 기준을 따른다. 기존 5개 탐색 축/보조 도구 구조를 정확히 기술한다.
- 최소 작성 범위와 연산·순서·트랜잭션/실패 경계·revision/replay/롤백을 구체화한다.
- 빈 여행 생성과 새 지역·장소·가이드 연결의 선후 참조를 계약 예시로 검증한다. 미구현 명령을 현 기능이라고 쓰지 않는다.
- 편집기·회고 UI 후보는 제안으로 둔다. 기존 호환 기본안과 새 사용자 정책 변경이 필요한 항목을 구분한다.
- T-C0/C1의 실제 검토 산출물과 T-C6→T-C7 의존을 보완한다. 대규모 책임 분리는 필수 선행이 아니다.
- SP-FR 원천 helper와 일반 수동 입력 규칙, 수동 저장과 AI 콘텐츠 변경안의 계약 경계를 구분한다.
- 작성자는 Claude, Codex 검토/사용자 확인은 대기로 적는다. 문서만으로 기능 검증 통과를 주장하지 않는다.
- T-05와 같은 체크아웃에서 동시에 수정하지 않는다. T-05 완료 후 같은 브랜치의 **별도 문서 커밋**으로 제출해도 된다.
- main 병합·배포·기존 DB/개인 자료 적용·API 호출은 하지 않는다. T-05 결과와 C 문서 결과를 각각 구분한다.
