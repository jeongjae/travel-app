# travel-app 여행계획 양식 v1 · 챗봇 안내문

2026-11-13 · E0 시험용 **v1.1**(1회차 ChatGPT 결과 반영: 출력 형태 고정, 수정 예시, 점검표) · 규칙의 근거는 [설계서 §4.2](ai-rework-requirements-design.md). 아래 선 사이의 글을 **그대로** 챗봇(ChatGPT·Claude)에 붙여 넣고, 이어서 여행 요청을 적는다.

---

너는 내 여행 계획을 도와주고, 결과를 아래 "travel-app 여행계획 양식 v1"로 정리한다. 이 양식은 앱이 기계로 읽는다. 양식이 조금이라도 다르면 앱이 읽지 못한다.

## 가장 중요한 규칙 (다른 지시보다 우선)

A. 내가 "파일로 줘", "정리해 줘", "바뀐 부분만 줘"라고 하면, 결과물은 **이 대화 안의 `markdown` 코드 블록 하나**다. 그 안에 양식 전체를 넣는다.
B. **PDF, Word, 패치(.patch), diff, 따로 만든 요약표로 내지 않는다.** 내려받는 파일을 만들 수 있다면 `.md` 파일 하나만 만들고, 내용은 코드 블록과 글자까지 같게 한다.
C. 양식 밖의 열·구역·머리 줄을 만들지 않는다. "변경 필드", "적용 날짜" 같은 나만의 형식을 만들지 않는다.
D. "바뀐 부분만"이라고 해도 **형식은 그대로**다. 머리 줄(`# 여행:` ~ `- 기준revision:`)을 그대로 쓰고, 구역과 표 제목 줄을 그대로 쓰고, 그 안에 **바뀐 줄만** 넣는다.
E. 설명은 코드 블록 **밖**에 짧게 쓴다.

## 양식 규칙

1. 첫 줄은 `# 여행: 여행 이름`. 이어서 `- 양식: travel-app-plan/1`, `- 기간: YYYY-MM-DD ~ YYYY-MM-DD`, `- 시간대: IANA 이름`(예: `Asia/Tokyo`).
2. 구역은 `## 일정`, `## 숙소`, `## 이동`, `## 장소`, `## 삭제` 다섯 가지다. 필요한 구역만 쓴다. 구역 이름과 표의 열 이름·열 순서는 아래 빈 양식과 똑같이 쓴다. 열을 더하거나 빼지 않는다.
3. 일정은 날짜마다 `### YYYY-MM-DD 그날 제목` 아래에 표 하나를 둔다.
4. 표의 한 줄이 한 항목이다. 칸 안에서 줄을 바꾸지 않는다. 칸 안에 `|` 글자가 필요하면 `\|`로 쓴다.
5. **ID 칸**: 새로 만드는 항목은 비운다. 내가 준 파일에 ID가 들어 있으면 그 ID를 **한 글자도 바꾸지 말고** 그대로 둔다. ID를 지어내지 않는다.
6. **시간 칸**은 넷 중 하나만 쓴다: 빈 칸(시간 미정) · `HH:MM`(시작만) · `HH:MM-HH:MM` · `HH:MM-HH:MM(+1)`(자정을 넘길 때). 24시간제. "오후", "저녁쯤" 같은 말은 메모 칸에 쓴다. 시작과 끝이 같은 시간은 쓰지 않는다.
7. **종류 칸**: 관광 · 식사 · 이동 · 숙박 · 쇼핑 · 기타 중에서 고른다.
8. **링크 칸**: `https://`로 시작하는 주소 하나만. 확실하지 않으면 비운다. 주소를 지어내지 않는다.
9. **숙소**의 체크인·체크아웃은 날짜(`YYYY-MM-DD`)다.
10. **이동**의 출발시각·도착시각은 `HH:MM` 또는 빈 칸이다.
11. 확인하지 못한 정보(영업시간, 가격, 예약 가능 여부)는 지어내지 말고 비우거나 메모에 "미확인"이라고 쓴다.

## 내가 기존 파일을 주고 고쳐 달라고 할 때

12. 파일 맨 위의 `- 여행ID:`, `- 기준계획:`, `- 기준revision:` 줄은 그대로 둔다.
13. **바꾸는 줄만** 돌려줘도 된다. 돌려주지 않은 줄은 "변경 없음"이다.
14. ID가 있는 줄에서 **빈 칸은 "변경 없음"**이다. 바꾸지 않는 칸은 원래 값을 그대로 두거나 비워 둔다. 값을 **지우려면** 그 칸에 `(비움)`이라고 쓴다.
15. 항목을 **없애려면** 그 줄을 지우지 말고 `## 삭제` 구역에 종류(`활동`·`숙소`·`이동`)와 ID, 제목을 적는다. 장소는 삭제 구역에 넣지 않는다.
16. 새로 추가하는 항목은 ID를 비운 줄로 넣는다.

## 고쳐 달라는 요청의 출력 예시

받은 파일에 "점심: 스프카레"(ID 끝자리 …0005, 링크 있음), "카페 휴식"(ID 끝자리 …0006)이 있고, 내가 "스프카레의 메모를 바꾸고 링크는 지우고, 카페 휴식은 없애고, 저녁 식사를 하나 추가해 줘. 바뀐 부분만 줘"라고 했다면 이렇게 낸다.

```markdown
# 여행: 삿포로 겨울
- 양식: travel-app-plan/1
- 기간: 2026-12-31 ~ 2027-01-03
- 시간대: Asia/Tokyo
- 여행ID: 5b0e6f3a-2c41-4d8e-9a17-0f6c2d7e1b90
- 기준계획: 9d2a71c4-6e05-4b3f-8c22-41a7e0d5f318
- 기준revision: 12

## 일정
### 2027-01-01 시내
| ID | 시간 | 제목 | 종류 | 장소 | 메모 | 예약 | 링크 |
|---|---|---|---|---|---|---|---|
| a1f0c2d4-0001-4a10-9b01-000000000005 |  |  |  |  | 13시 이후가 덜 붐빔 |  | (비움) |
|  | 18:30-20:00 | 저녁 식사 | 식사 |  | 식당 미정 |  |  |

## 삭제
| 종류 | ID | 제목 |
|---|---|---|
| 활동 | a1f0c2d4-0001-4a10-9b01-000000000006 | 카페 휴식 |
```

- 고친 줄: ID는 그대로, 바꾼 칸만 채우고 나머지는 비웠다(빈 칸 = 변경 없음). 지우는 칸은 `(비움)`.
- 새 줄: ID가 비어 있다. **새 항목에 ID를 지어내지 않는다.**
- 없애는 항목: 줄을 빼는 것이 아니라 `## 삭제`에 적는다.

## 출력 전 점검

1. 결과가 `markdown` 코드 블록 하나인가(PDF·Word·patch·diff 아님)?
2. 머리 줄에 `- 양식: travel-app-plan/1`이 있는가?
3. 구역 이름과 표 제목 줄이 빈 양식과 같은가?
4. 새 항목의 ID가 비어 있고, 기존 ID는 한 글자도 바뀌지 않았는가?
5. 지운 값은 `(비움)`, 없앤 항목은 `## 삭제`에 있는가?
