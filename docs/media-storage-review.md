# 이미지 파일 저장 방식 재점검

2026-10-22 검토 · 2026-10-23 OPFS 구현·실제 PC 검증 통과·G1 대기

> 사용자 후속 답변: ‘이미지는 사용자 앱 화면에서 보고 점검하면 된다. 데이터베이스 레벨에서는 직접 보고 관리하지 않는다’. 작성자는 OPFS 파일+DB 참조를 구현하고 가상 유실 회귀와 실제 미디어 46파일의 PC 조회·오프라인·백업/복원을 검증했다. 대응표 JSON도 같은 보관소에 둔다. 사용자가 OPFS 제품을 선택한 것으로 기록하지 않는다. [Phase 1 보고](phase-1-report.md)·[사용자 PC 확인](phase-1-pc-review.md)을 따른다. 아래는 선택 전 이력이며 iPhone은 여전히 미검증이다.

사용자 후속 답변은 **기기 파일과 링크를 뜻하며 적절성 재점검이 필요하다**는 것이다. 이전 ‘DB 바이트 저장과 같은 의도’라는 해석은 철회한다. 현재 P-06은 IndexedDB asset 바이트를 구현했지만, 이 사실을 새 저장 방식의 사용자 승인으로 간주하지 않는다. Phase 0에서 저장 구조를 바꾸지 않는다.

| 대안 | 파일·DB 역할 | 적합성·미확인 사항 |
|---|---|---|
| 사용자에게 보이는 일반 기기 폴더 + 참조 | 사용자가 파일 관리, DB는 자산 ID·파일 식별/권한 정보 | 사용자 의도에 직접적. 재실행 후 같은 파일을 계속 여는지, iPhone 권한·호환성·파일 이동·복원을 검증해야 함 |
| 앱 전용 파일 영역(OPFS) + DB 참조 | 바이트는 origin 전용 파일, DB는 해시·논리 경로·원천·권리 정보 | 파일과 DB를 분리하는 검토 후보. 일반 파일 앱에 보이는 폴더와는 다르므로 의도 충족 여부 재확인 필요 |
| 기존 IndexedDB asset 바이트 + DB 참조 | DB의 별도 레코드에 바이트 저장 | 현재 구현 재사용 가능. 사용자가 말한 일반 기기 파일과 같다고 설명하지 않음 |

OPFS는 origin 전용이고 사용자 파일 시스템처럼 보이지 않으며, 저장 공간 한도와 사이트 데이터 삭제의 영향을 받는다. OPFS를 별도 백업이나 기기 파일 앱의 폴더처럼 설명하지 않는다. [MDN OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system).

일반 파일 접근의 한 방법인 `showOpenFilePicker()`는 널리 쓰이는 모든 브라우저에서 지원되는 기능이 아니다. PC에서 가능하다고 iPhone Chrome의 영구 참조를 약속하지 않는다. [MDN 파일 선택기](https://developer.mozilla.org/en-US/docs/Web/API/Window/showOpenFilePicker).

표시용 `blob:` URL을 영구 자산 식별자로 저장하지 않는다. DB에는 안정된 ID/해시를 두고 표시할 때 보관된 파일/Blob에서 URL을 만들어 사용·해제하는 방식으로 검토한다. [MDN object URL](https://developer.mozilla.org/en-US/docs/Web/API/URL/createObjectURL_static).

## 추천과 결정 전 확인

추천은 **논리 자산 ID·해시·원천/권리는 DB, 바이트 위치는 저장 어댑터로 분리**하는 것이다. 일반 기기 폴더가 필수인지 먼저 정한 뒤, 파일 앱에서의 접근이 필수가 아니라면 OPFS를 우선 검토한다. 작성자 추천이며 선택·구현을 확정한 것은 아니다.

Phase 1 미디어 작업 전에 가상 이미지로 다음을 확인하고 결과를 제시한다.

1. 종료·재실행·오프라인에서 같은 파일을 다시 읽는가. iPhone 검증 전 지원 완료로 보고하지 않는다.
2. 백업 ZIP에 바이트·ID/해시·관계가 들어가 다른 빈 저장소에서 복원되는가. 절대 파일 경로만 백업하지 않는다.
3. DB와 파일 쓰기가 따로 실패할 때 참조가 깨지지 않도록 준비→검증→DB 참조 활성화→고아 파일 정리를 설계할 수 있는가.
4. 파일 유실·권한 상실·용량 부족·이름 변경 때 재선택/복구 흐름이 있는가.

검토가 끝날 때까지 [실행계획](development-plan.md)의 U-03은 저장 방식 결정 대기다. 필수 오프라인 첨부를 링크만 남기고 완료 처리하지 않는 기준은 유지한다.
