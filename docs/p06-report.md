# P-06 중간보고: 첨부·오프라인·전체 백업/복원

2026-10-22 · 대표 가상 구현·검증 완료. 실기기·실제 여행 전체 이행 완료 판정은 포함하지 않는다.

## 구현한 흐름

- 가이드의 **저장소·백업**에서 브라우저 사용량/한도·영구 보관 여부, 선택 여행의 현재·과거 첨부 준비 상태를 확인한다. 영구 보관 요청은 사용자가 버튼으로 실행하며 허용 여부를 그대로 표시한다.
- 첨부는 메타데이터나 `verified` 표시만 믿지 않고 실제 Blob 크기·SHA-256을 확인한다. 누락/손상은 안내하고, 검증한 로컬 패키지/백업에서 일치하는 바이트만 복구한다. 첨부 복구는 계획·본문·실제·업무 순번을 변경하지 않는다.
- 과거 첨부 누락 때문에 현장 기록까지 막히던 경계를 수정했다. 기존 첨부가 없어도 기록을 저장할 수 있고, 새 첨부 revision은 준비된 바이트를 요구한다. 불완전한 전체 백업은 완료로 표시하지 않는다.
- 짧은 DB 트랜잭션에서 activeSpaceId/cutSeq와 여행·콘텐츠·B·초안 heads를 고정한다. 이후 불변 이력은 200행 단위로 읽고, cutSeq 이후 새 계획/자식·편집·영수증을 제외한다. 쓰기 중에도 시작 시점의 백업을 만든다.
- 전체 백업 ZIP v2는 S-02~16의 15개 collection과 필요한 모든 과거 첨부를 보존한다. 계획·실제·정정·초안/결정·원천 패키지/B·명령 fingerprint/결과를 포함한다. 물리 spaceId, 준비 작업, 캐시, 서버 AI job, 환경 파일/키는 내보내지 않는다. 기존 v1 JSON 백업과 별도 경로다.
- ZIP 생성 후 입력 검증 경로로 완성 파일을 다시 읽어 확인한 뒤 저장 링크를 제공한다. ‘생성 완료’와 사용자의 외부 위치 보관 완료를 구분한다.
- 전체 복원은 v1/v2 여행이 없는 빈 저장소만 허용한다. 새 비활성 space에 200행 단위로 적재하고 행 지문·참조·B·영수증 결과·첨부 해시를 재검증한다. 마지막 트랜잭션에서 시작 space/순번과 빈 상태를 재확인한 후 activeSpaceId만 전환한다. 이후 순번은 cutSeq보다 크다.
- 같은 복원 job의 동시/반복 활성화는 한 번만 전환하고 완료 결과를 재사용한다. 원래 v2 성공 명령의 동일 입력 replay도 그대로 보존한다.
- 취소·오류·재시작 중 남은 비공개 작업을 목록으로 확인하고 재개/정리할 수 있다. 실패한 준비 때문에 기존 여행을 지우지 않는다. 임시 첨부 정리는 모든 현재·과거 revision과 다른 준비 작업의 참조를 보존한다.

구현 경계: `src/repository.ts`에서 내보내는 ContentRepository → `src/storage/recovery.ts`, 교환 검증은 `src/transfer/backup.ts`와 공통 `readArchive`, UI는 지연 로딩하는 `src/content/Recovery.tsx`다. 첨부 상태 조회는 선택 여행의 asset 인덱스만 읽는다. React 성능 지침을 적용해 무거운 화면을 상시 렌더링하지 않는다.

## 실행한 기술 판단

| 판단 | 실행한 추천안·근거/영향 |
|---|---|
| 첨부 축출 | 현재·과거에 참조된 파일을 자동 축출하지 않는다. 참조 없는 임시 파일만 정리하고 브라우저 자체 축출은 실제 바이트 검사/원본 파일 복구로 처리한다. |
| 누락 시 현장 입력 | 이미 존재하는 첨부 누락은 경고/백업 차단 대상이며, 현장 기록의 저장 전제에서 제외한다. 새 첨부 도입의 검증은 유지한다. |
| 복원 실패 | 준비 영역을 공개하지 않고 보존해 재시작 때 정리/재시도할 수 있게 한다. 저장 공간 부족 시 원본과 활성 포인터를 유지한다. |
| staging 변조 | 스키마상 유효한 값으로 바뀌어도 잡을 수 있도록 준비한 전체 행의 순서 독립 지문을 활성화 전에 재대조한다. |
| v1 원문 | v2 JSON을 완화하지 않고, v1 전환 보고서의 original에만 명시적 tagged codec을 적용한다. undefined와 누락의 차이·차단용 구형 영수증을 보존한다. |
| 포트 충돌 | 확장 권한으로 PID 27512가 현재 checkout의 `vite preview --host 127.0.0.1 --port 4173 --strictPort`임을 확인했다. 종료하지 않고 명시적 `TRAVEL_APP_REUSE_PREVIEW=1`로 테스트에서 재사용한다. 기본 설정은 계속 새 서버를 요구한다. |
| 브라우저 경로 | Browser plugin/`browser` skill이 제공되지 않아 프로젝트 Playwright를 사용했다. 휴대폰 실기기 검사로 바꾸어 부르지 않는다. |

위 선택은 이번 사용자의 기술 판단 위임에 따라 실행한 구현안이다. 새 제품 정책의 사용자 합의·호스팅/공개 범위 결정으로 기록하지 않는다.

## 검증

- 최종 `npm run check`: **108/108** 검사·TypeScript·프로덕션/PWA 빌드 통과. 기존 94 + P-06 12 + P-07 preflight 2다.
- P-06 신규 12검사: 편집/새 계획 생성 중 cutSeq 고정, 두 여행·모든 이력/B/영수증 복원·정확 replay, 빈 저장소/준비 중 새 여행 보호, 취소·재시작·미공개 정리, 모의 용량 부족/활성화 실패 원자 보존, 첨부 누락·동일 크기 손상/현장 기록/복구, 고아만 정리, 중복·cutSeq·참조 오류/유효한 staging 변조 거부, v1 undefined 원문 왕복, snapshot 정리, 405개 추가 기록의 페이지 경계·동시 활성화.
- `npm run test:e2e`: **30/30** 통과(PC 15 + 모바일 15). 기존 26 + 신규 4다. ZIP 다운로드/파일 재선택/빈 독립 브라우저의 오프라인 복원·재시작·이미지 표시, 첨부 바이트 축출 후 현장 입력/불완전 백업 차단/파일 복구/완전 백업을 확인했다. 화면 identity·본문 표시·console/pageerror·오버레이·가로 넘침 검사 통과. PC 1504×1040, 모바일 390×844; 뷰포트 스크린샷을 직접 확인했다.
- `npm run check:pilot`: native Node 계약·Python 3검사·별도 의존성 브라우저 번들 통과. `.venv/Scripts/python.exe -m pip check` 통과.
- 처음 기본 샌드박스의 기존 모의 AI 4검사는 임시 파일/loopback EACCES로 실패했다. 확장 실행에서 전체 통과했다. 실제 OpenAI 호출은 하지 않았다.
- 첫 신규 E2E는 여행 추가의 완료를 기다리지 않아 한 여행만 백업하는 표본 준비 오류를 발견했다. 미리보기 h3 대신 dialog 닫힘과 실제 h1을 기다리도록 고쳤고 전체 재통과했다. 추가 B 검증의 Zod refinement/omit 조합 오류도 수정해 재통과했다.

## 재현과 미검증

```powershell
npm run check
# 4173 소유가 이 checkout의 preview인지 확인한 경우에만 설정
$env:TRAVEL_APP_REUSE_PREVIEW='1'
npm run test:e2e
npm run check:pilot
.venv/Scripts/python.exe -m pip check
```

최종 코드 검증 결과는 [현재 인계](handoff.md)를 우선한다. 브라우저 검사의 원본 스크린샷/가상 백업은 OS 임시 `travel-app-playwright` 경로에 있고 실제 여행 파일을 저장소에 추가하지 않았다.

한도는 ZIP 256MiB, 해제 합계 512MiB, 단일 첨부 64MiB, 단일 행 512KiB, 레코드 파일 32MiB, 총 100,000행이다. DB 읽기/적재는 나누지만 ZIP 작성·입력 검증은 메모리에 바이트/행을 보유한다. 이 한도가 휴대폰에서 안전하다고 실측하지 않았다. 실제 브라우저 용량 고갈·OS 프로세스 강제 종료·iOS 파일 앱 보관·origin 이동·서비스워커 실제 업데이트·실기기 설치는 P-07에 남는다. 부분 재개는 ready job 활성화이며, loading 중단을 바이트 위치부터 이어 쓰는 기능은 제공하지 않는다. 실패 job 정리 후 원본 파일에서 다시 준비한다.
