# travel-app 목적지 가이드 양식 v1 (`travel-app-guide/1`) 규격

2026-11-16 · 작성: Codex 역할 세션 · 상태: **v1 초안(P1 구현 기준) — P0 통과본의 형식을 그대로 규격으로 옮김**
근거: [설계서](ai-rework-requirements-design.md) §4.8 · [P0 시험](p0-guide-trial.md) §6·§7 · [계획 준비 MVP 설계](travel-prep-mvp-design.md) §4.3과 [검토](travel-prep-mvp-design-review.md) · 챗봇에게 주는 글은 [요청문](guide-format-v1-prompt.md) · 예시는 [P0 결과](p0-results/g1-guide-hakodate.md)

가이드는 **고르기 위한 임시 자료**다. 가이드를 붙여 넣거나 항목을 골라도 여행 DB는 바뀌지 않는다. 장소·활동을 만들지 않는다.

## 1. 입력 글

[계획 양식 규격](plan-format-v1.md) §1·§9와 **같은 규칙**을 쓴다: 붙여 넣은 글 또는 `.md` 파일, 보이지 않는 글자 처리, 코드 블록이 있으면 블록 안만 후보, `- 양식:` 줄이 정확히 한 번, 표만 읽음. 양식 값은 `travel-app-guide/1`. 계획 양식(`travel-app-plan/1`)의 글이 들어오면 "이것은 계획입니다. AI 결과 붙여넣기에 넣으세요"로 안내한다(반대도 같다).

## 2. 머리 줄

| 줄 | 필수 | 비고 |
|---|---|---|
| `# 가이드: 목적지` | 필수 | 목적지 이름 |
| `- 양식: travel-app-guide/1` | 필수 | 없거나 다른 값이면 거부 |
| `- 기준일: YYYY-MM-DD` | 선택 | 챗봇이 글을 쓴 날이다. **검증한 날이 아니다.** 형식이 틀리면 경고 |

## 3. 표

구역은 `## 항목` 하나, 표 하나. 열은 **이름으로** 읽는다(순서 무관). 모르는 열은 읽지 않고 "가져오지 않음"으로 보여 준다.

| 열 | 필수 | 규칙 |
|---|---|---|
| 종류 | 필수 | `볼거리` · `먹거리` · `체험` · `코스` · `지역` 중 하나. 다른 값은 오류 |
| 이름 | 필수 | 비어 있으면 오류 |
| 지역 | 선택 | |
| 한 줄 설명 | 선택 | 코스는 "A → B → C" |
| 예상 소요 | 선택 | 글 그대로 보여 준다. 숫자로 바꾸거나 합산하지 않는다 |
| 확인 필요 | 선택 | 글 그대로 보여 준다 |

- 한 줄 = 한 항목. 칸 안 줄바꿈 금지, `|`는 `\|`. 열 개수가 제목 줄과 다른 줄, 값 오류가 있는 줄이 하나라도 있으면 **가이드 전체를 받지 않고** 줄 번호·이유를 보여 준다(일부만 받지 않는다).
- 같은 `종류+이름+지역`이 두 번 나오면 경고하고 둘 다 보여 준다(합치지 않는다).
- 항목 수 상한 200줄, 글 상한은 계획 양식과 같다.
- 줄 순서가 처음 보여 주는 순서다.

## 4. 고른 상태와 요청서

| 상태 | 요청서에 들어가는 묶음 |
|---|---|
| 고르지 않음(기본) | 들어가지 않는다 |
| 꼭 포함 | `[꼭 포함]` — "반드시 넣어 줘. 어렵다면 이유와 대안을 알려 줘" |
| 관심 | `[관심]` — "동선과 시간이 맞으면 넣어 줘" |
| 제외 | `[제외]` — "넣지 말아 줘" |

- 요청서의 항목 표기: `종류 / 이름 / 지역`(지역이 비면 뺀다). 고른 항목의 `확인 필요`는 `[확인할 것]` 묶음에 `이름: 확인 필요`로 모은다.
- "꼭 포함"은 예약·방문 확정이 아니다.
- 화면에는 `AI가 만든 가이드 · 내용은 확인되지 않았습니다`를 항상 보여 준다.
