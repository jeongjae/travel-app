### 수정 지시 R1 — 추가·날짜 이동 활동을 시간순 자리에 넣는다

브랜치 `codex/e02a-r1-order`(main 기준). 범위: `src/plan-update/`와 그 시험, `UpdatePreview.tsx`의 안내 한 줄. 데이터 경계 0건, `ChangePlan` 1회 유지.

용어: "끼우는 활동" = 고른 변경 중 새 활동(`add`)과 날짜를 옮긴 활동(`move`)이 그 날짜에 들어오는 것. "기존 활동" = 그 날짜에 원래 있고 삭제를 고르지 않은 나머지.

1. **자리 규칙**(날짜별로, 고른 변경을 모두 반영한 뒤 계산한다):
   - 기존 활동끼리의 순서는 바꾸지 않는다(이미 시간순이 아니어도 그대로 둔다).
   - 시작 시각이 있는 끼우는 활동은, 기존 활동을 지금 순서대로 보다가 **자기보다 시작 시각이 늦은 첫 기존 활동의 바로 앞**에 넣는다. 그런 활동이 없으면 맨 끝. 시간 미정인 기존 활동은 비교에서 건너뛴다(자리는 그대로).
   - 시간 미정인 끼우는 활동은 맨 끝.
   - 같은 자리에 여럿이 들어가면 시작 시각순, 같으면 글의 줄 순서.
   - 시각 비교는 날짜를 포함한 시작 시각으로 한다(자정을 넘긴 활동은 그날의 늦은 쪽).
2. **계산 위치**: 순서는 `computeUpdate`가 아니라 **고른 뒤**(`buildSelection`)에 정한다 — 일부만 고르면 고른 것만으로 자리를 정한다. `order`는 정수라 뒤의 기존 활동 번호가 밀린다. 번호가 실제로 바뀌는 기존 활동만 `upsert-item`으로 더하고, 같은 글에서 수정도 고른 활동이면 연산 하나로 합친다(한 대상에 연산 2개 금지 — 재검사가 막는다).
3. **미리보기**: 번호만 밀리는 기존 활동은 "수정" 수와 적용 사유의 개수에 넣지 않는다. 적용 단추 근처에 "순서 조정 n건(기존 활동의 내용은 바뀌지 않습니다)"을 보여 준다. 끼우는 활동에는 "○○ 앞에 들어갑니다" 또는 "그날 마지막에 들어갑니다"를 붙인다.
4. **바꾸지 않는 것**: 내보내기 → 그대로 가져오기 = 변경 0건(AC-04). 제자리 수정(날짜가 같은 `edit`)의 순서. 이동(leg)·숙소. 재검사 항목.
5. **[사용자 확인 대기 — 답이 올 때까지 구현하지 않는다]** 시간 칸만 바뀐 기존 활동(날짜는 같음)도 시간순 자리로 옮길지.
6. 시험(단위): 가운데 끼우기 / 늦은 활동이 없어 맨 끝 / 시간 미정은 맨 끝 / 같은 날 둘 이상 / 시간순이 아닌 기존 날짜에서 기존 순서 보존 / 일부만 고르기 / 추가와 삭제를 함께 / 날짜 이동 / 번호가 밀린 활동을 같은 글에서 수정(연산 1개) / 실제 저장소 적용 뒤 순서 확인. E2E 1건: 12:00 활동을 추가해 적용하면 일정 화면에서 오전·오후 활동 사이에 보인다.
