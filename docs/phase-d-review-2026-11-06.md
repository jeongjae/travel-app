## 2. 해석 — Codex 의견

1. **범위(U-D5)는 제안대로가 맞다.** AI는 "기존 일정의 항목 단위 조사·근거·검증 보조"로 두고 전체 일정 자동 생성은 D-X. 확인 두 번(전송 동의 / 적용 승인), 채팅 UI 미채택, 변하는 사실 '미확인' 고정은 유지할 가치가 크다.
2. **개인용 앱에 비해 설계가 무겁다.** 다중 사용자 작업 소유권, 금액 예약·정산 원장, 서버 강제 종료 훈련 등은 기업 서비스 수준이다. 사용자 1명·기기 1~2대 기준으로 줄이면 작업 8개 → 약 5개로 줄일 수 있다.
   - 인증: 다중 사용자 소유권 → 본인 1명 인증. 단, "무인증으로 비용이 나가는 경로 없음"은 유지.
   - 비용: 자체 예약·정산 원장 → 공급자(OpenAI) 쪽 프로젝트 예산 한도 + 요청당 토큰 상한 + 앱의 사용량 표시. 공급자 한도가 실제로 호출을 막는지(알림만인지)는 착수 시 공식 문서로 확인하고, 막지 않으면 앱 쪽 일일 한도를 둔다.
   - 복구: "응답 유실 시 자동 재호출 금지 + 결과 불명 표시"만 핵심으로 두고 강제 종료 훈련(T-D5)은 모의 시험으로 축소.
3. **운영 경로(U-D1)가 실제 병목이다.** 지금 배포 앱은 정적 사이트(GitHub Pages, 서버 없음)라 AI 서버를 어디에 둘지 정해야 한다.

| 후보 | 장점 | 단점 |
|---|---|---|
| A. 집 PC 서버 + 비공개 원격 접속 | 비용 거의 없음, 현 Node 서버 그대로 | 여행 중 PC 전원·네트워크 유지 필요. 꺼지면 AI 불가 |
| B. 관리형 서버에 앱+API 함께 | 이동 중 안정 | 호스팅 비용·운영. **주소(origin)가 바뀌어 기존 브라우저 저장 여행이 자동으로 따라오지 않음** → 백업·복원 이행 필요 |
| **C′. 지금 Pages 유지 + 작은 AI 프록시(예: Cloudflare Worker)** | 주소가 그대로라 기존 여행 데이터 이행 불필요. PC 꺼져도 동작. 사용자가 Worker 배포 경험 있음 | 현 Node 서버(파일 기반 작업 저장)를 옮겨야 함. 실행 시간·저장소 제약에 맞춘 비동기 설계 필요. 다른 주소 간 호출이라 인증·CORS 설계 추가 |

   Codex 권고: **C′를 우선 검토**(데이터 이행 위험이 가장 작다). A는 시험용으로만 적합.
4. **iPhone 실기기 확인을 D 앞으로 당기기를 권한다.** D 종료 조건이 "확정 휴대폰 환경"인데 아직 한 번도 실기기에서 보지 않았다. iPhone 브라우저 저장소가 일정 기간 안 쓰면 지워질 수 있는지(홈 화면 추가 여부 포함) 같은 위험은 AI보다 먼저 드러나야 한다. 비용 없이 30분 안팎.
