# T-D1 결과 · AI 전송 최소화·동의·의미 검증

2026-11-06 · 기준 main `c678390` · 브랜치 `codex/d01-send-semantics` · **R1~R4 수정 반영 / Claude 자체 검사 완료 / Codex 검토 대기 / 사용자 미확인**

## 요약

1. **G1~G8, G10, G15, G18과 수정 지시 R1~R4를 반영했다.** 로컬 Node 서버와 모의 provider 기준이며 OpenAI 실제 호출과 키 사용은 없다.
2. **전송:** 조사 호출에 요청 원문이 가지 않는다. 작성 호출은 허용 목록이고 표식 전수 시험으로 허용 밖 값 0을 단언한다.
3. **동의:** 내용·서버·모델·한도 지문에 묶이고, 지문이 다르면 서버가 400으로 거부한다.
4. **시간 검증:** 도착 전·출발 후·이동 구간·고정 활동과 겹침을 거부한다. 야간 일정은 12시간 이내로 허용한다.
5. **표시와 전송:** 도착·출발 입력의 화면 값이 곧 전송 값이다. 비우면 키가 없다.
6. **보관:** 요청 원문·고른 기록·활동 요약을 작업 저장소와 조회 응답에서 뺐다(§R3 표). AI 출력은 남는다.
7. **카드:** 항목별 사유, 출처 종류·개수, 확인 시각, 영향을 보여 준다. 변하는 사실은 공식 출처와 확인 날짜가 없으면 미확인이다.
8. **확인 필요:** 예약 활동의 시각 변경·제거는 따로 체크해야 적용된다. 표시는 활동 ID에 묶이고 revision이 바뀌면 지워진다.
9. **저장 스키마·저장 명령 변경 0건.** 절충 3건은 §3에 있다.

**검사:** `pnpm run check` exit 0(395건 중 394 통과·1 건너뜀). AI·통합·회고 E2E 26개 로컬 통과. 원격 CI 결과는 보고에 적는다.

**Codex가 먼저 볼 곳:** §정정, §R3, §3, §4, §5.

## 정정 (16:20 보고)

- **이동 시각은 해석 차이가 아니라 결함이었다.** 16:20 보고는 "지침과 다른 해석"으로만 적었다. 실제로는 장거리 이동이 하나인 날 도착이 출발보다 늦어져, 시각이 있는 제안이 모두 거부되고 유료 보정 호출이 낭비됐다.
- **보관 범위 확대를 적지 못했다.** T-D1이 요청 원문과 고른 기록을 `jobs.json`에 새로 남겼는데 16:20 결과 문서에 없었다(§R3).
- **화면과 전송이 달랐다.** 입력을 비워도 추정값이 전송됐다.

## 2. 계약·구조 변경

`src/ai-v2-contract.ts` 변경 목록:

- 요청: `context`와 `consent: true`를 없애고 `scope`·`research`·`planning`·`consent{server, model, limits, fingerprint}`로 나눴다. `scope`는 OpenAI로 가지 않는다.
- 출력: 항목에 `reason`, 근거에 `checkedAt`·`operationIndexes`를 더했다. 근거 최대 20건을 19건으로 줄였다(사유 행 1건 몫).
- 작업 결과: 완성된 변경안 대신 `{output, sources, scope, warnings}`. 작업에 `usage`를 더했다.
- 작성 DTO: 날짜의 `arrival`·`departure`·`blocked`는 값이 없으면 키가 없다. `followingDay{date, firstStart, arrival}`를 더했다.

**변경안 완성이 브라우저로 옮겨졌다.** 서버가 받지 않은 필드(`officialUrl`, `taskRefs` 등)를 보존하려면 전체 활동을 아는 쪽에서 완성해야 한다. `materializeV2Proposal`을 `src/ai-v2-semantics.ts`로 옮겼고, 서버와 브라우저가 같은 `validateAiV2Output`을 쓴다. 재회수가 중복 저장되지 않도록 현재 시각 대신 작업 완료 시각을 쓴다.

**시험 변경(약화 여부 검토 요청):**

- "여행·계획 불일치" 시험은 요청 안의 중복 `tripId`가 사라져, 없는 날짜 참조와 여행 범위 밖 날짜 시험으로 바꿨다.
- 기록 전체 전송 단언은 지침에 따라 고른 기록만 전송으로 바꿨다.
- E2E 모의 라우트의 `records = []` 단언은 기록 선택 시험과 공존하도록 개별 시험으로 옮겼다.

## 4. 지침과 다르게 해석한 곳

- **도착·출발(사용자 결정 D-2로 추정 유지):** 이동에 시각 필드가 없어 장거리 이동의 양 끝 활동 시작 시각으로 얻는다. 그날 첫 활동에서 떠나면 도착, 앞에 활동이 있고 마지막 활동으로 끝나면 출발, 그 밖은 이동 구간만 막는다.
- **지시서보다 더한 것:** 이동 구간은 입력칸이 없어 잘못 얻어도 지울 수 없으므로 날짜별 "이동 구간 제약 끄기"를 넣었다.
- **`followingDay`:** 자정을 넘는 제안을 선택 범위 밖 다음 날과 비교하려고 **그날의 날짜·첫 시각·도착 시각을 새로 보낸다.** 제목과 내용은 보내지 않는다. 미리보기 상세 JSON에 보인다.
- **고정 활동:** `bookingIds`가 있는 활동만 고정으로 본다. 시각이 없는 예약 활동은 겹침 검사 대상이 아니다.
- **변하는 사실 판정:** 낱말 목록으로 찾으므로 놓치거나 과하게 잡을 수 있다.
- **확인 시각:** 공식 출처가 밝힌 날짜만 "확인"으로 표시하고, 나머지는 "수집 … (확인 시각 없음)"으로 표시한다.

## 5. 미검증

- 실제 OpenAI 응답과 새 출력 스키마의 호환(strict 구조화 출력 포함). 실제 호출이 없다.
- 실제 여행 데이터의 필드 내용과 요청 크기, 추정 규칙이 실제 일정에 맞는지.
- iPhone 실기기.
- E2E는 서버를 `page.route`로 모의한다. 로컬 Node 서버의 HTTP 경로는 단위 시험으로만 지난다.
- 재적용 중 실패 경로(R4)는 화면에서 일으키기 어려워 단위 시험으로만 검사했다.
