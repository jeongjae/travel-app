## 요약

- 예정 외 활동에 같은 여행의 활성 장소를 고르거나 장소 없이 기록하고, 실제 기록 화면에서 찾아 읽고, 추가식으로 정정하며, 장소 이름·본문이 바뀐 뒤에도 기록 당시 장소 내용을 읽는다. 재실행·오프라인·두 여행 전체 백업→빈 브라우저 복원 뒤에도 같다. 모두 가상 입력이며 사용자 DB·iPhone·실제 ZIP·main·배포·API는 건드리지 않았다.
- 새 명령·스키마·commandVersion 변경 없음. 기존 RecordActual/CorrectActual/AddNote와 ActualEditor/타임라인을 재사용했다.

## 기존 기능과 보완 범위

| 공백(보완 전) | 보완 |
|---|---|
| 예정 외 활동에 장소 선택 없음 | 일정 항목에 연결되지 않은 기록에 "기록할 장소"(활성 장소·장소 없음) 선택 |

| 저장 경계가 새 장소 연결을 검증하지 않음 | `src/storage/field-guard.ts`(`guardActualRecord`) |
| 재시도마다 새 requestId·recordId | 폼을 연 시점에 recordId 고정, `reuseRequest`로 같은 입력은 같은 요청 ID |
| 정정 체인이 타임라인에서 이어지지 않음 | "정정 n/m단계 · 최신 정정본/이후 정정본 있음 · 정정한 이전 기록·이후 기록 제목" |

## 참조·정정 결정

- 새로 연결하는 장소: 이 여행의 **활성** 장소이고 기록 맥락이 그 장소의 **현재 head revision**을 고정해야 한다(없는/비활성/다른 여행/오래된 revision 거부). 정정에서 이미 연결된 장소를 유지할 때는 나중에 비활성이 되어도 허용한다.
- 정정: 원본의 `planVersionId/activityId`와 `sourceRefs`를 바꾸면 거부. 이미 정정된 원문 재정정은 기존 규칙으로 CONFLICT. 오래된 domain revision은 기존 규칙으로 CONFLICT(폼은 입력을 남기고 "입력한 내용은 그대로 남아 있습니다…" 안내).
- 정정에서 장소를 바꾸면 원본 맥락을 유지하고 새 장소의 현재 revision을 더한다(원본에 없던 연결 대상은 현재 head에서 보충, 있던 항목은 당시 revision 유지). 원본 기록은 수정되지 않는다.
- 일정 항목에 연결된 기록에는 장소 선택을 두지 않는다. 장소 없이 기록해도 계획 항목을 만들지 않으며 장소·날짜·시각을 추정해 확정하지 않는다(시각은 기본 "시각 미상").
- 새 장소가 필요하면 "새 장소 먼저 저장"→C-01 장소 작성(별개 저장)→저장하면 기록 폼으로 돌아와 입력(이름·메모·결과·시각)이 이어지고 새 장소가 선택된다. 장소 작성을 닫아도 기록 폼으로 돌아온다. 폼 복귀 시 최신 domain revision·맥락을 다시 읽는다.

## 사용자가 볼 산출물·확인 동작

`pnpm run build && pnpm run preview:ui` → `http://127.0.0.1:4173/?workspace=content`, 새 프로필/빈 검토 공간에서만. 가상 입력 예: 여행 2032-06-01~03, 지역 "가상 지역", 장소 "가상 카페".
1. `실제 기록`(더 보기 안) → `예정 외 활동 기록` → 활동 이름·`기록할 장소` 선택(또는 장소 없음)·메모 → 저장.
2. 목록 카드에서 "장소 · … (기록 당시 이름)", `기록 당시 내용`(당시 고정 내용), `정정` 두 번 → "정정 n/m단계" 확인. 장소 이름을 `가이드`에서 바꾼 뒤 다시 확인.
3. `새 장소 먼저 저장`으로 장소를 만든 뒤 기록 폼에서 이어 저장.
스크린샷은 따로 만들지 않았다(시험·로그가 증거). 모바일은 Playwright(Pixel 7) 에뮬레이션이며 iPhone 실기기 확인은 아니다.

## 미검증·한계·경미한 발견 (Codex 관리 후보)

- 사용자 화면 확인·Codex 독립 검토·iPhone 실기기 확인 대기. 원격 CI는 push 후 사용자 보고에 기재.
- 일정 항목에 연결된 방문/건너뜀 기록은 장소를 바꿀 수 없다(항목의 장소 연결을 따름). 정정에서 장소를 비우는 것은 예정 외 기록에서만 가능.
- 정정에서 시작 시각만 바꾸면 기존 종료 시각을 그대로 두며, 역전은 계약 검증이 거부한다. 종료 시각 편집 UI는 없다(보존만).
- 기록 목록의 시간 그룹은 각 기록의 시작 시각 기준이며 정정본과 원본이 다른 그룹에 놓일 수 있다. 연결 문구로 이어 읽는다.
- 새 장소 선행 저장 뒤 기록 저장이 실패해도 장소는 남는다(지시대로 별개 저장). 폼은 오류와 입력을 유지한다.
- 구버전 앱이 새 기록/가이드가 든 백업을 못 읽을 수 있는 배포 순서 문제는 C-01에서 지적한 그대로다. CL-08 DST 계산은 바꾸지 않았다. T-C6 회고·사진/지출·GPS·AI는 범위 밖.
- 상위 설계/계획/후속 목록은 수정하지 않았다. 제안: T-C5 항목(장소 선택/없는 기록·정정 전후·오프라인 재조회) 해소로 기록, "기록 당시 내용"의 임의 장소 열림은 이번에 수정함을 변경 이력에 남길 것.
- 미추적 `docs/status-review-2026-10-26.md`는 그대로다. main 병합·배포·실제 자료 적용·API 호출 없음.
