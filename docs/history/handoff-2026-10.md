## 최신 후속 상태 · AI 연결 완료

최종 빌드는 JS를 framework/data/time/app 청크로 분리했으며 최대 청크 약 219 kB, 앱 셸 프리캐시 14개·약 615 KiB다. 브라우저 테스트 산출물은 시스템 임시 폴더 `travel-app-playwright`에 둔다. 스크린샷은 세션 visualization 폴더에 보관하고 실제 데이터·실패 trace를 Git에 포함하지 않는다. `.env.local`의 키가 dist에 포함되지 않는지 값 출력 없이 검사한다.

## 아직 구현하지 않은 것과 제품 결정

**로컬 AI 흐름은 구현됐지만 공개 배포·실기기 여행 사용까지 완료한 것은 아니다.** 실제 웹 조사·모델 호출·검증 보정·작업 상태·실패/중단/재시작·초안 저장을 연결했다. 모의 검증과 실 API 검증은 위 표처럼 구분한다. 서버 재시작 시 진행 작업을 무단 재호출하지 않고 중단 상태로 복원하며, 재시도는 사용자가 최신 컨텍스트로 실행한다.

후속 사용자 답변으로 확정된 항목:

1. 개인용·모바일 우선.
2. 오프라인 일정 조회·현장 기록 저장·백업 제공. 기기 간 자동 동기화는 첫 MVP 제외.
3. 앱 내부 AI 실행, 모든 변경안 확인 후 적용. OpenAI API의 새 키 안전 생성을 선택했다. 서버 실행 위치·호스팅·모델·예산 한도는 미정.

### API 키 생성·로컬 저장 이력

첫 Platform `Codex` 키 발급 뒤 기본 임시 디렉터리 파일이 다음 실행에서 없어 로컬 저장이 실패했다. 사용자가 재시도를 승인한 후 프로젝트의 무시 경로에 보관한 보안 도우미 상태로 새 키를 생성하고 `.env.local` 저장에 성공했다. 선택 프로젝트는 `Default project`, 만료 값 미지정(임의 만료 추가 없음)이었다. 현재 키는 모델 접근·실제 생성으로 검증했다. 원문은 출력하지 않는다.

향후 새 키 설정에서도 보안 도우미 `prepare --dir <프로젝트의 무시 경로>`로 실행 간 상태를 유지하고 공개 JWK만 전달한다. 첫 저장 실패 키의 폐기만 남아 있으며, 새 키를 다시 발급할 필요는 없다. 사용 후 임시 RSA 디렉터리는 제거했다.

실제 AI 결과 가상 픽스처는 `.cache/ai-smoke-result.json`, `.cache/ai-live-demo-import.json`에 있으며 사용자 실제 데이터가 아니다. 이 파일들을 커밋하지 않는다. 서버의 완료 작업은 `local-data/ai-jobs/jobs.json`에 저장된다. 해당 파일도 Git에서 제외된다.

기타 미검증: 실제 SP-FR 43일 전체 가져오기(원본 재배포 대신 구조에 맞춘 가상 카드로 검증), 원본 수집 CLI의 사용자 실제 체크아웃 실행, iOS/Safari·Android 설치·실기기, 저장소 정리/용량 초과·OS의 브라우저 데이터 축출, 다른 기기 동기화, 실제 예약·지도·결제·사진·지출, 원격 CI·배포. 백업은 암호화되지 않은 로컬 다운로드다. 이동 한 활동의 출발/도착 시간대 동시 표시는 초기 범위 밖이다.

## 다음 세션

1. `git status`, 이 문서와 제품 결정 답변을 확인한다.
2. 위 확정 정책과 현재 키를 유지한다. 첫 저장 실패 키 정리가 필요한 점을 구분한다.
3. 휴대폰에서 접근할 서버·인증·호스팅·예산 한도를 사용자에게 구체적인 선택지로 제시한다. 실제 배포는 별도 승인된 범위에서 수행한다. 로컬 서버가 공개 운영 준비됐다고 가정하지 않는다.
4. 실제 원본을 사용자가 보유한 로컬 체크아웃에서 묶어 미리보기·검증한다. 예약·사진 재배포와 원본 수정은 하지 않는다.
5. 이후 필요한 원격 커밋/push·배포 범위를 구분하여 진행한다.
