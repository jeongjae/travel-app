## 최신 계획 · 전략 정의 후 단계별 이행

사용자가 구현을 다른 세션에서 시작하도록 지정했다. 새 세션의 [인수인계 지시서](../../IMPLEMENTATION_HANDOFF.md)에 따라 P-01부터 구현·검증한다. 이 세션에서는 계획·인계 문서만 작성했으며 하단은 과거 프로토타입 구현 이력이다.

이행의 중심은 파일/코드 내부 콘텐츠의 DB화와 정적 페이지의 공통 프로그램 전환이다. 원천 콘텐츠→DB 필드/관계→공통 화면의 대응과 기술 선정안·저장/파일 계약·대표 구간 검증 계획을 작성했다. 다음 실행 단위는 P-01이다. AI 등 신규 확장과 상세 이력 고도화가 이 중심 작업을 대신하지 않는다.

1. 최종 목표·이행 완료 기준: `goal-and-migration-criteria.md` v0.5. 콘텐츠 DB화·공통 프로그램 전환, 이행 수준·콘텐츠 편집·여행별 독립 사본·이행 후 앱 중심 편집은 사용자 확정, 세부 판정 조건은 검토안.
2. 기존 기능·콘텐츠 분류: `migration-inventory.md` v0.3. 기존 본문 편집은 이행, 새 가이드 작성과 내장 지도 조작은 후속, 지도 목록·링크 우선, 저장소 원본만 이행으로 사용자 답변 반영 완료. 파일별 상세 조사와 원천→DB→공통 화면 대응이 남아 있음.
3. 공통 데이터 구조·원본/편집 책임과 기술 대안 설계: `target-architecture.md` v0.3 검토안 작성. 여행별 독립 사본과 이행 후 travel-app 중심 편집은 사용자 확정. 중심 목표와 논리 엔티티·이력·미정 시각·재가져오기·트랜잭션·첨부/백업 경계를 제안하고 프로토타입 재사용 대안을 비교했다. 아래 대응·기술 선정안을 작성했으며 물리 스키마·명령/파일 계약과 대표 구간 계획은 다음 구체화 대상.

   - 원천/화면 대응: `content-db-mapping.md` v0.1에 D-01~23 논리 구조, P-01~25 필드·코드 콘텐츠 대응, V-01~11 조회/저장 계약과 두 가상 여행 예시를 작성했다. 실제 DB화·화면 구현·테스트는 미실행이다.

4. 대표 구간의 전체 흐름 이행·검증: 미착수. 원본 보호, 의미/수량/참조 대조, 다른 여행 적용과 오프라인·복원 검증.

## 과거 프로토타입 구현 이력

## 1. 기반과 작은 전체 흐름 (현재 구현)

프로젝트 전용 npm 의존성·lockfile·고정 Node 버전·고정 로컬 포트. 도메인 타입·외부 입력 검증 → IndexedDB 트랜잭션 저장소 → 여행·계획·실제 기록·변경안 UI → SP-FR 변환·백업 → PWA 앱 셸 순서.

검증: Vitest로 여행 격리·실제 기록 보존·정정·충돌·중복 적용·부분 실패·복원·DST/자정 확인. Playwright로 모바일/PC 핵심 흐름, 재로드, 다른 탭 변경, PWA 오프라인 재시작 검증. 단순 빌드 통과를 데이터 보존 또는 AI 통합 완료라고 하지 않는다.

## 2. 사용자 정책 답변 반영

사용자 확정: 개인용·모바일 우선, 오프라인 조회·현장 기록·백업, 앱 내부 OpenAI API 실행, 모든 변경안 확인 후 적용. 서버 호스팅·모델·예산 범위는 후속 결정이다. 키 생성 후 로컬 저장 실패 상태는 handoff를 확인한다.

## 3. AI 반복 실행

외부 실행기를 실제 저장 경로에 연결한다. 사용자 판단 전까지 조사·초안·검증을 자동으로 반복하고, 필요할 때만 결정 대기로 멈춘다. 오래된 컨텍스트나 실패는 최신 상태로 재시도하되 이중 적용하지 않는다. 앱 내부 AI는 서버와 인증·비용·키 보관 결정 후 구현한다.

로컬 개발 구현 완료: Node 서버의 웹 조사→구조화 작성→검증/보정→브라우저 초안 자동 저장, 매 변경안 확인 적용. 상태·중단·중복 방지·서버 재시작 표시와 실제 제공자 1회 검증 완료. 서버 호스팅·공개 인증·실기기 사용은 다음 단계다.

## 4. 확장

실제 기기 여행 테스트 → 필요에 따라 서버·계정·동기화 → 사진/지출/지도. 공개 배포·원격 push는 별도 수행 상태로 기록한다.
