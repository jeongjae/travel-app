# Claude Sonnet T-05 R2 · 비교 검증 보존·계획 UI 증거

2026-10-29 · 기준 `08dde96` 이후 Codex 검토 문서 커밋 · **전달 준비 / 구현 미착수**

R1의 구버전 패키지 호환 P1은 해결됐다. [재검토](claude-task-05-review.md)의 두 항목만 마무리한다.
Sonnet이 조사·수정·검사·증거·커밋/push까지 수행하고 최종 20줄/2,000자와 증거 색인으로 제출한다.

1. `canonicalPlanValue`가 days/items/legs/stays 외의 필드를 지워 기존 기준 B 불일치를 숨긴다.
   `.cache/t05-codex/zz-codex-t05-extra-field.test.ts`를 읽고 정식 가상 회귀로 옮겨 수정 전 실패를 확인한다.
   기존 기준 배열 순서만 정규화하고 추가/미지원 필드는 보존 비교하거나 명시적으로 거부한다.
   패키지 bytes/digest·provenance·DB baseline·과거 계획을 다시 쓰거나 검증을 생략하지 않는다.
   가능하면 any[] 대신 기존 계획 비교 row 타입을 사용한다. 타입 정리를 제품 기능 확장으로 키우지 않는다.
2. 가상 **계획 단위** 재가져오기 UI의 같은 입력(불필요한 차이 없음)·실제 변경·충돌 보류를 PC/모바일에서 검사한다.
   기존 content.spec.ts의 가이드 본문 검사는 대체 증거가 아니다. 기존 도구/fixture를 재사용하고 결과를 구체적 테스트 이름으로 연결한다.
   사용자 프로필이나 실제 ZIP을 테스트 fixture로 쓰지 않는다. 기대값을 완화하지 않는다.

구 기준 호환·세 방향 분류·실제 시간/지역/순서 변경·원본 비변경·승인 전 불변·충돌/defer 회귀를 유지한다.
대상 검사 후 `pnpm run check:deferred`로 최종 검사한다. 이미 포함된 검사를 같은 코드에서 반복하지 않는다.
코드/검사와 `docs/claude-task-05-r2-result.md` 보고를 별도 커밋으로 기존 작업 브랜치에 push한다.
보고에 시작/종료 SHA·재현 전후·UI 검사 프로젝트/이름·exit code·CI·미검증을 남긴다.
main 병합·배포·실제 사용자 자료 적용·API 호출·F-2/F-3·C 기능/문서 수정은 하지 않는다.
