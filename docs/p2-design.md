# P2 설계서 v0.1 — 준비 자료의 보관과 기기 간 이동

2026-11-25 · Codex 작성 · **상태: 사용자 승인 대기**(승인 전에는 구현 지시를 내지 않는다). 사용자 결정(11/25 11:37): "P2는 A안" = 설계서를 먼저 보고 승인한 뒤 구현.

"준비 자료" = 조건·취향 답, 붙여 넣은 가이드, 가이드에서 고른 것(꼭 포함·관심·제외), 지난번 답.

## 1. 지금 상태 (사실 — 코드 확인)

| 자료 | 있는 곳 | 한계 |
|---|---|---|
| 준비 초안 1건(답·가이드 원문·고른 것) | 이 기기 브라우저 설정(`localStorage`, 키 `travel-app.prep-draft.v1`) | 백업 ZIP에 없다. 다른 기기로 가지 않는다. 사이트 데이터를 지우면 사라진다 |
| 지난번 답(취향 8칸) | 같은 곳(키 `travel-app.last-answers.v1`) | 같음 |

- 여행 DB의 표 20개 가운데 자료를 담는 16개는 모두 "여행 하나"에 딸린 구조다(`spaceId+tripId`). 나머지 4개는 공간 정보와 백업·가져오기 작업 관리용이다. 여행에 속하지 않는 자료를 둘 자리가 없다.
- 전체 백업에 담는 표는 15개로 고정돼 있고(`exchangeCollections`), 표를 늘리면 저장 계약·백업 검증·복원·이행 검사를 함께 바꿔야 한다.
- 전체 백업 복원은 **빈 공간에서만** 된다([운영 설명서](phase-4-operations.md) C). 그래서 준비 자료를 백업에 넣어도, 여행이 이미 있는 다른 기기의 평소 공간으로는 들어가지 않는다.
- 기기 사이를 자동으로 맞추는 기능(동기화)은 앱에 없다. 계획 글도 사용자가 복사·파일로 옮긴다.

## 4. 추천 (Codex 제안 — 사용자 합의 아님)

**두 단계로 나눈다. 지금은 1단계(안 1)만 한다.**

- 이유 ①: 요청의 핵심이 "기기 간"이라면 안 2만으로는 풀리지 않는다(복원이 빈 공간 전용). 안 1은 풀린다.
- 이유 ②: 안 1은 데이터 경계를 건드리지 않아 실제 여행 자료에 위험이 없다. 안 2는 백업 형식을 바꾸므로 실사용 점검·단계 E(복구 훈련) 전에 하기에는 위험이 크다.
- 이유 ③: 안 1에서 만든 "글 ↔ 준비 자료" 변환은 나중에 안 2를 해도 그대로 쓴다.
- 알림: 계획서의 P2 이름은 "DB 저장"이었다. 이 추천은 1단계에서 DB 저장을 **하지 않는다**. b(지워져도 잃지 않기)는 사용자가 파일을 보관할 때만 풀린다.

### 1단계 P2-1 — 준비 자료 내보내기·가져오기

- 위치: "AI로 계획 만들기" 화면. 단추 2개 — **준비 자료 내보내기**(복사 · 파일 저장), **준비 자료 가져오기**(붙여넣기 · 파일 선택).
- 담는 것: 조건·취향 답, 가이드 원문, 고른 것, 지난번 답. 양식 이름 `travel-app-prep/1`. 사람이 읽을 수 있는 글(표)로 만들고, 메모 앱이 따옴표·줄바꿈을 바꿔도 읽히게 한다(세부는 지시서에서 정함).
- 가져오기: 미리보기(답 몇 칸, 가이드 목적지·항목 수, 고른 것 수)를 보여 주고 승인하면 반영. **이 기기에 초안이 이미 있으면 덮어쓰기 전에 확인**한다. 양식이 다르거나 깨진 글은 거절하고 기존 초안을 그대로 둔다. 계획 글·가이드 글을 잘못 넣으면 맞는 화면을 안내한다.
- 옮기는 일은 사용자가 한다(메일·메신저·iCloud 등). 자동 동기화는 없다.
- 안내 문구: 파일에는 예산·동행 같은 답이 그대로 들어간다는 것을 내보내기 옆에 적는다.
- 데이터 경계(`src/contracts`·`src/storage`·`src/transfer`·`src/repository.ts`)·Worker 변경 0건.

### 2단계 P2-2 — DB 저장·백업 포함 (보류)

- 실사용 점검에서 "준비 자료를 잃어 곤란했다" 또는 "목적지별 보관함이 필요하다"가 확인되면 별도 설계서로 진행한다. 그때 d(여행에 남기기)도 함께 판단한다.

## 5. 하지 않는 것

- 자동 동기화·서버 저장(안 4), 계정.
- 여행 사이의 장소·가이드 콘텐츠 재사용(스페인·프랑스 자료 재사용), 앱이 제공하는 추천 코스 — 별도 묶음.

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| 메모·메신저가 글을 바꿔 가져오기가 실패 | 파일 저장·파일 선택을 함께 둔다. 양식을 표 중심으로 하고 고른 것은 항목 이름으로 맞춘다 |
| 가져오기로 지금 초안을 실수로 덮어씀 | 덮어쓰기 전 확인, 거절 시 기존 초안 유지 |
| iPhone에서 파일 저장·선택이 다르게 동작 | 계획 글 가져오기에서 확인된 방식(클립보드 단추·길게 눌러 붙여넣기·파일)을 그대로 쓴다. 새 방식은 **미확인** — 일괄 확인 목록에 넣는다 |

## 7. 구현·검증 계획 (승인 뒤)
