## 요약

- 실제 기록 도구 안에 "날짜별 회고 보기"를 더했다. 날짜(또는 "날짜 미상 기록")와 비교할 계획 버전만 고르며, 현재/과거 계획 열, 날짜별 실제 기록(최신 정정본 대표), 계획 변경 이유·근거를 이어 읽고 당시 장소 본문으로 갔다가 같은 날짜·버전으로 돌아온다.
- 새 저장 명령·스키마·마이그레이션 없음. 기존 `repo.get`(읽기 트랜잭션)으로 읽은 데이터에서 순수 함수 `src/content/retro-rules.ts`가 모델을 만든다. 5개 탐색·새 탭·AI·통계 대시보드는 만들지 않았다.
- 가상 입력만 사용. 사용자 DB·iPhone·실제 ZIP·main·배포·API는 건드리지 않았다.

## 조회·날짜·버전 연결 결정

| 항목 | 결정 |
|---|---|
| 날짜 목록 | 모든 계획 버전의 날짜 + 실제 기록의 날짜(정정 포함). 대표 기록 날짜가 없으면 "날짜 미상" 구역 |
| 계획 열 | 현재 계획과 선택한 과거 계획을 각 버전 값으로 따로 표시(항목 순서·시각·이동·숙박). 현재 값을 과거 열에 쓰지 않음 |
| 당시 계획 | 기록의 명시 `planVersionId/activityId`로만 연결. 없으면 "계획 연결 없음", 기록 시각/commitSeq로 추정 안 함 |
| 날짜 차이 | 계획일과 실제일이 둘 다 있고 다를 때만 "실제 날짜와 다름". 계획일로 실제일을 대체하지 않음 |
| 정정 | 최신 정정본이 대표, 원본·중간 정정은 "정정 n단계 원문 보기". 정정으로 날짜가 옮겨지면 옛 날짜에 "정정으로 …로 옮긴 기록", 새 날짜에 "앞선 단계의 날짜" 표시. 건수는 대표 기록만 집계 |
| 변경 이유 | 계획의 `reason/parentId`와, `resultPlanVersionId`가 그 계획이고 상태가 applied인 변경안 revision만 연결(같은 proposalId의 대기/거절 revision은 쓰지 않음). 적용 revision이 없으면 "변경안 연결 없음", proposalId가 없으면 "저장된 이유만" |
| 이유 범위 | 이유는 "계획 전체"로 표시. 해당 날짜가 직전 버전과 같으면 "같음 · 개별 원인으로 보지 않음", 달라졌으면 변경된 활동 ID 계산(비교만, 추정 아님) |
| 근거 | 적용 변경안의 evidenceRefs(고정 revision)를 그대로 열고, 없으면 "근거 없음" |
| 당시 본문 | C-04의 `openRecordedPlace`와 계획 열의 "당시 장소 본문"(해당 계획의 contextRefs 고정)을 재사용. 읽기 전용 화면이라 수정 버튼 없음 |
| 복귀 | 선택(회고 열림·날짜·버전)을 부모가 보관해 "실제 기록으로 돌아가기" 후 그대로 복원 |

중간에는 대상 시험만 돌렸고 포함 검사는 최종 `check:deferred` 한 번만 실행했다.

## 사용자가 볼 산출물·확인 동작

`pnpm run build && pnpm run preview:ui` → `http://127.0.0.1:4173/?workspace=content`, 새 프로필/빈 공간만. 가상 입력: 여행 2032-06-01~03, 장소 "가상 카페", 활동 "가상 산책"·"가상 식사", 모의 변경안 1건.
1. 더 보기 → `실제 기록` → `날짜별 회고 보기`.
2. 날짜를 2032-06-01/02/날짜 미상으로 바꿔 대표 기록·정정 원문·이동 안내 확인. 계획 버전을 과거 계획으로 바꿔 현재/과거 열과 변경 이유 확인.
3. `기록 당시 내용` → 당시 고정 본문 → `실제 기록으로 돌아가기`.
스크린샷은 만들지 않았고 증거는 시험·로그다. 모바일은 Playwright(Pixel 7) 에뮬레이션이며 iPhone 확인이 아니다. 배치는 읽기 UI 후보이며 새 사용자 정책 확정이 아니다.

## 미검증·한계·경미한 발견 (Codex 관리 후보)

- Codex 독립 검토·사용자 확인·iPhone 확인 대기. 원격 CI 결과는 push 후 사용자 보고에 기재.
- 근거(evidence) 이동은 모델 시험(고정 revision 참조 보존)까지만 확인했고, 근거 본문 화면 이동 E2E는 가상 근거를 만들 UI가 없어 만들지 않았다. 코드는 기존 evidence 상세 화면을 같은 방식으로 연다.
- 날짜 미상 구역에서는 날짜별 계획 변화 비교를 하지 않는다. 기록이 연결한 계획 버전의 이유만 보인다.
- 기록이 연결한 계획 버전의 "이 날짜 변화" 판정은 보고 있는 날짜 기준이라, 계획일과 실제일이 다르면 해당 계획일 기준이 아니다.
- 계획 날짜가 없는 숙박(시작일 없음)은 날짜별 열에 나타나지 않는다.
- 회고를 열면 여행 전체 데이터를 읽는다(큰 여행에서 느릴 수 있음; 성능 측정은 하지 않음).
- 모의 변경안의 origin은 저장값 `ai`라 "AI 초안"으로 표시되지만 실제 AI 호출은 없다.
- 상위 설계/계획/후속 목록은 수정하지 않았다. 제안: T-C6 해소 기록(날짜별 읽기 전용 회고, 파일 `retro-rules.ts`/`Retrospective.tsx`). C-06〔T-C7〕 전체 마감은 아직이다. 미추적 `docs/status-review-2026-10-26.md`는 그대로. main 병합·배포·실제 자료·API 없음.
