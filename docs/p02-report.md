# P-02 중간보고: 새 저장소·명령

2026-10-21 · 단계 범위 구현·검증 완료. 재가져오기 명령은 P-05에 연결한다.

## 범위와 구현

- 기존 `trips`를 보존하고 Dexie 물리 version 2에 S-01~20을 추가했다. 새 논리 참조에 spaceId를 섞지 않고 저장 행에만 붙인다.
- `src/repository.ts`가 새 ContentRepository를 내보낸다. 새 명령은 이 경계의 트랜잭션에서 workspace/헤더/대상 행/영수증을 함께 처리한다. 저장 전 도메인 검증과 불변 행 보존 검사, 새 행만 추가·현재 head 갱신을 수행한다.
- C-01~07/C-09의 저장 경로, 정확한 v2 result replay, 요청 ID 재사용 거부, revision 충돌, 계획 자식 원자 저장, 정정·초안/결정 이력을 구현했다. C-08 재가져오기는 P-05에서 완성한다.
- 목록은 헤더, 계획은 선택 버전의 자식, catalog는 선택 kind의 현재 head/revision을 읽는다. 본문은 상세 열 때 읽는다. 전체 dataset 조립은 검증/쓰기 후보용이다.
- 기존 데이터가 있으면 legacy 모드를 유지한다. 원문 검토→고정 입력 대조→새 space 적재/활성화를 명시적으로 수행한다. 기존 trips와 v1 원문 보고서/영수증을 보존하며 전환 이후 옛 쓰기는 차단한다.

## 사용자 질문 대신 선택한 방안

| 항목 | 실행한 추천 방안·근거 |
|---|---|
| 기존 데이터 전환 | 사용자 데이터가 있는 브라우저는 자동 전환하지 않는다. 앱에서 검토/전환 버튼을 제공한다. 개발 중 자동으로 실제 DB를 바꾸지 않으면서 제품의 확인 절차를 구현하는 선택이다. |
| v1 당시 계획 연결 부족 | 원래 활동 ID는 전체 원문 보고서에 보존한다. v1에 실제 기록 당시 planVersionId가 없으므로 임의 버전을 만들어 붙이지 않는다. 알려진 제목/장소/시각은 구조화한다. |
| v1 receipt | prototype-v1로 보존하고 해당 requestId의 새 쓰기를 안전하게 거부한다. 없는 resultRefs를 발명하지 않는다. |
| 가져온 이력 순번 | 원천 내부 commitSeq 순서를 보존해 workspace 범위로 이동하고 최종 업무 순번을 그 이상으로 올린다. 초안·과거 revision의 앞뒤 관계를 유지한다. |
| 개발 실행 범위 | 실제 여행 DB를 초기화하지 않고 fake-indexeddb와 브라우저 테스트 전용 context로 검증한다. 공개 배포·유료 API 실행은 하지 않는다. |

위 표는 사용자의 이번 자율 진행 위임에 따라 내린 기술 선택이며 개별 제품 정책의 새 사용자 합의가 아니다.

## 검증 기록

- `npm run check`: **85개 통과**, TypeScript/프로덕션/PWA 빌드 통과.
- 신규 저장소 검사 6개: v1 store/원문 보존, 검토 중 수정 시 전환 취소, 두 여행/본문 편집/정확 replay, 두 연결 충돌/주입 실패 원자 취소, 실제/정정/과거 계획 보존, 초안 승인/오래된 결과 거부/거절 revision 유지.
- `npm run test:e2e`: **14/14 통과**(PC 7, 모바일 7). AI 8787 점유로 첫 기동은 실패했으며, UI 전용 preview:ui/모의 API로 분리해 완료했다. 관련 선택은 P-03 보고서에 기록했다.
- P-05 최종 재검증: 전체 **94개/빌드·26개 E2E 통과**. 기존 v1 승인/실제/영수증·미확인 근거 변환 검사와 실제 화면 전환 E2E를 추가했다. v1 IndexedDB의 명시적 undefined 선택 필드와 누락은 tagged 지문으로 구분해 원문 변경을 감지한다. 새 v2의 엄격 JSON 계약은 유지한다.
- 미확인 v1 근거의 checkedAt은 collectedAt으로 보존한다. 사용자/결정 시각이 없는 확정 상태는 만들어 내지 않고 변환을 거부한다. 최종 receiptSchema는 저장할 result와 trip/domain/commit 기준을 함께 검증한다.
