## 1. 범위와 산출물

AGENTS.md → handoff → 개발계획 → 요구/결정 → C 설계 §3~6·C 계획을 읽는다.
[설계](phase-c-design.md)의 T-C1·T-C2·T-C3.1을 한 사용자 흐름으로 구현한다. 구현 명령 이름은 계획 T-C1의 제안이며
현 계약을 조사해 확정하고 차이가 있으면 결과에 근거를 남긴다. 임의 범용 DB 쓰기 API를 만들지 않는다.
새 `codex/c01-authoring` 브랜치에서 현재 커밋을 보존하고 시작한다. main/기존 배포의 오래된 상태에서 시작하지 않는다.
worktree·reset·기존 사용자 DB 조작·배포·API 호출은 하지 않는다.

### A. 콘텐츠 생성 저장 계약(T-C1)

- 신규 region/place/guide와 기존 소유자 연결 갱신을 같은 저장소 트랜잭션으로 처리한다.
- 장소.guideId↔place-guide.ownerRef, 지역.guideIds↔region-guide.ownerRef의 최종 참조 그래프를 검증한다.
- expectedDomainRevision과 기존 소유자 expectedRevisionId, 고유 ID·여행 격리·비활성 참조·필수 섹션을 검사한다.
- 생성/갱신/head/receipt/여행 revision은 전부 성공 또는 전부 롤백. 동일 요청 replay는 중복 쓰지 않는다.
- C-01 UI가 쓰지 않는 새 가이드 종류/대량 편집/AI 변경안은 확장하지 않는다. 과거 revision·계획·실제 기록을 보존한다.

### B. 빈 여행 생성·날짜(T-C2)

- 기존 새 여행 모달을 우선 재사용한다. 이름·기간·확인한 시간대를 받아 지역 없는 여행을 생성한다.
- 초기 날짜는 콘텐츠 참조 없이 regionIds=[], 야간 미설정으로 만들고 오늘/전체 일정에서 읽힌다.
- 실재 달력 날짜·시간대·역전 기간을 검증한다. 기존 조회/이행 여행을 재계산하지 않는다.

### C. 지역/장소·설명 작성→일정 연결(T-C3.1)

- 현재 5개 기본 탐색을 유지한다. 가이드 안에서 지역과 장소+설명 작성, 오늘 일정에서 장소를 선택해 항목 추가/순서·시간 수정.
- 현행 Markdown 섹션 편집을 확장하고 place-guide 필수 why_go/deep/practical을 충족한다.
- 저장→다른 화면에서 찾기→열어 읽기→재실행/오프라인 재조회까지 연결한다.
- 기존 item 연산과 placeLinks를 사용한다. 실제 기록·이전 계획은 그대로 유지하고 새 계획 버전과 이유를 남긴다.
- 입력 오류/충돌 시 작성 중 입력을 보존한다. 구현상 UI 선택이 필요하면 현 구조의 최소 기본안으로 완성해 시제품을 제출한다.
  새로운 제품 정책·비용/외부 영향 결정이 필요할 때만 질문하고 독립 작업은 계속한다.

## 2. 필수 검증

- 가상 지역/장소/본문의 원자 생성·소유 연결, 중복 ID·다른 여행 참조·stale domain/content revision·쓰기 실패 롤백·replay.
- 계획 ID가 같아도 다른 탭의 실제 기록으로 여행 revision이 바뀌면 저장 거부. 과거 계획·현장 기록 불변.
- PC/모바일 E2E: 새 여행→지역/장소 작성→다른 화면 찾기→일정 연결/순서 변경→재실행 조회.
- 두 가상 여행을 함께 두고 본문·계획·기록 격리와 기존 SP-FR 가상 조회/편집 회귀를 확인한다.
- 새 콘텐츠·연결·계획을 포함한 전체 백업→빈 review 공간 복원→재조회. 구 v2 파일/백업 읽기·T-05 비교 회귀 유지.
- 최종 `pnpm run check:deferred`. 중간은 대상 검사만 실행하고 같은 코드의 전체 검사를 반복하지 않는다.
- 사용자가 볼 산출물: 가상 새 여행/장소/일정 화면, 재현 동작과 실행 명령, 실제 생성 파일/화면 증거 위치.
  모바일 에뮬레이션과 실기기·Claude 자체 검사와 Codex 검토를 구분한다.

## 3. 제출·보류 원칙

필요한 부분의 책임 분리만 별도 구조 커밋으로 한다. 전체 파일 리팩터링을 선행 과제로 키우지 않는다.
계약/저장, 여행 생성, 작성/일정 UI를 검토 가능한 기능 커밋으로 나누고 결과 보고는 별도 문서 커밋으로 push한다.
`docs/claude-task-c01-result.md`에 기준/종료 SHA·변경 범위·검사/exit code·증거·미검증·후속 항목을 남긴다.
새 경미한 문제는 결과에 영향/재개 조건과 함께 적고 핵심 흐름을 먼저 끝낸다. Codex가 후속 목록을 관리한다.
데이터 손실·격리/저장/복원/충돌·보안 결함은 보류하지 않는다. 해당 흐름을 수정·검증한 뒤 진행한다.
T-06/F-2·F-3·숙박/이동 편집(T-C3.2)·지역/여행 가이드 UI(T-C4)·회고·사진/지출·AI·배포는 이번 범위 밖이다.
C 설계/상위 정책 문서는 임의 개정하지 말고 차이와 제안은 결과 보고에 남긴다. 사용자 실자료는 공개 fixture/커밋에 넣지 않는다.
