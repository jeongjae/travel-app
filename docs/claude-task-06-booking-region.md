## 2. 의미·수용 조건

- 작성자 기술 기준: 예약 regionId는 원천에 명시된 지역 참조가 유효한 경우에만 보존한다.
  현재 원천에 그런 필드가 없다면 미설정으로 둔다. 선택 지역 1개·야간 숙박·예약 날짜로 예약 장소의 지역을 발명하지 않는다.
  명시값이 있는데 패키지 참조 범위를 벗어나면 조용히 바꾸거나 누락하지 말고 차단/검토 사유를 보고한다.
- `placeId`·activityIds·planVersionId·bookingIds·예약 시각/상태/원문/출처는 해당 기존 범위와 계약을 유지한다.
  placeId로 지역을 새 추정하는 정책도 이번에 추가하지 않는다. 지역 미상 표기가 기존 화면에서 안전한지 확인한다.
- 같은 예약을 포함하는 전체/부분 변환의 의미 필드는 동일해야 한다. 선택 범위에 따른 활동 연결/포함 차이는 별도 설명한다.
- 원천 명시 지역이 없는데 잘못 부여되던 경우만 제거한다. 기존 사용자 DB/과거 계획·예약 편집값은 자동 수정하지 않는다.
- T-04 하루/야간 지역·T-05 구 비교 기준 호환/추가 필드 거부·충돌/defer를 유지한다.
- 새 변환 의미를 기존 `spfr-pilot-v3` 후보와 구분할 어댑터/정규화 버전으로 표시한다.
  버전 상수·CLI·검증 도구의 판별 조건을 함께 조사하고 구 v2/v3 파일을 재해석 없이 계속 읽는다.
  파일/명령 스키마 버전은 실제 계약 변경 없이 올리지 않는다.

## 3. 검사·실제 산출물

- 가상 fixture로 단일/복수 지역, 같은 예약 전체/부분 변환, 지역 미상, 존재한다면 원천 명시 참조·잘못된 참조를 검사한다.
- 수정 전 실패→후 통과를 보이고, payload의 무관한 예약 필드를 약화하거나 기대값 전체를 새 출력으로 덮어쓰지 않는다.
- 패키지 ZIP 왕복→가상 DB 조회→재가져오기 검토(승인 전 불변/실제 앱 편집 충돌)로 계약을 확인한다.
  기존 검사를 재사용하고 부족한 경우에만 추가한다.
- 지역 미상 예약이 PC/모바일에서 조회 가능하며 잘못된 지역 필터/라벨을 만들지 않는지 대상 화면 증거를 제출한다.
  실제 iPhone 확인과 모바일 에뮬레이션을 구분한다.
- 최종 `pnpm run check:deferred`와 영향을 받는 Python audit 시험을 실행한다. 포함된 검사를 중복 실행하지 않는다.
- 실제 원천/verified/T-04 후보는 읽기 전용. 기존 경로를 덮어쓰지 않고 새 `local-data/phase2/t06-candidate/` 아래 전체 후보를 만든다.
  기존 여행 이름 등 비의도 메타 차이를 최소화하고 입력 원천 SHA·출력 버전·크기·해시를 기록한다.
- audit 도구로 T-04 후보와 비교한다. 예상 예약 regionId·버전/생성 메타 이외 차이, 계획/기록/콘텐츠/첨부 변경은 원인 확인 전 통과로 처리하지 않는다.
  실제 예약 원문·날짜·본문·ZIP·사진·개인 로그는 공개 커밋하지 않는다. 공개 보고는 수량·필드명·익명 ID·해시로 충분하다.
