## 1. 기준·사용자 산출물

## 2. 단위 A · 가이드 생성·소유 연결

- 지역 가이드는 기존 `region-guide`와 지역 ownerRef를 사용한다. 지역.guideIds에 추가할 때 기존 연결을 유지한다.
  기존 CreateContentBatch/updateOwners 경로를 사용해 guide·소유자 새 revision·heads·여행 revision·receipt를 한 번에 저장한다.
- 여행 공통 가이드는 기존 `preparation`을 우선 사용하고 ownerRef는 같은 여행의 trip을 명시한다.
  C-01 배치는 현재 place-guide/region-guide만 허용하므로 필요한 종류/owner 검증만 확장한다.
  trip owner의 tripId/entityId 일치, 다른 여행/잘못된 owner·기존 ID·필수 입력을 검증한다.
  적합한 기존 모델을 사용할 수 없는 근거가 있다면 최소 대안을 결과에 설명하며 범용 쓰기 명령으로 확대하지 않는다.
- 일반 `region-essentials`·교통권·회화 등 구조화 종류까지 신규 작성 기능을 늘리지 않는다.
- 기존 장소 본문 교체/가이드 연결 제거 금지(C-01 R1)를 유지한다. 이번 작업에 소유자 변경·물리 삭제·가이드 교체 명령은 추가하지 않는다.
- 가이드의 최소 입력은 제목·섹션 제목/본문이다. 새 가이드의 안정적인 섹션 key/order와 Fact/첨부 참조 규칙을 지킨다.
  현행 EditContentSection 등 편집 경로를 재사용하고 가이드 제목 수정도 가능한 최소 흐름으로 완성한다.

## 3. 단위 B · 기본정보 수정·조회 연결

- CL-06: 지역 이름/한 줄 소개/지역 설명, 장소 이름/종류/요약/소속 지역을 기존 상세 화면의 최소 폼으로 수정한다.
  없는 지역을 참조하거나 비활성 콘텐츠에 새로 연결하지 않는다. 지역 없는 장소 허용은 유지한다.
- UpdateContent 등 기존 저장 명령을 우선 재사용한다. expectedDomainRevision과 expectedRevisionId를 함께 확인하고 새 revision으로 저장한다.
  수정 가능한 필드만 변경한다. 편집하지 않은 guideId/guideIds·aliases·Fact bindings·섹션 key·출처·첨부·관련 링크/구조화 필드를 보존한다.
  기본정보 수정 때문에 기존 본문을 비우거나 다른 가이드로 교체하지 않는다. 새 kind/소유자/ID를 몰래 변경하지 않는다.
- 가이드 본문/기본정보 수정은 과거 revision·계획/실제 기록의 contextRefs를 바꾸지 않는다.
  최신 상세 정보와 당시 맥락의 과거 정보가 서로 혼동되지 않게 기존 조회 계약을 유지한다.
- 현재 isReadingGuide 등은 preparation을 원천 ID 접두사/첨부 유무로 구분하는 부분이 있다.
  새 수동 가이드가 빈 체크리스트·숨겨진 문서로 처리되지 않게 목록/소유자 기반 조회를 확인한다.
  새 문서에 원천처럼 보이는 ID를 붙여 우회하지 말고 기존 원천 준비/회화/체크 UI의 동작을 보존한다.
- 입력 오류·다른 탭 수정 시 폼 내용을 보존하고 충돌을 알린다. 같은 요청 재시도에 중복 revision/가이드가 생기지 않아야 한다.
  통상적인 UI 선택은 현 구조의 최소안으로 완성해 제출하고, 새 제품 정책/비용/외부 영향이 필요한 경우에만 질문한다.

## 4. 단위 C · 필수 검사

- 생성/수정: 지역 가이드 원자 연결, 여행 공통 가이드 유효 owner, 잘못된 owner/다른 여행/중복/비활성 참조 거부.
- 기존 연결 유지, stale domain/content revision, 다른 탭 현장 기록, replay·중간 쓰기 실패 전체 롤백·과거 revision/계획/기록 불변.
- 기본정보 수정 전후 무관한 본문/Fact bindings/출처/첨부/원천 구조화 필드 동일. 실제 Fact 포함 가상 본문으로 토큰·바인딩 보존을 검사한다.
- PC/모바일 E2E: 생성→다른 화면/목록에서 찾기→본문·제목/기본정보 수정→검색/상세 재조회→재실행.
  연결된 일정/장소 상세와 지역의 여러 가이드, 여행 공통 가이드의 준비 화면 조회를 확인한다.
- 오프라인 작성/수정·재조회, 두 여행 격리, 새 가이드/메타데이터를 포함한 전체 백업→빈 review 공간 복원을 확인한다.
  기존 SP-FR 가상 준비·회화·지역/장소 본문·Fact·C-01/C-02·T-05 회귀와 구 파일/백업 읽기를 유지한다.
- 최종 `pnpm run check:deferred`. 중간은 대상 검사만 실행하고 같은 코드의 포함 검사를 중복 실행하지 않는다.
- 산출물 확인 동작·가상 입력·스크린샷 또는 실행 가능한 검사/로그 경로를 제출한다.
  모바일 에뮬레이션은 iPhone 확인과, 자체 검사는 Codex 검토/사용자 확인과 구분한다.

## 5. 제출·범위 통제

계약/저장 확장·가이드 UI·기본정보 편집을 검토 가능한 기능 커밋으로 나누고 구조/포맷 변경은 별도 커밋으로 분리한다.
`docs/claude-task-c03-result.md`에 기준/종료 SHA·모델/owner 결정·변경 범위·검사/exit code·CI·증거·미검증을 기록한다.
결과 문서는 별도 커밋으로 현재 작업 브랜치에 push한다. Codex 검토·사용자 확인은 대기로 둔다.
경미한 문제는 영향/재개 조건과 함께 보고에 남기고 핵심 흐름을 먼저 완성한다. 상위 설계·계획·후속 목록은 Codex가 관리한다.
데이터 손실·소유/여행 격리·저장/복원·충돌·보안 문제는 보류하지 않고 해결한다.

사용자 DB/원본/기존 ZIP·개인 자료를 수정하거나 공개 fixture/커밋에 넣지 않는다.
